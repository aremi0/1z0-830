Ch 1: Building Blocks

1.1 Ambiente di Sviluppo e Componenti (JDK)

Definizioni e Concetti Il Java Development Kit (JDK) contiene il software minimo necessario per lo sviluppo, inclusi i comandi javac (compila i file .java in bytecode .class), java (esegue il programma lanciando la JVM) e jar (pacchettizza i file). È fondamentale utilizzare la versione 21 del JDK per l'esame 1Z0-830, poiché le regole sintattiche e i comportamenti del codice possono variare significativamente tra le versioni del linguaggio. Il codice Java è compilato in bytecode, che consiste in istruzioni in un formato speciale che la JVM sa come eseguire su qualsiasi macchina fisica reale, agendo come una "scatola magica" che fa girare il file .class all'interno dello specifico sistema operativo e hardware.

Regole di Sintassi e Opzioni Il comando javadoc genera la documentazione. Le opzioni di Java sono case-sensitive; ad esempio, non è possibile passare -D invece di -d per specificare la directory di destinazione.

  • -cp / -classpath / --class-path: Specifica la posizione dei file necessari per compilare o eseguire il programma.
  • -d <dir>: Specifica la directory in cui posizionare i file di classe generati.

1.2 Struttura delle Classi e File Sorgente (Membri e Commenti)

Definizioni e Concetti Le classi sono i mattoni costruttivi di base dei programmi Java che descrivono caratteristiche e comportamenti tramite campi (variabili che detengono lo stato) e metodi (operazioni sullo stato; in altri linguaggi spesso chiamati funzioni o procedure), definiti insieme come membri della classe. Un oggetto (o istanza) è la rappresentazione a runtime di una classe in memoria, mentre un riferimento (reference) è una variabile che punta a un oggetto; in termini di modello, il riferimento si comporta in modo simile a un puntatore all'indirizzo sull'heap dove risiede l'oggetto. Un file .java può contenere al massimo una sola classe public, il cui nome deve coincidere esattamente con quello del file (incluso il case), ma può ospitare più classi non pubbliche. Java chiama una parola con un significato speciale keyword. Un Access Modifier (modificatore di accesso) è una parola chiave che dichiara il livello di esposizione di un membro verso potenziali chiamanti.

Commenti e Tranelli I commenti supportati sono tre: a riga singola (//), multiline (/* */) e Javadoc (/** */). ⚠️ Tranello: Non è possibile annidare commenti multiline; il compilatore vede il primo */ come chiusura e segnala errore per l'extra */ orfano.

Esempio di Codice (Commenti che non compilano):

/*
 * /* ferret */
 */ // DOES NOT COMPILE

⚠️ Tranello (Dichiarazioni esterne): Non è consentito dichiarare campi o metodi al di fuori della dichiarazione della classe.

String name; // DOES NOT COMPILE: fuori dalla classe
public class Meerkat { }

1.3 Il Metodo main() (Scrittura e Entry Point)

Definizioni e Concetti Il metodo main() rappresenta il punto di ingresso (entry point) cercato dalla JVM quando inizia a far girare un nuovo programma. La firma standard deve essere public static void main(String[] args). void indica che non viene restituito alcun valore, mentre static vincola il metodo alla classe.

Varianti Legali e Varargs Sono ammesse varianti come lo scambio d'ordine tra public e static, l'aggiunta del modificatore final (anche sul metodo o sui parametri, es. public final static void main(final String[] args)), l'uso di nomi variabili diversi da args e l'uso dei varargs (String... args) al posto dell'array. Sono accettati tre formati per il parametro: String[] args, String options[], o String... friends. I parametri sono le variabili dichiarate nella firma; la firma del metodo è data dal nome del metodo e dai tipi dei parametri (in ordine). Un array (String[]) ha dimensione fissa; con i varargs (String...) si passa una sequenza di argomenti compatibile.

⚠️ Tranello (Parametri mancanti): L'accesso a un indice dell'array args (es. args[0] se non ci sono argomenti, o un indice oltre l'ultimo fornito) lancia a runtime l'eccezione java.lang.ArrayIndexOutOfBoundsException.

1.4 Dichiarazione di Package e Import (Regola PIC)

Definizioni e Concetti I package sono raggruppamenti logici per le classi, simili a cartelle in uno schedario. Un Import Statement comunica a Java in quali pacchetti cercare le classi. I Child Packages (pacchetti figli) sono pacchetti più dettagliati (es. com.wiley.javabook è figlio di com.wiley). Una wildcard (*) importa le classi direttamente in quel pacchetto, non le classi dei sotto-pacchetti, né campi o metodi (es. import java.util.*; non importa nulla da java.util.concurrent.* — servono import espliciti o ulteriori wildcard sul sotto-pacchetto). Il pacchetto java.lang è l'unico importato automaticamente; importarlo esplicitamente o con * è ridondante ma consentito. Se non si dichiara alcun package, le classi appartengono al default package (pacchetto senza nome; uso sconsigliato in applicazioni reali o moduli).

Regola PIC (Package, Import, Class) Il codice deve seguire l'ordine rigoroso: 1) Package (opzionale, prima riga non di commento), 2) Import (opzionali), 3) Class (dichiarazione della classe).

⚠️ Tranelli (Struttura e Conflitti):

  • Inversione dell'ordine: Scambiare package e import impedisce la compilazione.
  • Ambiguità: Se due pacchetti contengono classi con lo stesso nome e vengono entrambi importati con wildcard (es. java.util.Date e java.sql.Date), l'uso del nome semplice causa un errore di ambiguità; la soluzione è usare il nome completo (Fully Qualified Class Name).

Esempio di Codice (Ordine errato):

import java.util.*;
package structure; // DOES NOT COMPILE: package deve essere il primo

1.5 Inizializzazione e Creazione di Oggetti

Definizioni e Concetti Gli oggetti si creano con la parola chiave new che chiama un costruttore, il quale ha lo stesso nome della classe e nessun tipo di ritorno. Un blocco di codice è compreso tra parentesi graffe {}. Gli Instance Initializer (inizializzatori d'istanza) sono blocchi che appaiono fuori da un metodo e vengono eseguiti quando viene creata un'istanza.

Ordine di Inizializzazione Tassativo:

  1. I campi e i blocchi inizializzatori d'istanza vengono eseguiti nell'ordine in cui appaiono nel file sorgente.
  2. Il costruttore viene eseguito per ultimo, dopo che i campi e i blocchi sono stati inizializzati.

⚠️ Tranello (Illegal Forward Reference): Non si può fare riferimento a una variabile prima che sia stata definita all'interno dei blocchi di codice inizializzatori.

{ System.out.println(name); } // DOES NOT COMPILE: riferimento in avanti illegale
private String name = "Fluffy";

1.6 Tipi di Dati Primitivi e Wrapper

Definizioni e Concetti Java offre 8 tipi primitivi che rappresentano singoli valori in memoria (non sono oggetti): boolean, byte (8-bit), short (16-bit), int (32-bit), long (64-bit), float (32-bit), double (64-bit), char (16-bit Unicode). String non è un primitivo ma un oggetto. Ad ogni primitivo corrisponde una classe wrapper (es. Integer per int), che è un tipo di riferimento e può essere assegnata a null, a differenza dei primitivi. Le classi numeriche wrapper estendono Number, tranne Boolean e Character; sui tipi numerici wrapper sono disponibili, tra l'altro, metodi statici di utilità come max, min, sum. Un letterale è un numero o valore presente direttamente nel codice. I letterali interi ammettono prefissi per la base: ottale (0…), esadecimale (0x / 0X), binario (0b / 0B).

⚠️ Tranelli (Null e Underscore):

  • Null: I tipi primitivi non possono mai essere assegnati a null.
  • Underscore nei numeri: Permessi tra le cifre per migliorare la leggibilità, ma vietati all'inizio, alla fine, subito prima o subito dopo un punto decimale.

Esempi di Codice (Underscore illegali):

int value = null; // DOES NOT COMPILE
double d1 = 1_000.0_; // DOES NOT COMPILE (alla fine)
double d2 = 1_000._0; // DOES NOT COMPILE (vicino al punto)
double d3 = _100.0;   // DOES NOT COMPILE (all'inizio)

1.7 Text Blocks (""")

Definizioni e Concetti I blocchi di testo sono stringhe multiline che iniziano e finiscono con tre doppi apici ("""). Il contenuto non deve essere "escaped". Lo Spazio bianco essenziale è parte della stringa importante per il valore finale, mentre lo Spazio bianco incidentale serve solo alla leggibilità del codice.

Sequenze di Escape e Tranelli:

  • \ alla fine di una riga omette l'andata a capo nell'output.
  • \s preserva gli spazi bianchi finali che verrebbero altrimenti eliminati dal compilatore. ⚠️ Tranello: Un blocco di testo deve iniziare con """ seguiti obbligatoriamente da un andata a capo sulla prima riga; il contenuto inizia sulla riga successiva.

Esempio di Codice (Errore sintassi):

String b = """doe"""; // DOES NOT COMPILE: manca l'andata a capo dopo i primi """

1.8 Identificatori e Variabili (Regole e Parole Riservate)

Definizioni e Concetti Un identificatore è il nome di una variabile, metodo, classe, interfaccia o pacchetto. Deve iniziare con una lettera, un simbolo di valuta (es. $, ¥, €) o un underscore (_). Possono includere numeri ma non iniziare con essi. Non si possono usare nomi uguali alle reserved words (es. public, class, for). Le variabili di istanza/classe ricevono valori di default (0, null, false), mentre le variabili locali devono essere inizializzate manualmente prima di essere lette.

⚠️ Tranelli (Java 21 e Inizializzazione):

  • Underscore singolo: Un singolo underscore _ è un identificatore illegale in Java 21 (short _; non compila).
  • Inizializzazione delle Locali: Il compilatore segnala errore se esiste un percorso logico dove la variabile non viene inizializzata prima dell'uso.
  • Dichiarazione con più variabili: In int i1, i2, i3 = 0; l'inizializzatore con = si applica solo all'ultima variabile elencata: solo i3 è inizializzata a 0, mentre i1 e i2 restano non inizializzate sino a un'assegnazione successiva.
  • Sintassi identificatore: un identificatore non può iniziare con una cifra (es. int 3DPointClass; non compila) né coincidere con una parola riservata usata come nome (es. double public; non compila). Java è case-sensitive: Public come nome può essere lecito, ma public resta parola riservata.

Esempio di Codice (Inizializzazione parziale):

public void findAnswer(boolean check) {
   int answer;
   int onlyOneBranch;
   if (check) {
      onlyOneBranch = 1;
      answer = 1;
   } else {
      answer = 2;
   }
   System.out.println(answer);       // OK
   System.out.println(onlyOneBranch); // DOES NOT COMPILE (se check è false)
}

1.9 Inferenza del Tipo (var)

Definizioni e Concetti La parola chiave var abilita l'inferenza del tipo per le variabili locali (Local Variable Type Inference): la variabile deve essere inizializzata sulla stessa riga in cui si dichiara, così che il tipo sia deducibile. Il tipo fissato a tempo di compilazione non cambia. var è anche un reserved type name: non si può usare come nome di tipo per una classe, interfaccia o enum definiti dal programma.

⚠️ Tranelli (Uso limitato di var):

  • Non può essere usata per variabili di istanza, parametri di metodi o tipi di ritorno.
  • Non può essere inizializzata a null senza un cast esplicito; var n = null; non compila, mentre ad es. var x = (String) null; o var $num = (Integer) null; possono essere accettate dal compilatore per deduzione del tipo.
  • Non può essere usata in dichiarazioni di variabili multiple (es. var a = 2, b = 3; non compila).

1.10 Scope delle Variabili

Definizioni e Regole Lo scope (ambito) definisce la porzione di codice in cui una variabile è accessibile.

  • Variabili Locali: Dalla dichiarazione fino alla fine del blocco {} corrente.
  • Parametri del Metodo: Per l'intera durata del metodo.
  • Variabili d'istanza: Dalla dichiarazione finché l'oggetto non è idoneo alla garbage collection.
  • Variabili di classe (static): Per l'intera durata del programma. I blocchi interni possono vedere variabili dei blocchi esterni, ma non viceversa.

1.11 Garbage Collection (GC) e Distruzione di Oggetti

Definizioni e Concetti La Garbage Collection è il processo di liberazione automatica della memoria sull'heap tramite l'eliminazione di oggetti non più raggiungibili. Un oggetto diventa idoneo (eligible) per la GC nel momento esatto in cui non è più raggiungibile da alcun riferimento attivo (es. referenza impostata a null o tutti i riferimenti fuori scope).

⚠️ Tranello (System.gc): Chiamare System.gc() è solo un suggerimento alla JVM e non garantisce l'esecuzione immediata della pulizia.

1.12 Casi Limite e Tranelli Sintattici

Tutti i casi limite e i tranelli sintattici sopra descritti (come la regola PIC, l'Illegal Forward Reference, gli underscore nei numeri, la sintassi dei Text Blocks e i limiti di var) costituiscono gli elementi critici per evitare errori di compilazione nel Capitolo 1.

2.1 Comprensione degli Operatori Java

Definizioni e Concetti Un operatore Java è un simbolo speciale che può essere applicato a un insieme di variabili, valori o letterali — definiti operandi — e che restituisce un risultato. Il termine operando si riferisce al valore o alla variabile a cui l'operatore viene applicato. L'output dell'operazione è definito semplicemente come il risultato. Classificazione: Gli operatori sono classificati in unari (un operando), binari (due operandi) o ternari (tre operandi). Precedenza degli Operatori (Operator Precedence): Determinare quali operatori vengono valutati e in quale ordine è definito precedenza degli operatori (Tabella 2.1).

⚠️ Tranello: Ordine di Valutazione Gli operatori Java non vengono necessariamente valutati da sinistra a destra. L'ordine dipende dalla specifica precedenza degli operatori coinvolti. Confondere l'ordine in espressioni miste (es. moltiplicazione prima dell'addizione e operatori unari prima di quelli binari) è un errore comune.

Esempio di Codice (dal libro):

int cookies = 4;
double reward = 3 + 2 * --cookies;
System.out.print(reward); // Stampa 9.0

In questo esempio, viene prima eseguito il decremento (--cookies porta il valore a 3), poi la moltiplicazione (2 * 3 = 6), e infine l'addizione (3 + 6 = 9). Il valore viene promosso a 9.0 per l'assegnazione a double.

2.2 Applicazione degli Operatori Unari

Definizioni e Concetti Un operatore unario è quello che richiede esattamente un operando, o variabile, per funzionare. Tipi: Includono il complemento logico (!), il complemento bit per bit (~), il più (+), la negazione (-), l'incremento (++), il decremento (--) e il cast ((tipo)). Incremento/Decremento Prefisso (++w, --x): Aumenta o diminuisce il valore di 1 e restituisce il nuovo valore. Incremento/Decremento Postfisso (y++, z--): Aumenta o diminuisce il valore di 1 e restituisce il valore originale.

⚠️ Tranello: Applicazione Errata e Valori di Ritorno Esistono restrizioni rigide: non si può applicare la negazione logica ! a numeri o la negazione bit a bit ~ a booleani. In Java 0/1 e false/true non sono correlati.

Esempi di Errore (NON COMPILANO):

int pelican = !5;         // DOES NOT COMPILE: inversione logica su numero
boolean penguin = -true;  // DOES NOT COMPILE: negazione numerica su boolean
boolean parrot = ~true;   // DOES NOT COMPILE: complemento bit a bit su boolean
boolean peacock = !0;     // DOES NOT COMPILE: inversione logica su numero

Esempio (prefisso e postfisso):

int parkAttendance = 0;
System.out.println(++parkAttendance); // Stampa 1 (nuovo valore)
System.out.println(parkAttendance--); // Stampa 1 (valore originale prima del decremento)
System.out.println(parkAttendance);   // Stampa 0

L'operatore prefisso aggiorna e restituisce il nuovo valore; quello postfisso aggiorna la variabile ma restituisce il valore originale. ⚠️ Tranello: Sbagliare il valore restituito quando la stessa variabile è incrementata e usata nello stesso statement.

2.3 Operatori Aritmetici Binari

Definizioni e Concetti

  • Operatore Binario: Operatori che richiedono due operandi; sono di gran lunga i più comuni.
  • Tipi: Includono addizione (+), sottrazione (-), moltiplicazione (*), divisione (/) e modulo (%).
  • Operatore Modulo: Talvolta chiamato operatore di resto, è semplicemente il resto di quando due numeri vengono divisi.
  • Applicabilità: Possono essere applicati a tutti i primitivi Java eccetto boolean; l'operatore + può essere utilizzato per la concatenazione di oggetti String.

⚠️ Tranello: Parentesi Quadre e Comportamento Modulo

  • Java richiede parentesi tonde () bilanciate; non permette l'uso di parentesi quadre [] per raggruppare espressioni aritmetiche.
  • Confondere il comportamento del modulo con la divisione intera: con operandi interi, la divisione dà un quoziente troncato (verso zero, senza parte decimale), mentre il resto si ottiene con %. Errori comuni: usarli in modo scambiato, ad esempio per verifiche pari/dispari o in cicli con wraparound.

Esempio di Errore (NON COMPILA):

short robin = 3 + [(4 * 2) + 4]; // DOES NOT COMPILE: parentesi quadre non ammesse

2.4 Regole di Promozione Numerica

Definizioni e Concetti

  • Promozione Numerica Primitiva (Numeric Promotion): Processo mediante il quale Java converte automaticamente i tipi di dati più piccoli in tipi più grandi durante le operazioni.
  • Le 4 Regole Fisse:
    1. Se due operandi hanno tipi diversi, Java promuove il più piccolo al tipo del più grande.
    2. Se un operando è integrale e l'altro in virgola mobile, l'integrale è promosso a virgola mobile.
    3. I tipi byte, short e char vengono sempre promossi a int prima di essere usati con operatori aritmetici binari, anche se nessuno degli operandi è un int.
    4. Il risultato finale ha lo stesso tipo degli operandi promossi.

⚠️ Tranello: La "Trappola del byte/short/char" Tentare di assegnare il risultato dell'operazione tra due short a una variabile short senza cast esplicito fallirà perché il risultato è un int.

Esempio di Errore (NON COMPILA):

short mouse = 10;
short hamster = 3;
short capybara = mouse * hamster; // DOES NOT COMPILE: il risultato è un int

2.5 Assegnazione di Valori e Casting

Definizioni e Concetti

  • Operatore di Assegnazione (=): Memorizza il risultato di un'espressione nella variabile sul lato sinistro.
  • Casting: Operazione unaria in cui un tipo di dati viene interpretato esplicitamente come un altro. È richiesto per il "narrowing" (da tipo grande a piccolo).
  • Overflow/Underflow: Si verifica quando un numero supera il limite del tipo (overflow): il sistema "ricomincia" dal valore opposto (wrap around). L'underflow è il fenomeno analogo quando il valore è troppo basso per il tipo (stesso tipo di avvolgimento).
  • *Assegnazione Composta (+=, -=, =, /=, %=): Applica un'operazione e assegna il risultato. Esegue automaticamente il cast del valore risultante al tipo della variabile a sinistra.

Letterali in virgola mobile: Per impostazione predefinita, un letterale con punto decimale è di tipo double. Assegnarlo a un float senza suffisso f o F non compila.

⚠️ Tranello: letterale float

float y = 2.1; // DOES NOT COMPILE: 2.1 è un double

⚠️ Tranello: Casting parziale, assegnazione in if e assegnazione composta

  • Casting: applicare il cast solo al primo operando di un'espressione binaria fa sì che il prodotto/somma resti promosso (es. a int); spesso la compilazione verso un tipo più piccolo fallisce. Il cast unario ha precedenza elevata rispetto agli operatori aritmetici.
  • if e =: inserire un'assegnazione = invece di un confronto == in un if (l'espressione di assegnazione ha un valore: quello assegnato).
  • Assegnazione semplice vs composta: con +=, *= e simili, il compilatore può accettare casi che con = puro e cast richiederebbero maggiore attenzione.

Esempi (dal libro / casi d'esame):

short mouse = 10;
short hamster = 3;
short capybara = (short)mouse * hamster; // DOES NOT COMPILE: il cast si applica solo a mouse,
                                         // poi l'operazione * promuove tutto a int

System.out.print(2147483647 + 1); // Stampa -2147483648 (Overflow)

Esempio (assegnazione composta che compila):

long goat = 10;
int sheep = 5;
sheep *= goat; // COMPILA: cast implicito a int eseguito dall'operatore *=

Esempio (tranello if e =):

boolean healthy = false;
if(healthy = true) // ATTENZIONE: assegna true, non confronta
   System.out.print("Good!"); // Viene stampato

2.6 Operatori di Uguaglianza e Relazionali

Definizioni e Concetti

  • Operatori di Uguaglianza (==, !=): Restituiscono un boolean. Per i primitivi confrontano i valori; per gli oggetti verificano se i riferimenti puntano allo stesso oggetto in memoria.
  • Operatori Relazionali (<, <=, >, >=): Confrontano due espressioni numeriche e restituiscono un boolean.
  • Operatore instanceof: Determina a runtime se un oggetto è membro di una particolare classe o interfaccia.

⚠️ Tranello: Incompatibilità, instanceof e null

  • Non è possibile mescolare tipi non confrontabili con == / != (es. boolean con numeri, double con String).
  • null instanceof T (con T tipo riferimento) restituisce sempre false.
  • instanceof con tipi incompatibili a compile-time (impossibili) produce errore di compilazione. null non può comparire a destra in instanceof (sintassi non valida).

Esempi di errore (NON COMPILANO):

boolean monkey = true == 3;       // DOES NOT COMPILE
boolean gorilla = 10.2 == "Koko"; // DOES NOT COMPILE

Number time = 10;
if (time instanceof String) { }  // DOES NOT COMPILE: Number non può essere String

System.out.print(null instanceof null);   // DOES NOT COMPILE: null a destra vietato

Esempio di Codice (dal libro):

System.out.print(null instanceof Object); // Stampa false

2.7 Operatori Logici e Condizionali

Definizioni e Concetti

  • Operatori Logici (&, |, ^): Quando applicati a boolean, valutano sempre entrambi i lati dell'espressione.
  • Operatori Bitwise (&, |, ^): Quando applicati a tipi numerici, eseguono confronti bit a bit.
  • Operatori Condizionali (&&, ||): Chiamati operatori di corto circuito (short-circuit). Il lato destro non viene valutato se il risultato finale è determinato dal lato sinistro.
  • Effetto Collaterale non Eseguito: Situazione in cui un'espressione (es. un incremento) non viene eseguita a causa del corto circuito.

⚠️ Tranello: Incrementi nel Corto Circuito Mettere una modifica di variabile sul lato destro di && o || sperando che venga eseguita sempre.

Esempio di Codice (dal libro):

int rabbit = 6;
boolean bunny = (rabbit >= 6) || (++rabbit <= 7);
System.out.println(rabbit); // Stampa 6: ++rabbit non è mai stato eseguito!

2.8 Operatore Ternario

È l'unico operatore ternario del linguaggio (spesso chiamato operatore condizionale ? :).

Definizioni e Concetti

  • Sintassi: espressioneBooleana ? espressione1 : espressione2 — la prima sotto-espressione deve essere di tipo boolean (o convertibile a boolean); le altre due sono i possibili risultati e a runtime ne viene valutata sola una (comportamento simile al corto circuito, con l'obbligo però di risultati compatibili con il contesto). Il secondo e il terzo operando possono essere espressioni che restituiscono un valore, purché le regole di assegnazione o contesto siano soddisfatte.
  • Funzionamento: Solo una delle due espressioni a destra verrà valutata a runtime.
  • Compatibilità: I tipi delle due espressioni di risultato devono essere compatibili con la variabile o il contesto in cui si usa il valore (altrimenti non compila, es. int e String mescolati per un'assegnazione a int).

⚠️ Tranello: Tipi Incompatibili e Semicolon Assegnare un'espressione ternaria a una variabile il cui tipo non copre entrambi i rami di output.

Esempio di Errore (NON COMPILA):

int stripes = 7;
int animal = (stripes < 9) ? 3 : "Horse"; // DOES NOT COMPILE: "Horse" non è int

Ch 3: Making Decisions

3.1 Dichiarazioni di Decisione: Statements e Blocchi

Definizioni e Concetti Un Java statement è un'unità completa di esecuzione terminata da un punto e virgola (;). Un blocco di codice in Java è un gruppo di zero o più istruzioni tra parentesi graffe bilanciate ({}) e può essere utilizzato ovunque sia consentita un'istruzione singola. I "control flow statements" interrompono il flusso di esecuzione utilizzando il processo decisionale, il looping e il branching, consentendo all'applicazione di eseguire selettivamente particolari segmenti di codice. La singola istruzione o il blocco di istruzioni che viene eseguito se la condizione di una dichiarazione decisionale valuta a true è definito "target".

3.2 L'istruzione if e la Clausola else

Definizioni e Concetti L'istruzione if è composta da un'espressione booleana e da un'istruzione o un blocco di istruzioni; se l'espressione booleana valuta a true, il target viene eseguito. L'istruzione else permette di eseguire un blocco alternativo quando la condizione del if valuta a false. In Java, a differenza di altri linguaggi, i valori 0 e 1 non sono considerati valori booleani e non possono essere usati direttamente nelle condizioni.

⚠️ Tranello (Valori numerici come booleani): In Java, a differenza di altri linguaggi di programmazione e di scripting, i valori numerici non sono correlati ai valori booleani. Tentare di usare 0 o 1 (o qualsiasi intero) come condizione in un'istruzione if causa un errore di compilazione.

Esempio di Codice (non compila):

int hourOfDay = 1;
if (hourOfDay) {  // DOES NOT COMPILE
   // ...
}

Motivo: In Java, 0 e 1 non sono considerati valori boolean.

3.3 Pattern Matching con l'operatore instanceof

Definizioni e Concetti Il pattern matching è una tecnica di controllo del flusso di programma che esegue una sezione di codice solo se soddisfa determinati criteri. L'aggiunta di una variabile dopo il tipo (chiamata pattern variable) istruisce il compilatore a trattarlo come pattern matching, evitando potenziali ClassCastException perché l'operazione di cast viene eseguita solo se l'operatore instanceof restituisce true.

Sintassi (instanceof con pattern variable) Si indica al compilatore che si usa il pattern matching dichiarando una variabile subito dopo il tipo controllato, ad esempio if (number instanceof Integer data).

3.4 Pattern Variables e Clausole Condizionali

Definizioni e Concetti Il pattern matching supporta una clausola condizionale opzionale, dichiarata come espressione booleana, utilizzata per filtrare i dati. Una pattern variable è soggetta alla "flow scoping": la variabile è in scope fintanto che il compilatore può determinare definitivamente il suo tipo (tipicamente nel ramo in cui il tipo è garantito, ad esempio dopo un if con instanceof positivo, e non necessariamente nel ramo else). È considerata cattiva pratica riassegnare una pattern variable, operazione che può essere impedita con il modificatore final.

⚠️ Tranello (Scope della pattern variable): Una pattern variable è in scope solo quando il compilatore può determinare definitivamente che il tipo è corretto. Se usata in un blocco else dopo un instanceof positivo, o viceversa, il codice non compila.

Esempio di Codice (non compila):

public void m(Object obj) {
   if (obj instanceof LocalDate date)
      System.out.println(date);
   else
      System.out.println(date); // DOES NOT COMPILE: date non è in scope qui
}

⚠️ Tranello (Negazione di instanceof): Quando si usa l'operatore di negazione !, è necessario prestare attenzione alle parentesi. Senza parentesi corrette, il compilatore non riconosce la variabile.

Esempio di Codice (non compila):

if (!obj instanceof LocalDate date) // DOES NOT COMPILE: mancano parentesi
   return;

3.5 Struttura di switch statement e switch expression

Definizioni e Concetti Il vecchio switch statement instrada l'esecuzione verso i rami case senza dover restituire un valore; il nuovo switch expression valuta l'intera costruzione come un'espressione che produce un valore. Entrambi i tipi possono prevedere una clausola default opzionale; nelle switch expression il default è spesso obbligatorio affinché l'espressione abbia sempre un valore di ritorno, salvo che tutti i casi possibili siano già coperti in modo esaustivo (come con un enum completo o una sealed class con pattern di copertura completa).

Regole di Sintassi e Comportamento

  • Valori ammessi nei case: oltre al requisito generale di "compile-time constant values", rientrano tipicamente letterali, costanti enum e variabili final inizializzate con un letterale sulla stessa riga di dichiarazione.
  • Separatori : e ->: in uno stesso switch si può usare la sintassi con due punti (:) o con l'operatore freccia (->); se si sceglie la freccia, va usata in modo uniforme per tutte le clausole (non si mischiano le due forme).
  • Enum nel case: quando la variabile selezionata è di tipo enum, ogni case deve usare solo il nome della costante (es. case SPRING), non il nome qualificato dell'enum (es. case Season.SPRING non compila all'interno dello switch su quell'enum).
  • Combinare più valori in un case: È possibile specificare più valori in un unico blocco case separandoli con una virgola, evitando così di dover scrivere più case vuoti di fila per sfruttare il fall-through. Questo funziona sia con la sintassi : che con ->. Esempio: case 1, 2, 3 -> "Piccolo"; oppure case 1, 2, 3: System.out.print("Piccolo"); break;.

⚠️ Tranello (Valori delle clausole case): I valori delle clausole case devono essere "compile-time constant values". Variabili non marcate come final, o variabili final il cui valore è determinato da un metodo a runtime, non sono ammesse.

Esempio di Codice (non compila):

final int getCookies() { return 4; }
void feedAnimals() {
   final int bananas = 1;
   int apples = 2;
   final int cookies = getCookies();
   switch (numberOfAnimals) {
      case bananas:       // OK: costante determinata a compile-time
      case apples:        // DOES NOT COMPILE: non è final
      case getCookies():  // DOES NOT COMPILE: metodo valutato a runtime
      case cookies:       // DOES NOT COMPILE: valore final ma assegnato a runtime
      case 3 * 5:         // OK: espressione risolvibile a compile-time
   }
}

⚠️ Tranello (Nomi qualificati per gli enum): All'interno di uno switch, le clausole case devono usare solo il nome della costante enum, non il nome dell'enum qualificato.

Esempio di Codice (non compila):

switch(day) {
   case DaysOff.ValentinesDay: // DOES NOT COMPILE: deve essere solo ValentinesDay
}

⚠️ Tranello (Semicolons orfani o mancanti): Nelle switch expressions, un punto e virgola è richiesto dopo ogni espressione case o default (se non è un blocco) e alla fine dell'intera costruzione quando è usata in un'assegnazione o come espressione. Al contrario, un punto e virgola è proibito subito dopo un blocco case con le graffe.

Esempio di Codice (non compila):

int fish = 1;
var name = switch (fish) {
   case 1  -> "Goldfish"           // DOES NOT COMPILE: manca semicolon
   case 2  -> { yield "Trout"; };  // DOES NOT COMPILE: semicolon extra dopo il blocco
   default -> "Shark";
}  // DOES NOT COMPILE: manca semicolon finale per l'assegnazione var

⚠️ Tranello (Mischiare le sintassi): Non è permesso mischiare la sintassi con l'operatore freccia (->) e quella con i due punti (:) nello stesso switch.

3.5.1. Tipi Supportati e Pattern Matching in switch

Definizioni e Concetti I tipi supportati includono int, Integer, byte, Byte, short, Short, char, Character, String, valori enum e var (se risolto in uno dei precedenti). A partire da Java 21, qualsiasi tipo di oggetto può essere utilizzato come variabile di switch se viene utilizzato il pattern matching. Non sono supportati boolean, long, float e double.

3.5.2. Guard Clauses e l'uso di when

Definizioni e Concetti Il pattern matching con switch include una "guard clause", ovvero una clausola condizionale opzionale aggiunta a un ramo case. La parola chiave when è obbligatoria tra la variabile di pattern e l'espressione condizionale. Questo permette di gestire scenari complessi come case Integer i when i > 10 -> "Joseph";.

Variabili a runtime nei case (Il trucco del Pattern Matching) La regola di base dello switch non è cambiata: i valori scritti direttamente dopo la parola case devono continuare a essere costanti a tempo di compilazione (es. case miaVariabileDinamica: è sempre illegale, sia negli statements che nelle expressions). Tuttavia, con le Guard Clauses di Java 21, puoi aggirare il problema e ottenere esattamente quel risultato. Basta dire allo switch: "Cattura il valore in una nuova variabile di pattern e poi applica una condizione logica a runtime con when".

Esempio di Codice (Confronto dinamico legale in Java 21):

Integer numeroSegreto = generaNumeroRandom(); // Variabile a runtime
Object tentativo = 5;

int punti = switch (tentativo) {
    // Catturo il valore in 't' e lo confronto a runtime con 'numeroSegreto'
    case Integer t when t.equals(numeroSegreto) -> 100;
    
    // Posso aggiungere altre condizioni dinamiche a runtime!
    case Integer t when t > numeroSegreto -> 50; 
    case Integer t when t < numeroSegreto -> 10;
    
    default -> 0;
};

Questo rende i nuovi switch di Java potentissimi, permettendoti di sostituire completamente le catene di if-else if più complesse!

⚠️ Tranello (Posizionamento delle guard clauses when): L'ordine è critico anche con le clausole when. Un caso senza guardia domina lo stesso caso con una guardia successiva.

Esempio di Codice (non compila):

return switch (animal) {         
   case Integer i             -> "Daniel"; 
   case Integer i when i > 10 -> "Joseph"; // DOES NOT COMPILE: Daniel vince sempre
};

3.5.3. Ordinamento dei Rami e Dominanza (Unreachable Code)

Definizioni e Concetti Quando si lavora con il pattern matching, l'ordine dei rami è fondamentale indipendentemente dal tipo di switch. Un ramo non può essere "dominato" da un'istruzione precedente; se il compilatore rileva che è impossibile raggiungere un case (unreachable code), viene generato un errore di compilazione. Ad esempio, case Number n domina rami successivi come case Integer i.

⚠️ Tranello (Casi dominati, unreachable code): Un ramo case più specifico che segue un ramo più generico è considerato "dominato" e causa un errore di compilazione come codice irraggiungibile.

Esempio di Codice (non compila):

String message = switch (height) {         
   case Number n  -> "Unknown"; 
   case Integer i -> "Rounded"; // DOES NOT COMPILE: dominato da Number
};

3.5.4. Posizione del default: Switch Tradizionale vs Pattern Matching

La regola sulla posizione del default dipende da quale switch stai usando.

Nel vecchio switch con valori costanti puoi metterlo dove ti pare, ma nel nuovo switch con il Pattern Matching sei obbligato a metterlo alla fine.

Poiché il default è il caso più generale in assoluto (cattura letteralmente qualsiasi cosa), "domina" su tutti gli altri. Di conseguenza:

  • Il default DEVE essere l'ultimo blocco. Se lo metti prima di un case String s, Java ti darà errore perché la stringa verrebbe catturata in anticipo dal default.

L'unica eccezione: L'unica cosa che puoi affiancare o mettere insieme al default alla fine dello switch è la gestione del null. In Java 21 è molto comune (e legale) scrivere l'ultima riga così:

    // ... altri case ...
    case null, default -> System.out.println("O è nullo, o non so cosa sia");
}

3.5.5. Esaustività: L'obbligo del default

L'obbligo di inserire un blocco default o di coprire tutti i casi possibili (esaustività).

1. Switch Expressions (Sempre Esaustive) Qualsiasi switch che restituisce un valore (expression) deve essere esaustivo. Il compilatore pretende la certezza assoluta che, in qualsiasi scenario possibile, il flusso di codice produca un risultato da assegnare o restituire.

2. Le clausole when "accecano" il compilatore Nel Pattern Matching, il compilatore esegue un'analisi statica del codice e non risolve la logica o le condizioni dentro le clausole when (come >, <, equals). Per il compilatore, un case accompagnato da un when è incerto e potrebbe restituire false. Di conseguenza, anche se logicamente hai coperto tutti i valori numerici, il compilatore richiede un caso di riserva garantito (un default o un case incondizionato dello stesso tipo).

Esempio di Codice (Compila):

Integer tentativo = 5;
int punti = switch (tentativo) {
    case Integer t when t == 5 -> 100;
    case Integer t when t > 5 -> 50; 
    case Integer t when t < 5 -> 10;
    // In assenza di default, serve un caso "incondizionato" per gli Integer!
    // Altrimenti non compila.
    case Integer t -> 0; 
};

3. Switch Statements: Tradizionale vs Pattern Matching Fino a Java 21, gli switch statements (che eseguono solo istruzioni senza restituire un valore) potevano omettere il default e ignorare i valori non previsti. Con l'introduzione del Pattern Matching, le regole del gioco cambiano:

  • Statement TRADIZIONALE (Costanti): Il default NON è obbligatorio. Se il valore non fa match con le costanti (es. case 1, case 2), lo switch viene ignorato e il programma procede senza errori.
  • Statement CON Pattern Matching: Il default (o l'esaustività) è OBBLIGATORIO. Se utilizzi anche solo un "Pattern label" (es. case Integer t), devi coprire il 100% delle possibilità, esattamente come in una expression. E se la variabile dello switch è di tipo Object, l'unico modo per coprire tutti i tipi possibili (String, Float, ecc.) è usare il default.

Esempio di Codice (Statement con Pattern Matching - Non compila senza default):

Object tentativo = 5;

// Questo è uno STATEMENT (non restituisce nulla, stampa e basta)
switch (tentativo) {
    case Integer t when t > 10 -> System.out.println("Maggiore");
    case Integer t when t <= 10 -> System.out.println("Minore o uguale");
    
    // ERRORE DI COMPILAZIONE SE OMETTI IL DEFAULT! 
    // Essendo 'tentativo' un Object, serve per gestire String, Float, ecc.
    default -> System.out.println("Non è un numero intero");
}

3.6 Cicli while e do/while

Definizioni e Concetti Un ciclo è una struttura di controllo ripetitiva che può eseguire un'istruzione o un blocco di codice più volte in successione. Il ciclo while valuta un'espressione booleana di terminazione prima di ogni iterazione; il ciclo do/while, spesso presentato come forma alternativa del ciclo condizionale, garantisce l'esecuzione del blocco almeno una volta prima della valutazione della condizione.

3.7 Il Ciclo for di Base

Definizioni e Concetti Il ciclo for è composto da tre sezioni separate da punti e virgola: inizializzazione, espressione booleana (condizione) e aggiornamento. Le sezioni di inizializzazione e di aggiornamento possono contenere più istruzioni separate da virgole. Le variabili dichiarate nel blocco di inizializzazione hanno scope limitato e sono accessibili solo all'interno del ciclo for.

⚠️ Tranello (Inizializzazione multipla con tipi diversi nel ciclo for): Nella sezione di inizializzazione di un ciclo for tradizionale, è possibile dichiarare più variabili, ma devono condividere lo stesso tipo dichiarato una sola volta.

Esempio di Codice (non compila):

for (int i=0, long j=3; i<10; i++) { ... } // DOES NOT COMPILE: tipi diversi

3.8 Il Ciclo for-each Potenziato

Definizioni e Concetti Dichiarato con una sezione di inizializzazione e un oggetto su cui iterare, il lato destro deve essere un array integrato di Java o un oggetto il cui tipo implementa java.lang.Iterable. In pratica rientrano le collezioni come List e Set; la classe Map non può essere usata direttamente come sorgente del for-each (non implementa Iterable), anche se espone metodi che restituiscono viste di tipo Collection sulle quali invece si può iterare.

⚠️ Tranello (Tipi non supportati nel for-each): Il lato destro di un ciclo for-each deve essere un array o implementare Iterable. Una String o una Map (direttamente) causano errore.

Esempio di Codice (non compila):

String birds = "Parrots";
for (char c : birds) { ... } // DOES NOT COMPILE: String non è un array o Iterable

3.9 Controllo del Flusso con Branching: Etichette e Salti

Definizioni e Concetti Un'etichetta (label) è un identificatore che segue le regole degli identificatori Java, seguito da due punti (:), applicabile a cicli o switch per gestire salti più articolati. Java permette l'uso di etichette con i cicli while, do/while, for e con lo switch. Le istruzioni break e continue modificano il flusso all'interno di uno statement, mentre return può essere usato come alternativa a etichette e break per uscire da metodi.

Comportamento di break e continue

  • break: esce dalla struttura di controllo corrente o da quella etichettata se si usa la forma break nomeEtichetta;.
  • continue: salta alla fine dell'iterazione corrente e passa alla valutazione della condizione del ciclo (o all'iterazione successiva nel for).
  • switch: accetta break (anche per uscire dal ramo) ma non accetta continue se lo switch non è annidato in un ciclo.

yield nelle switch expression Nei blocchi case scritti con graffe in una switch expression, si usa yield per restituire il valore del ramo, in modo analogo a un return locale al ramo; è richiesto quando il ramo è un blocco che deve produrre un valore, salvo che il blocco non termini per esempio con un'eccezione. La parola chiave yield non si usa nelle switch statement tradizionali.

⚠️ Tranello (continue nello switch): Mentre break è ammesso sia nei cicli che negli switch, continue è ammesso solo nei cicli. Usare continue dentro un ramo di uno switch che non è all'interno di un ciclo causa errore.

Esempio di Codice (non compila):

switch (day) {
   case 1: continue; // DOES NOT COMPILE: continue non ammesso qui
}

⚠️ Tranello (yield fuori dalle switch expressions): La parola chiave yield è specifica per restituire valori dalle switch expressions e non può essere usata negli switch statements tradizionali o fuori da essi.

4.1 Creazione e Manipolazione di Stringhe (String)

Definizioni e Concetti Una String è fondamentalmente una sequenza di caratteri ed è un tipo di riferimento speciale che non richiede necessariamente l'operatore new per essere istanziato. La classe String è speciale e non richiede necessariamente di essere istanziata con new. Le stringhe sono immutabili, il che significa che chiamare un metodo su una String restituirà un oggetto diverso invece di cambiare il valore del riferimento originale. In altre parole, chiamare un metodo su una String restituisce un altro oggetto String, anziché mutare il valore del riferimento. Java utilizza il "pool delle stringhe" (o pool di internamento) per raccogliere e riutilizzare i valori letterali e le costanti, ottimizzando l'uso della memoria. Il string pool, noto anche come intern pool, è un'area nella Java Virtual Machine (JVM) che raccoglie tutti i valori letterali e le costanti presenti nel programma. Un code point (punto di codice Unicode) è un valore numerico per un carattere nel modello Unicode; può riguardare unità più ampie del singolo valore char a 16 bit. Contesto — API (interfaccia di programmazione applicativa): in questo senso, un'API è un insieme di classi o definizioni di interfacce che espone un blocco di funzionalità (le API principali del linguaggio e delle librerie standard).

Regole di Sintassi e Comportamento Operativo L'ordine delle operazioni e il tipo degli operandi determinano se il simbolo + indichi un'addizione numerica o una concatenazione. Accostare due String in sequenza (concatenarle) costituisce la concatenazione di stringhe. Per la manipolazione delle stringhe vigono le regole: 1. se entrambi gli operandi sono numerici, + indica l'addizione numerica; 2. se almeno un operando è una String, + indica la concatenazione; 3. l'espressione viene valutata da sinistra a destra («se coinvolgi due numeri, usa l'addizione numerica, altrimenti la concatenazione, e valuta da sinistra a destra»). Gli indici partono da 0.

Metodi principali e sintassi

  • substring(): public String substring(int beginIndex) e public String substring(int beginIndex, int endIndex). beginIndex è incluso, endIndex è escluso. Il parametro endIndex può valere uno in più rispetto all'ultima posizione della sequenza, se si desidera fermarsi proprio a fine sequenza.
  • indent(n): con un valore positivo aggiunge lo stesso numero di spazi all'inizio di ogni riga; con un valore negativo tenta di rimuovere altrettanti spazi; con zero l'indentazione non cambia. Normalizza le interruzioni di riga e, se manca, aggiunge un a capo finale.
  • stripIndent(): elimina lo spazio bianco incidentale (legato al solo layout): le righe non vuote vengono spostate a sinistra in modo coerente; non aggiunge un'interruzione finale se manca.
  • Simboli di formattazione: %s (adatto a un valore qualsiasi, spesso String), %d (interi come int e long), %f (valori a virgola come float e double), %n (inserisce un'interruzione di riga secondo il separatore di riga del sistema operativo).

⚠️ Tranello (Ordine di valutazione): L'ordine delle operazioni è un classico tranello.

Esempio di Codice (Ordine di valutazione):

System.out.println(1 + 2 + "c"); // Stampa 3c
System.out.println("c" + 1 + 2); // Stampa c12

⚠️ Tranello (substring — indici): l'indice finale di substring(inizio, fine) non fa parte del risultato. "12345".substring(1, 3) restituisce "23", non "234".

Esempio di Codice (substring):

System.out.println("12345".substring(1, 3)); // Stampa 23

⚠️ Tranello (Risultato ignorato sull'immutabilità): Un altro tranello riguarda i risultati non assegnati a causa dell'immutabilità: ignorare il valore di ritorno di un metodo su una String rende l'istruzione inutile.

Esempio di Codice (concat dimenticata):

String s = "1";
s.concat("2");
System.out.println(s); // Stampa 1 (il risultato di concat è andato perduto)

4.2 Utilizzo della classe StringBuilder

Definizioni e Concetti A differenza di String, StringBuilder è mutabile e non è una sequenza di caratteri immutabile. StringBuilder è una sequenza di caratteri mutabile. Quando si concatenano chiamate ai metodi di StringBuilder, l'oggetto cambia il proprio stato interno e restituisce un riferimento a se stesso, a differenza di String dove ogni chiamata crea un nuovo oggetto. La maggior parte dei metodi restituisce un riferimento all'oggetto corrente. Questa classe è fondamentale per migliorare le prestazioni quando si devono costruire stringhe in modo dinamico, ad esempio all'interno di un ciclo for.

Regole di Sintassi e Comportamento Operativo

  • Method chaining (concatenazione di chiamate a metodo): tecnica in cui ogni metodo restituisce l'oggetto su cui invocare il passo successivo. Per leggere il codice, si parte da sinistra, si valuta il primo metodo, poi quello successivo sul valore restituito, fino al punto e virgola.
  • Sintassi insert(): public StringBuilder insert(int offset, String str). L'offset è l'indice in cui inserire il parametro richiesto.
  • append(), insert(), delete(): modificano lo stato interno del StringBuilder. substring() su StringBuilder restituisce una nuova String (non muta il builder).
  • equals() su StringBuilder: a differenza di String, confronta i riferimenti, non il contenuto dei caratteri.

⚠️ Tranello (append e insert concatenati): valutare insert e append nell'ordine in cui compaiono; ogni operazione usa gli indici dopo le modifiche precedenti.

Esempio di Codice (append/insert — domanda d'esame tipica):

var sb = new StringBuilder();
sb.append("aaa").insert(1, "bb").insert(4, "ccc");
System.out.println(sb); // Stampa abbaaccc

⚠️ Tranello (Riferimenti e stato interno): Il tranello principale risiede nella modifica dello stato interno: se si concatenano chiamate ai metodi di StringBuilder, l'oggetto muta il proprio stato e restituisce un riferimento a se stesso.

Esempio di Codice (stesso oggetto):

var sb = new StringBuilder("aaa");
var sb2 = sb.append("bbb");
System.out.println(sb == sb2); // true (puntano allo stesso oggetto)

4.3 Comprensione dell'Uguaglianza (== vs equals)

Definizioni e Concetti L'operatore == controlla l'uguaglianza dei riferimenti (due variabili puntano allo stesso oggetto in memoria). Per String, equals() confronta invece il contenuto; l'esito di un confronto con == tra letterali equivalenti o tra letterale e istanza dipende dal string pool, che raccoglie i valori letterali e le costanti del programma. Il metodo equals() segue l'implementazione della classe: per String verifica l'uguaglianza carattere per carattere.

⚠️ Tranello (String pool e intern()): È un tranello d'esame comune l'uso di intern() per forzare una stringa nel pool, rendendo vero il confronto con == contro un letterale equivalente.

Esempio di Codice (== e intern()):

var s = "Hello";
var t = new String(s);
System.out.println("Hello".equals(s)); // vero (contenuto uguale)
System.out.println(s == t);            // falso (oggetti diversi)
System.out.println("Hello" == s);      // vero (stesso letterale nel pool)
System.out.println(s == t.intern());   // vero (t entra nel pool)

I letterali String provengono dal string pool: due letterali con lo stesso contenuto si riferiscono allo stesso oggetto e risultano uguali con ==.

4.4 Comprensione degli Array

Definizioni e Concetti Un array è un'area di memoria a dimensione fissa sull'heap che riserva spazio per elementi primitivi o riferimenti a oggetti. È una lista ordinata che può contenere duplicati. Gli indici iniziano sempre da zero e la proprietà length restituisce il numero di posizioni allocate, senza parentesi perché non è un metodo. L'attributo length non descrive il contenuto delle celle, ma solo quante posizioni sono state allocate. Un array anonimo è un array creato e inizializzato sul posto (es. method(new int[] { 1, 2, 3 })) senza prima assegnarlo a una variabile con nome; tipo e valori iniziali compaiono nello stesso costrutto new.

Regole di Sintassi e Comportamento Operativo Dichiarazioni legali includono int[] numAnimals;, int [] numAnimals2;, int []numAnimals3;, int numAnimals4[];, int numAnimals5 [];. Per le dichiarazioni multiple: int[] ids, types; crea due variabili di tipo int[], mentre int ids[], types; crea una variabile di tipo int[] e una variabile di tipo int.

⚠️ Tranello (Parentesi dopo il nome della variabile): Il posizionamento di [] nella stessa riga con più variabili cambia i tipi: con int[] ids, types; entrambe sono int[]; con int ids[], types; solo la prima è int[] e la seconda è int.

Esempio di Codice (dichiarazioni multiple e parentesi):

int a[], b; // a è int[], b è int
int[] c, d; // c è int[], d è int[]

Ricerca e Comparazione

  • Arrays.sort(): ordina l'array sul posto; in pratica si usa spesso prima di binarySearch, perché la ricerca binaria presuppone un ordine definito tra gli elementi.
  • Arrays.compare(): restituisce un valore negativo se il primo array è minore del secondo, positivo se il primo è maggiore del secondo, 0 se risultano equivalenti secondo l'ordine definito dalle regole sotto.
  • Arrays.mismatch(): restituisce l'indice della prima posizione in cui i due array differiscono, oppure -1 se risultano equivalenti sulla porzione comune; si combina con compare() per verificare equivalenza o divergenza tra sequenze.
  • Arrays.equals() / deepEquals(): equals() confronta il contenuto di array monodimensionali; deepEquals() va usato per array multidimensionali (es. int[][]).
  • Definizione di "minore" per la comparazione: 1. null è minore di qualsiasi altro valore. 2. Per i numeri vale l'ordine aritmetico. 3. Per le stringhe, una è minore se è prefisso dell'altra. 4. Tra stringhe/caratteri, le cifre precedono le lettere. 5. Tra stringhe/caratteri, le lettere maiuscole precedono (sono minori di) le minuscole, secondo le regole API.
  • binarySearch(): 1. Se l'elemento è presente, restituisce l'indice corrispondente. 2. Se non c'è, il valore di ritorno è l'opposto dell'indice in cui andrebbe inserito, meno uno (cioè -(inserimento) - 1).

Esempio di Codice (binarySearch, elemento assente):

int[] list = {2, 4, 6};
System.out.println(Arrays.binarySearch(list, 3)); // Stampa -2

⚠️ Tranello (ArrayStoreException): Si verifica a runtime quando si assegna a uno slot dell'array un oggetto il cui tipo non è compatibile con il tipo reale dell'array, pur avendo compilato grazie a un riferimento più generico (es. Object[] che punta a un String[]).

Nota (modello del libro): Un StringBuilder può in linea di principio finire in un Object[], ma se il riferimento Object[] è in realtà un String[], non si ha un vero Object[] generico: lo slot deve accettare solo String, quindi assegnare un StringBuilder provoca ArrayStoreException a runtime.

Esempio di Codice (ArrayStoreException):

String[] strings = { "stringValue" };
Object[] objects = strings;
objects[0] = new StringBuilder(); // Compila; a runtime: ArrayStoreException

⚠️ Tranelli (Indici e ricerca binaria):

  • ArrayIndexOutOfBoundsException: La lunghezza è sempre di un'unità in più dell'indice valido massimo (0 … length - 1). Un errore tipico è il ciclo for con <= al posto di < rispetto a length, accedendo a un indice inesistente. È inoltre un tranello usare l'indice length come se fosse valido, perché l'ultimo indice lecito è length - 1.

Esempio di Codice (indice fuori intervallo):

int[] nums = new int[3];
nums[3] = 0; // Lancia ArrayIndexOutOfBoundsException
  • Ricerca binaria: binarySearch richiede un array ordinato; in caso contrario il risultato non è definito. Usa sort() sull'array o rispetta l'ordine come precondizione.

4.5 Calcoli con le API Math

Definizioni e Concetti Java include la classe Math con numerosi metodi statici per eseguire calcoli comuni, come min(), max(), round(), ceil(), floor(), pow() e random(). Tutti i metodi della classe Math sono static; non serve creare un'istanza di Math per utilizzarli. Per l'esame 1Z0-830 è essenziale associare a ogni chiamata il tipo primitivo di ritorno atteso in base al tipo di ingresso (es. float vs double): prestare attenzione speciale ai tipi di ritorno nelle domande su Math — sono un'ottima occasione per i tranelli! Vengono inoltre trattate le classi BigInteger e BigDecimal per gestire numeri che superano le capacità dei primitivi o che richiedono precisione decimale assoluta. Come String, sono immutabili: si concatenano le chiamate ai metodi e si riassegna il risultato.

Regole di Sintassi e Comportamento Operativo

  • min() / max(): quattro overload ciascuno (double, float, int, long); restituiscono il valore minore o maggiore tra i due operandi, dello stesso tipo degli argomenti.
  • round(): elimina la parte decimale; se la frazione è ≥ 0,5 arrotonda per eccesso. Con double restituisce long; con float restituisce int.
  • ceil() / floor(): restituiscono sempre un double. ceil() arrotonda verso l'alto all'intero successivo; floor() verso il basso all'intero precedente (attenzione ai negativi).
  • pow(): restituisce sempre un double (es. Math.pow(5, 2) → 25.0).
  • random(): restituisce un double ≥ 0,0 e < 1,0 (mai negativo, mai esattamente 1.0).

Metodi principali e sintassi

int first = Math.max(3, 7);           // 7
int second = Math.min(7, -9);           // -9
long low = Math.round(123.45);          // 123
long high = Math.round(123.50);         // 124
int fromFloat = Math.round(123.45f);    // 123
double c = Math.ceil(3.14);             // 4.0
double f = Math.floor(3.14);            // 3.0
double squared = Math.pow(5, 2);        // 25.0
double num = Math.random();             // valore in [0.0, 1.0)
  • BigInteger / BigDecimal: preferire valueOf() ai costruttori. Si può passare un long a entrambi; un double solo a BigDecimal. Costanti utili: BigInteger.ZERO, BigDecimal.ONE. Operazioni comuni: add(), multiply(), divide(), max(). BigInteger gestisce interi oltre i limiti di long (es. new BigInteger("12345123451234512345") — il corrispondente letterale long non compila).

⚠️ Tranello (BigDecimal e errore di virgola mobile): i double possono produrre risultati decimali imprecisi; per calcoli monetari usare BigDecimal.

Esempio di Codice (floating-point error):

double amountInCents1 = 64.1 * 100;
System.out.println(amountInCents1); // 6409.999999999999

BigDecimal amountInCents2 = BigDecimal.valueOf(64.1)
    .multiply(BigDecimal.valueOf(100));
System.out.println(amountInCents2); // 6410.0

⚠️ Tranello (Tipi di ritorno): Math.round(5.5) restituisce un long, non un int. Math.floor(6.6) restituisce un double. Math.random() restituisce un double, quindi float three = Math.random(); non compila senza cast esplicito.

Esempio di Codice (errori di compilazione sui tipi di ritorno):

int two = Math.round(1.0);        // NON COMPILA (round(double) → long)
float three = Math.random();      // NON COMPILA (random() → double)
double one = Math.pow(1, 2);      // OK → 1.0

⚠️ Tranello (ceil/floor con negativi): ceil(-2.3) restituisce -2.0 (intero superiore, non -3). floor(-2.3) restituisce -3.0.

Esempio di Codice (negativi):

System.out.println(Math.ceil(-2.3));  // -2.0
System.out.println(Math.floor(-2.3)); // -3.0

⚠️ Tranello (Istanza di Math): i metodi sono static e la classe non è istanziabile (costruttore privato), quindi il codice non compila.

Esempio di Codice (new Math):

var math = new Math(); // NON COMPILA

4.6 Lavoro con Date e Ore (Date-Time API)

Definizioni e Concetti Le API per data e ora (java.time.*) includono LocalDate (solo data), LocalTime (solo ora), LocalDateTime (data e ora, senza fuso), ZonedDateTime (data, ora e fuso orario) e Instant (istante preciso in UTC/GMT). Sono tutte classi immutabili: plus(), minus() e with() restituiscono nuovi oggetti. Period rappresenta un intervallo basato su giorni, mesi o anni; Duration riguarda unità più fini (ore, minuti, secondi, nanosecondi). La vecchia classe java.util.Date non è all'esame. Per usare le classi moderne serve import java.time.*;.

Regole di Sintassi e Comportamento Operativo Non si costruiscono oggetti data/ora con new: si usano metodi statici of() o now() (factory pattern, costruttori privati). Per i mesi, Java conta da 1 (gennaio = 1), non da 0 — unica eccezione alla regola «Java conta da 0».

  • Scelta del tipo: LocalDate = solo data; LocalTime = solo ora; LocalDateTime = data + ora senza fuso; ZonedDateTime = data + ora + fuso (es. «conferenza alle 9 EST»).
  • Creazione: LocalDate.of(2025, Month.JANUARY, 20) oppure LocalDate.of(2025, 1, 20). LocalTime.of(6, 15) o con secondi/nanosecondi. ZonedDateTime.of(date, time, ZoneId.of("US/Eastern")).
  • Manipolazione: riassegnare sempre il risultato: date = date.plusDays(2). Metodi comuni: plusDays/Weeks/Months/Years, minusHours/Minutes/Seconds, withDayOfMonth(), withYear().
  • Anni bisestili: se si aggiunge un mese e il giorno non esiste (es. 29 febbraio in un anno non bisestile), Java regola alla data valida più vicina (es. 2025-01-29 + 1 mese → 2025-02-28). Anno bisestile: multiplo di 4 o 400, non altri multipli di 100.
  • Conversioni (at...): LocalDate.atTime(), LocalDate.atStartOfDay(), LocalTime.atDate(), LocalDateTime.atZone(). Da ZonedDateTime si ottiene un Instant con toInstant(). Non si può convertire un LocalDateTime in Instant (manca il fuso orario).
  • Period: Period.ofYears(1), ofMonths(3), ofWeeks(-3), ofDays(2), of(1, 0, 7). Period.between(data1, data2) — l'ordine conta. Output in formato ISO-8601: P3M (3 mesi), P7D (7 giorni), P-7D (7 giorni indietro). Non concatenare factory statici: Period.ofYears(1).ofWeeks(1) usa solo l'ultimo metodo.
  • Duration: ofDays(), ofHours(), ofMinutes(), ofSeconds(), ofMillis(), ofNanos(), oppure Duration.of(1, ChronoUnit.HALF_DAYS) (12 ore). Duration.between(istante1, istante2).
  • ChronoUnit: ChronoUnit.HOURS.between(one, two) calcola la differenza; tronca verso zero (non arrotonda). Funziona con LocalDateTime, ZonedDateTime, Instant.
  • Period vs Duration: Period con LocalDate, LocalDateTime, ZonedDateTime — non con LocalTime. Duration con LocalTime, LocalDateTime, ZonedDateTime — non con LocalDate.
  • Metodi per tipo (sintesi):
Metodo LocalDate LocalTime LocalDateTime / ZonedDateTime
plusDays() / minusDays() ✅ ❌ ✅
plusMonths() / minusMonths() ✅ ❌ ✅
plusHours() / minusHours() ❌ ✅ ✅
plusMinutes() / minusMinutes() ❌ ✅ ✅
plusSeconds() / minusSeconds() ❌ ✅ ✅
  • DateTimeFormatter: formattazione e parsing con costanti ISO (ISO_LOCAL_DATE, ISO_LOCAL_TIME, ISO_LOCAL_DATE_TIME) o pattern personalizzato DateTimeFormatter.ofPattern("MM/dd/yyyy hh:mm:ss"). Sintassi equivalente: date.format(formatter) oppure formatter.format(date). Parsing: LocalDate.parse("2025-10-20") o formatter.parse("2025-10-20"). Testo letterale nel pattern va racchiuso tra apici singoli ('at'); per un apice nel testo usare due apici consecutivi (''). M = mese, m = minuto; H = 24 ore, h = 12 ore.

⚠️ Tranello (Nessun new sui tipi java.time): var d = new LocalDate(); non compila.

Esempio di Codice (of come factory):

var d = LocalDate.of(2025, Month.JANUARY, 1);

⚠️ Tranello (Immutabilità — risultato ignorato): ignorare il valore di ritorno di plus(), minus() o with() lascia invariato l'oggetto originale (come con String.concat()).

Esempio di Codice (plusDays dimenticato — domanda d'esame tipica):

var date = LocalDate.of(2025, 4, 3);
date.plusDays(2);
date.plusHours(3); // NON COMPILA (LocalDate non ha ore)
System.out.println(date.getYear() + " " + date.getMonth() + " " + date.getDayOfMonth());
// Stampa: 2025 APRIL 3 (plusDays ignorato; plusHours non compila)

Esempio di Codice (corretto):

var date = LocalDate.of(2025, 2, 10);
var cutoff = date.withDayOfMonth(28).minusWeeks(1); // 2025-02-21
long days = date.until(cutoff, ChronoUnit.DAYS);     // 11

⚠️ Tranello (Metodi orario su data sola): plusHours(), plusMinutes(), plusSeconds() su LocalDate causano errore di compilazione. Lo stesso vale per Period su LocalTime e Duration su LocalDate.

Esempio di Codice (plusHours su LocalDate):

var date = LocalDate.of(2025, 4, 3);
date.plusHours(3); // NON COMPILA

⚠️ Tranello (of() e valori non validi): parametri fuori intervallo lanciano java.time.DateTimeException.

Esempio di Codice (giorno non valido):

var d = LocalDate.of(2025, Month.JANUARY, 32); // DateTimeException

⚠️ Tranello (Period — factory non concatenabili):

var wrong = Period.ofYears(1).ofWeeks(1); // equivale a Period.ofWeeks(1) soltanto!
var right = Period.of(1, 0, 7);           // 1 anno + 7 giorni
System.out.println(Period.ofMonths(3));   // Stampa P3M
System.out.println(Period.between(
    LocalDate.of(2025, 12, 25), LocalDate.of(2026, 1, 1))); // Stampa P7D

⚠️ Tranello (Period/Duration su tipo errato — runtime): oltre agli errori di compilazione, usare Period su LocalTime o Duration su LocalDate lancia un'eccezione a runtime.

Esempio di Codice (Period su LocalTime):

var time = LocalTime.of(12, 0);
var period = Period.ofDays(1);
time.plus(period); // UnsupportedTemporalTypeException a runtime

⚠️ Tranello (ChronoUnit.between() tronca): il risultato è un valore intero troncato, non arrotondato.

Esempio di Codice (ChronoUnit):

var one = LocalDateTime.of(2025, 1, 1, 10, 0);
var two = LocalDateTime.of(2025, 1, 1, 10, 45);
System.out.println(ChronoUnit.HOURS.between(one, two));   // 0 (non 1)
System.out.println(ChronoUnit.MINUTES.between(one, two)); // 45

⚠️ Tranello (DateTimeFormatter — tipo incompatibile): formattare una data con un formatter per l'ora (o viceversa) lancia un'eccezione a runtime.

Esempio di Codice (formatter incompatibile):

var date = LocalDate.of(2025, Month.OCTOBER, 20);
date.format(DateTimeFormatter.ISO_LOCAL_TIME); // RuntimeException

⚠️ Tranello (DateTimeFormatter — pattern invalido o testo non escapato): caratteri letterali nel pattern vanno racchiusi tra apici singoli; altrimenti il formatter li interpreta come simboli e può lanciare IllegalArgumentException.

Esempio di Codice (pattern e parsing):

var formatter = DateTimeFormatter.ofPattern("MMMM dd, yyyy 'at' hh:mm");
var dt = LocalDateTime.of(2025, Month.OCTOBER, 20, 6, 15);
System.out.println(dt.format(formatter)); // October 20, 2025 at 06:15

var parsed = LocalDate.parse("2025-10-20", DateTimeFormatter.ISO_LOCAL_DATE);

DateTimeFormatter.ofPattern("The time is hh:mm"); // IllegalArgumentException (T non valido)
DateTimeFormatter.ofPattern("MMMM dd', Party''s at' hh:mm"); // apice escapato con ''

⚠️ Tranello (Ora legale — DST, fuso US/Eastern): il cambio avviene alle 2:00 a.m. di domenica. A marzo («spring forward») da 1:59 si salta alle 3:00 — non esiste 2:30; plusHours(1) da 1:30 porta a 3:30. A novembre («fall back») l'ora 1:00–1:59 si ripete; plusHours(1) da 1:30 può restare 1:30. Creare un orario inesistente (es. 2:30 a marzo) fa rollare avanti Java (es. 3:30).

Esempio di Codice (spring forward — 9 marzo 2025):

var zone = ZoneId.of("US/Eastern");
var dateTime = ZonedDateTime.of(
    LocalDate.of(2025, Month.MARCH, 9), LocalTime.of(1, 30), zone);
System.out.println(dateTime);              // 2025-03-09T01:30-05:00[US/Eastern]
dateTime = dateTime.plusHours(1);
System.out.println(dateTime);              // 2025-03-09T03:30-04:00[US/Eastern]
System.out.println(dateTime.getHour());    // 3 (non 2!)

Esempio di Codice (orario inesistente — roll forward):

var dateTime = ZonedDateTime.of(
    LocalDate.of(2025, Month.MARCH, 9), LocalTime.of(2, 30),
    ZoneId.of("US/Eastern"));
System.out.println(dateTime); // 2025-03-09T03:30-04:00[US/Eastern]

Esempio di Codice (fall back — 2 novembre 2025):

var zone = ZoneId.of("US/Eastern");
var dateTime = ZonedDateTime.of(
    LocalDate.of(2025, Month.NOVEMBER, 2), LocalTime.of(1, 30), zone);
dateTime = dateTime.plusHours(1);
System.out.println(dateTime); // 2025-11-02T01:30-05:00 (ancora 1:30!)
dateTime = dateTime.plusHours(1);
System.out.println(dateTime); // 2025-11-02T02:30-05:00

Ch 5: Methods

5.1 Progettazione dei Metodi (Designing Methods)

Definizioni e Concetti Una dichiarazione di metodo (method declaration) elenca tutte le informazioni necessarie per chiamare il metodo: in pratica, modificatore di accesso, eventuali specificatori opzionali (optional specifiers, come static o final prima del tipo di ritorno), tipo di ritorno (return type), nome, lista dei parametri (parameter list) tra parentesi, lista delle eccezioni controllate (checked exceptions) e corpo del metodo (method body) tra parentesi graffe. Il tipo di ritorno void indica che non si restituisce alcun valore. Ogni parametro (parameter) è un valore o riferimento che il chiamante fornisce al metodo. La dichiarazione deve includere un corpo, a meno che il metodo non sia dichiarato abstract (o definito in contesti che lo consentono, come in una interfaccia in casi particolari).

  • Firma del metodo (Method Signature): composta esclusivamente dal nome del metodo e dalla lista dei parametri; indica a Java quale metodo invocare. Non include il tipo di ritorno né i modificatori di accesso.
  • Modificatore di accesso (Access Modifier): fissa da quali classi o package il metodo è utilizzabile e applica le regole di visibilità tra le parti del programma.
  • Ordine degli elementi: tassativo: 1. Modificatore di accesso, 2. Specificatori opzionali, 3. Tipo di ritorno (obbligatorio, salvo costruttori), 4. Nome del metodo, 5. Lista dei parametri (obbligatoria, anche se vuota), 6. Lista delle eccezioni (opzionale), 7. Corpo del metodo tra graffe (obbligatorio tranne per metodi abstract).
  • Requisito delle parentesi: obbligatorie dopo il nome del metodo, anche con lista dei parametri vuota.

⚠️ Tranelli (Dichiarazione di metodo):

  • Quattro livelli di visibilità: le uniche modalità di accesso per i metodi sono public, protected, accesso di package (nessuna parola chiave) e private. La parola chiave default non è un modificatore di accesso: compare negli switch e in altri contesti (es. interfacce); in esame è frequente confonderla con un quarto modificatore “default” come se stesse al pari delle altre quattro opzioni.
  • Uso di default sui metodi di classe: su una classe, default void m() non compila, perché default non qualifica in quel modo l’accesso.
  • Posizionamento di modificatori e specificatori: i modificatori di accesso e gli specificatori opzionali possono permutare tra loro, ma devono comparire tutti prima del tipo di ritorno; non posizionare il modificatore di accesso dopo void o dopo altro tipo.
  • Nomi illegali: un identificatore non può iniziare con una cifra, non può coincidere con una parola riservata e (in linea con le regole degli identificatori) non può consistere in un singolo carattere _ come nome del metodo.
  • Mancanza del return: in un metodo con tipo di ritorno non-void, ogni percorso deve restituire un valore, anche se una condizione sembra sempre vera (es. if (1 < 2)); il compilatore non valuta a fondo l’if a favore del programmatore.
  • Ritorno long in un metodo dichiarato int: non si può restituire un long o un valore “più grande” senza cast esplicito rispetto al tipo dichiarato.

Esempio di Codice (Modificatori default e public fuori posto):

public class ParkTrip {
   default void skip2() {} // DOES NOT COMPILE: default non è un modificatore di accesso
   void public skip3() {}  // DOES NOT COMPILE: public dopo il tipo di ritorno
}

Esempio di Codice (Specificatori in ordine errato e public dopo void):

public void final bike6() {} // DOES NOT COMPILE: specificatore o ordine non validi rispetto a tipo e nome

Esempio di Codice (Ritorno mancante):

String hike7(int a) {
   if (1 < 2) return "orange";
} // DOES NOT COMPILE: manca return sul ramo “else”

Sintesi: anche se 1 < 2 è sempre vero, il compilatore presuppone un ramo falso e richiede un return o un errore in quel percorso.

Esempio di Codice (Tipo di ritorno incompatibile):

int getHeight3() {
   long temp = 9L;
   return temp; // DOES NOT COMPILE: non si restituisce un long in un int senza cast
}

Esempio di Codice (Nomi di metodo non validi):

public void 2jog() {} // DOES NOT COMPILE: identificatore non può iniziare con cifre
public void _() {}    // DOES NOT COMPILE: un solo underscore come nome metodo

5.2 Dichiarazione di Variabili Locali e d'Istanza (Declaring Local and Instance Variables)

Definizioni e Concetti

  • Variabile locale: definita in un metodo o blocco. Non ha valore di default e va inizializzata prima della lettura. L’unico modificatore ammesso è final (inibisce la riassegnazione). Le classi locali e le lambda possono catturare solo variabili locali effectively final (o esplicitamente final), cioè non riassegnate dopo il primo assegnamento.
  • Variabile d’istanza: membro di classe, una copia per oggetto; ha valori predefiniti (es. 0, null, false).
  • Campo d’istanza final: va inizializzato esattamente una volta: in fase di dichiarazione, in un inizializzatore d’istanza oppure in un costruttore (secondo le regole del linguaggio sulle assegnazioni consentite).
  • Campo static final: va inizializzato esattamente una volta: in fase di dichiarazione oppure in un inizializzatore statico.

⚠️ Tranelli (Variabili locali e d'istanza):

  • Inizializzazione parziale: qualsiasi percorso in cui la variabile locale possa restare non inizializzata prima di una lettura genera errore di compilazione.
  • Dichiarazione multi-tipo in un’unica riga: consentita solo se condividono lo stesso tipo; int num, String value; non compila.
  • Stesso tipo in dichiarazione abbreviata: la possibilità di scrivere int a, b, c; resta vincolata a un unico tipo per tutte le variabili elencate.

Esempio di Codice (Lettura su ramo possibilmente falso):

public void findAnswer(boolean check) {
   int onlyOneBranch;
   if (check) { onlyOneBranch = 1; }
   System.out.println(onlyOneBranch); // DOES NOT COMPILE: se check è false, non inizializzata
}

Sintesi: se esiste almeno un percorso in cui la variabile non è stata assegnata, l’ultima lettura segnala errore.

Esempio di Codice (Tipi misti in una dichiarazione):

int num, String value; // DOES NOT COMPILE: la scorciatoia su più variabili vale solo con stesso tipo

5.3 Lavoro con i Varargs (Working with Varargs)

Definizioni e Concetti I varargs (T... nome) permettono di passare un numero variabile di argomenti, che a runtime vengono trattati come un array. È lecito passare un array esplicito oppure un elenco di argomenti separati da virgola, purché rispettino il tipo atteso. Regole: al più un varargs per firma, e, se c’è, deve essere l’ultimo parametro.

⚠️ Tranelli (Varargs):

  • Passaggio null: dato un parametro int... steps, l’espressione null non è un int; Java la interpreta come riferimento a un array nullo, non come “assenza di elementi” (a differenza del caso senza argomenti, ove si ottiene spesso un array di lunghezza 0) e su quel riferimento null ogni accesso, es. a .length, lancia NullPointerException.

Esempio di Codice (Sintassi varargs proibite):

public void walk3(int... steps, int start) {}  // DOES NOT COMPILE: varargs non in ultima posizione
public void walk4(int... start, int... steps) {} // DOES NOT COMPILE: al massimo un varargs

Esempio di Codice (Null in un varargs a runtime):

public void walkDog(int... steps) {
   int length = steps.length; // su null, NPE
}
// Esempio di chiamata:
walkDog(null); // NullPointerException quando si usa steps come array

5.4 Applicazione dei Modificatori di Accesso (Applying Access Modifiers)

Definizioni e Concetti I modificatori di accesso stabiliscono chi può usare un membro. L’ordine nella dichiarazione (modificatore di accesso prima del tipo di ritorno) è quello illustrato nel paragrafo 1. Java offre quattro livelli: private, accesso di package (nessuna parola chiave), protected e public. Il modificatore protected è il più articolato: oltre alla stessa classe e al package, consente accessi per ereditarietà e in certi casi tramite riferimenti al tipo di sottoclasse, secondo le regole del linguaggio.

Regole di Accessibilità

  1. private: accessibile solo all’interno della stessa classe.
  2. Accesso di package (default, senza parola chiave): accessibile dalla stessa classe e dalle altre classi nello stesso package.
  3. protected: stessa classe, stesso package e, in condizioni previste dalla regola del protected, le sottoclassi (anche in package diversi), con le limitazioni su come si attraversa il riferimento (tipo dichiarato vs. tipo reale).
  4. public: accessibile da qualsiasi punto del programma in cui il membro sia visibile.

⚠️ Tranello (Accesso protected e tipo del riferimento): un membro protected non è accessibile tramite un riferimento dichiarato con il tipo della superclasse se si opera da un package diverso da quello in cui il membro è reso protected, anche quando l’oggetto reale è un’istanza di sottoclasse. In esame, il caso Frog / Tadpole mette in luce la distinzione tra tipo statico del riferimento e regole d’accesso: Frog f = new Tadpole(); f.ribbit(); può non compilare con ribbit() protected definito in un altro package rispetto al codice chiamante.

Esempio di Codice (Tadpole / Frog):

// Esempio: Frog in package animal dichiara protected void ribbit()
// Tadpole in package other extends Frog
Frog f = new Tadpole();
f.ribbit(); // DOES NOT COMPILE: con il tipo dichiarato Frog, in questo scenario, non c’è accesso protected in un altro package

5.5 Accesso ai Dati Statici (Accessing Static Data)

Definizioni e Concetti Il modificatore static lega un membro alla classe: esiste in un’unica copia logica condivisa tra tutte le istanze. I metodi e i campi d’istanza possono richiamare membri static della stessa classe; viceversa, in un metodo o blocco static non si possono usare campi o metodi d’istanza senza un riferimento a un oggetto esplicito. Una costante unisce in genere static e final (immutabilità del valore dopo l’inizializzazione) e, per convenzione, spesso un nome in MAIUSCOLO con underscore tra le parole.

  • Inizializzatore statico: blocco static { ... } eseguito al caricamento della classe.
  • Riferimenti a membri d’istanza da contesto static: un campo o metodo d’istanza non ha this in un inizializzatore di campo static o in un inizializzatore statico; non si può quindi, ad esempio, inizializzare un campo static con un’espressione che usa un campo d’istanza “libero”.

⚠️ Tranelli (Membri statici):

  • Accesso tramite riferimento null: su un membro static la risoluzione è sul tipo della variabile; se la variabile è null, in lettura/invocazione static non scatta di regola un NullPointerException per il fatto in sé di avere riferimento nullo (il tranello d’esame è confondere con le chiamate su istanza).
  • Import static: scrivere import static pacchetto.Tipo.nome; o import static pacchetto.Tipo.*; (ordine: parola import prima, poi static); static import ... non è la sintassi corretta. L’import static importa membri static, non sostituisce un import normale se si intende importare l’intera classe come tipo.

Esempio di Codice (Accesso a membro statico tramite riferimento a null — tipico tranello d’esame):

Snake s = null;
System.out.println(s.hiss); // hiss è static: compila; nessun NPE solo perché s == null

Sintesi: per un membro static conta il tipo statico del riferimento, non l’oggetto sull’heap; non generalizzare ogni null a NullPointerException in questo scenario.

Esempio di Codice (Campo istanza in inizializzatore statico di campo statico):

public class Gorilla {
   public int total;
   public static double average = total / 5; // DOES NOT COMPILE: riferimento statico a campo istanza
}

Esempio di Codice (Import static errato):

import static java.util.Arrays;     // DOES NOT COMPILE: si importa un tipo, non un membro statico
static import java.util.Arrays.*;  // DOES NOT COMPILE: l'ordine corretto è import static, non l'inverso

5.6 Passaggio di Dati tra Metodi (Passing Data among Methods)

Definizioni e Concetti Java applica il passaggio per valore: alla chiamata, nel parametro formale viene copiato il valore dell’espressione passata. Se l’argomento è un riferimento a oggetto, la copiata è del riferimento; chiamato e chiamante possono così condividere lo stesso oggetto, ma se il metodo riassegna il parametro a un nuovo oggetto, la variabile del chiamante non cambia. I valori di ritorno possono essere ignorati dal chiamante: non è un errore di compilazione, ma, se il metodo restituisce un risultato significativo e nessuno lo usa, l’elaborazione che produce quel valore può risultare inutile rispetto all’intento (salvo che non si volesse solo un effetto collaterale).

  • Tipi primitivi: le modifiche al parametro non si riflettono sul chiamante.
  • Riferimenti a oggetti: modifiche allo stato dell’oggetto condiviso (campi, contenuto di collezioni, ecc.) restano visibili al chiamante; la sostituzione del riferimento locale al metodo, no.

5.7 Overloading dei Metodi (Overloading Methods)

Definizioni e Concetti L’overloading richiede lo stesso nome e parametri diversi (numero, tipo, ordine). Non basta variare solo il tipo di ritorno o i modificatori d’accesso: servono firme (nome + elenco parametri) distinte, altrimenti compaiono metodi duplicati.

Ordine di risoluzione (scelta del metodo sovraccaricato): in presenza di più candidati, Java prova, in quest’ordine:

  1. Corrispondenza esatta di tipi.
  2. Widening (promozione numerica) verso un tipo primitivo “più grande” dove le regole lo consentono.
  3. Autoboxing (es. int → Integer se serve un wrapper lato parametro atteso).
  4. Varargs come ultima risorsa, se i punti precedenti non bastano a scegliere in modo univoco.

Se due overload sono “vicini” nelle conversioni, il linguaggio dà in genere precedenza alla promozione primitiva (es. passaggio da int a long) rispetto all’autoboxing in un wrapper (es. Integer). Un esempio tipico: con glide(1, 2) e due metodi glide(long, long) e glide(Integer, Integer) si tende a selezionare la versione con long (promozione) anziché quella con Integer (boxing).

⚠️ Tranelli (Overloading):

  • Stessa lista di parametri, solo return diverso: non è un overload valido: dichiarazione duplicata.

Esempio di Codice (Differenze solo per tipo di ritorno):

public void fly(int numMiles) {}
public int fly(int numMiles) { return 1; } // DOES NOT COMPILE: stessa firma (nome + parametri)

Esempio (Risoluzione: promozione numerica e autoboxing): con chiamata glide(1, 2) e overload void glide(long i, long j) e void glide(Integer i, Integer j) si vince spesso l’overload con i long (promozione) rispetto a Integer (boxing), in linea con l’ordine di risoluzione sopra (da verificare sul codice reale, ma la logica d’esame resta: promozione prima del boxing ove applicabile).

5.8 Autoboxing e Unboxing (Autoboxing and Unboxing)

Definizioni e Concetti

  • Autoboxing: da tipo primitivo a tipo wrapper corrispondente (es. int a Integer) in contesti che lo prevedono, spesso senza cast esplicito.
  • Unboxing: da wrapper a primitivo; se il riferimento al wrapper è null, a runtime l’operazione sottintesa lancia NullPointerException (manca un valore con cui concretizzare il primitivo).

⚠️ Tranelli (Autoboxing e unboxing):

  • Promozione e boxing non “combinati” in un unico passo implicito verso Long: l’istruzione Long badGorilla = 8; non compila: un valore o letterale int non diventa, con un’unica conversione implicita, un riferimento Long (non è ammessa, in quella assegnazione, la doppia conversione: widening a long e poi boxing a Long nelle regole d’esame su questo modello).
  • Unboxing di null: estrarre il valore primitivo da un riferimento null a runtime produce NullPointerException (es. assegnare un Integer nullo a un int).

Esempio di Codice (Assegnazione a Long con letterale int):

Long badGorilla = 8; // DOES NOT COMPILE: non si applica in un colpo la combinazione voluta int → Long riferimento

Esempio di Codice (Unboxing e NullPointerException):

Character elephant = null;
char badElephant = elephant; // runtime: NullPointerException (unboxing su null)

Sintesi: sull’unboxing di null, aspettarsi sempre NPE a runtime, non un valore primitivo “nullo” (i primitivi non sono nullable).

Ch 6: Class Design

6.1 Comprensione dell'ereditarietà (Inheritance)

Definizioni e Concetti

  • Inheritance (Ereditarietà): L'ereditarietà è il processo mediante il quale una sottoclasse include automaticamente determinati membri della classe, inclusi primitivi, oggetti o metodi, definiti nella classe genitrice.
  • Subclass / Child Class (Sottoclasse / Classe Figlia): Qualsiasi classe che eredita da un'altra classe è definita sottoclasse o classe figlia, in quanto è considerata una discendente di tale classe.
  • Superclass / Parent Class (Superclasse / Classe Genitrice): La classe da cui il "figlio" eredita è definita superclasse o classe genitrice, in quanto è considerata un antenato della classe.
  • Single Inheritance (Ereditarietà singola): Modello di ereditarietà in cui ogni classe ha esattamente una classe genitrice diretta. Java segue rigorosamente questo pattern. Sono però ammessi più livelli di ereditarietà transitiva (la catena di estensioni può attraversare più classi). Java evita i problemi dell'ereditarietà multipla per le classi vietandola del tutto.
  • java.lang.Object: La radice della gerarchia: ogni classe, se non specificato diversamente, estende direttamente o indirettamente java.lang.Object. È l'unica classe in Java senza superclasse.

Terminologia di gerarchia (glossario)

  • Subtype (Sottotipo): termine usato soprattutto con interfacce e tipi in generale per indicare una relazione di discendenza.
  • Supertype (Supertipo): tipo "antenato" in una gerarchia.
  • Direct Subclass (Sottoclasse diretta): indica che la classe estende direttamente la relativa superclasse.

Regole di Sintassi e Comportamento Operativo

  • Parola chiave extends: Una classe viene indicata come sottoclasse dichiarandola con la parola chiave extends.
  • Transitività: L'ereditarietà è transitiva; se la classe X estende Y e Y estende Z, allora X è considerata una sottoclasse (anche indiretta) di Z.
  • Accessibilità dei membri: Una classe Java che ne estende un'altra eredita tutti i suoi metodi e variabili pubblici e protetti. Se la classe si trova nello stesso pacchetto, eredita anche tutti i membri con accesso di package. I membri private non sono mai accessibili direttamente tramite ereditarietà.

6.2 Modificatori delle classi (Class modifiers)

Definizioni e Regole Una dichiarazione di classe può includere vari modificatori:

  • final: Impedisce che una classe venga ulteriormente estesa. Le classi contrassegnate come final non possono essere estese.
  • abstract: Indica che la classe non può essere istanziata e richiede una sottoclasse concreta per essere istanziata.
  • sealed: Limita l'estensione solo a una lista specifica di classi.
  • non-sealed: Permette a una sottoclasse di una classe sigillata di avere ulteriori sottoclassi.

⚠️ Tranelli (Classi final e top-level):

  • Estendere classi final: All'esame, quando vedi una classe contrassegnata final e un'altra classe che dichiara di estenderla, puoi concludere subito che il codice non compila.
  • Modificatori di accesso per classi top-level: Le classi dichiarate direttamente nel file (non annidate) possono essere solo public o avere accesso di package. L'uso di protected o private causa errore di compilazione.

Esempi di Codice (classi top-level):

// ClownFish.java
protected class ClownFish{} // NON COMPILA

// BlueTang.java
private class BlueTang {} // NON COMPILA

6.3 Accesso ai riferimenti this e super

Definizioni e Concetti

  • this Reference: Riferimento utilizzato per accedere a un membro corrente o ereditato di una classe.
  • super Reference: Riferimento utilizzato per accedere a un membro ereditato. Viene spesso utilizzato per ridurre l'ambiguità, ad esempio quando una classe riutilizza il nome di un metodo o di una variabile ereditata.

Regole di Visibilità

  • Java controlla la visibilità partendo dall'ambito più ristretto (narrowest scope); se esiste una variabile locale o un parametro con lo stesso nome di una variabile d'istanza, è necessario usare this per accedere al membro della classe.

⚠️ Tranelli (this e super):

  • Assegnazioni "al contrario": Il compilatore consente l'uso di this anche quando non è strettamente necessario, ma nei quesiti d'esame questa flessibilità serve spesso a nascondere assegnazioni errate o ambigue.
    • Esempio (metodo completo):
    public void setData(int length, int theHeight) {
   length = this.length;  // assegnazione invertita — non va bene
   height = theHeight;    // ok, nome del parametro diverso
}
    • Spiegazione: La riga indicata nel testo d'esame è scorretta: la variabile d'istanza length vale inizialmente 0, quel valore viene copiato nel parametro omonimo, mentre la variabile d'istanza resta 0 (assegnazione capovolta rispetto all'intento). In esame, controlla sempre riga e flusso dei dati.
  • super per membri solo nella sottoclasse: Mentre this considera membri della classe attuale e ereditati, super vede solo i membri ereditati dalla superclasse.
    • Esempio (non compila se age non è nel genitore):
    public class Beetle extends Insect {
   protected int age = 3;
   public void printData() {
      System.out.println(super.age); // NON COMPILA se age non è nel genitore
   }
}
    • Spiegazione integrale: La variabile age è definita solo nella classe corrente, quindi è accessibile via this ma non via super. Per questo quella riga spesso non compila nei tranelli. Ricorda: this = membri attuali ed ereditati; super = solo ereditati.

6.4 Dichiarazione e overloading dei costruttori

Definizioni e Regole

  • Constructor (Costruttore): Metodo speciale che corrisponde al nome della classe e non ha tipo di ritorno. Viene chiamato quando viene creata una nuova istanza della classe.
  • this() Call: Chiamata a un altro costruttore della stessa classe (deve comparire come prima istruzione se usata).
  • super() Call: Chiamata al costruttore della superclasse (sempre, se presente, come prima istruzione del costruttore).
  • Prima riga: La prima riga di ogni costruttore deve essere una chiamata a this() o a super().
  • super() automatico: Se non c'è una chiamata esplicita, il compilatore inserisce un super() senza argomenti come prima riga.

⚠️ Tranelli (Cicli e super implicito):

  • Cicli nei costruttori (Constructor Cycles): Il compilatore rileva se un costruttore, direttamente o attraverso altri, richiama se stesso in modo infinito. Di solito si parla di un cycle. Poiché l'esecuzione non terminerebbe mai, la compilazione si ferma con errore. (Citazione semplificata dal manuale: il compilatore capisce che il costruttore chiama se stesso all'infinito.)
    • Esempio:
    public class Gopher {
   public Gopher(int dugHoles) {
      this(5); // NON COMPILA
   }
}
  • Genitore senza costruttore no-arg: Se la superclasse dichiara solo costruttori con parametri, il super() implicito senza argomenti non è più valido: serve un super(...) esplicito con gli argomenti attesi. In caso contrario la sottoclasse non compila (es. sottoclasse "vuota" che tenta l'invocazione del costruttore predefinito inesistente nel genitore).
    • Esempio:
    public class Mammal {
   public Mammal(int age) {}
}
public class Seal extends Mammal {} // NON COMPILA
    • Nota d'esame: Il compilatore potrebbe inserire in Seal un costruttore predefinito, ma quello invocherebbe un super() a zero argomenti inesistente in Mammal — quindi l'errore.

6.5 Ordine di inizializzazione degli oggetti

Definizioni e Regole

  • Order of Initialization (Ordine di inizializzazione): come e quando ai membri vengono assegnati i valori, lungo l'albero delle classi.
  • Loading the Class (Caricamento / inizializzazione di classe): attraverso l'ordine statico, il runtime invoca l'inizializzazione dei membri static nella gerarchia, partendo dalla superclasse più in alto. L'inizializzazione a livello di classe per un dato class loader avviene al massimo una volta.
  • Ordine a livello di classe: 1) superclasse, 2) variabili static e inizializzatori static nell'ordine in cui compaiono.
  • Ordine a livello di istanza: 1) inizializzazione lato superclasse; 2) variabili d'istanza e inizializzatori d'istanza nell'ordine del sorgente; 3) esecuzione del costruttore.
  • Inizializzazione dei campi final (istanza): ogni variabile d'istanza final deve ricevere un valore esattamente una volta entro la fine del costruttore (o tramite inizializzatore / blocco d'istanza coerente con le regole del linguaggio).
  • Inizializzazione dei campi static final: ogni static final va assegnata esattamente una volta, in dichiarazione o in un inizializzatore static (a seconda dei casi previsti dalle regole del compilatore).
  • Valori di default: a variabili d'istanza e static non final lasciate senza inizializzazione esplicita, il runtime applica i default in base al tipo (es. 0, 0.0, false, null per riferimenti, ecc., come da regole del capitolo sui tipi).

⚠️ Tranelli (Okapi e campi final):

  • Esempio Okapi extends GiraffeFamily: l'output complesso segue le regole sull'ordine; tipicamente compare la sequenza BECHG per ogni nuova istanza Okapi (tranello sull'ordine di stampa rispetto a statici, istanza e costruttori).
  • Doppia assegnazione a final (MouseHouse): se volume è final e già inizializzato in un inizializzatore d'istanza, un'ulteriore assegnazione nel costruttore non compila.
public class MouseHouse {
   private final int volume;
   { this.volume = 10; }
   public MouseHouse() {
      this.volume = 2; // NON COMPILA: già assegnata nell'inizializzatore
   }
}

6.6 Overriding dei metodi

Regole Tassative Un metodo è overridden (sovrascritto) se una sottoclasse definisce un metodo con la stessa firma (nome e parametri) rispetto alla versione ereditata, rispettando almeno queste vincolanti (oltre a regole su eccezioni e covarianza viste sotto):

  1. Firma identica: stesso nome e stessa lista di parametri.
  2. Accessibilità: almeno quanto il metodo sostituito (non può essere più restrittivo in modo illecito).
  3. Eccezioni (checked): non si introducono nuove eccezioni checked o più ampie di quelle del metodo sostituito.
  4. Tipi di ritorno: covarianza: il tipo di ritorno della sottoclasse deve essere sostituibile a quello del metodo sostituito.
  5. final / private: un metodo final non può essere sovrascritto. Un metodo private non partecipa all'ereditarietà di override: in sottoclasse non è "sostituzione" ma eventuale nuova dichiarazione (vedi Ridichiarazione in §7).

Nota (concetti chiave): quando un metodo è effettivamente overridden, la versione della sottoclasse sostituisce quella del genitore per tutte le chiamate che usano riferimenti al tipo sottostante (polimorfismo a esecuzione) — a differenza dell'hiding di metodi static o di variabili, dove decide soprattutto il tipo statico del riferimento.

⚠️ Tranelli (Eccezioni, tipi e static/non-static):

  • Eccezioni checked troppo ampie: esempio d'esame con Reptile e GalapagosTortoise. Il metodo sostituito non può dichiarare Exception se il metodo sostituito dichiara solo IOException (o eccezioni più strette) senza soddisfare le regole.
public class Reptile {
   protected void sleep() throws java.io.IOException {}
}
public class GalapagosTortoise extends Reptile {
   public void sleep() throws Exception {} // NON COMPILA: Exception è "più ampia"
}

  • Tipo di ritorno non covariante ammissibile (Rhino / BlackRhino): non puoi sostituire con un tipo "più lato" lato sostituibilità rispetto a String se la base restituisce String (es. un getColor() con String in superclasse astratta o concreta e con CharSequence in sottoclasse, salvo le eccezioni ammesse dalle regole). Spiegazione tipica: CharSequence non è un sottotipo di String; ogni String è CharSequence, non il contrario, quindi la firma sostituita non soddisfa la covarianza in quel verso.

    • Esempio:
    public abstract class Rhino {
   String getColor() { return "grey"; }
}
public class BlackRhino extends Rhino {
   CharSequence getColor() { return "black"; } // NON COMPILA
}

  • Annotazione @Override: documenta l'intento di sostituzione; il compilatore controlla che esista davvero un metodo sostituibile.

  • Static vs istanza (Bear / SunBear): non si può sostituire un metodo static con un metodo d'istanza, né nascondere un metodo d'istanza con un metodo static — non compila se si viola l'accoppiata static / istanza.

public class Bear {
   public static void sneeze() {}
   public void hibernate() {}
}
public class SunBear extends Bear {
   public void sneeze() {}        // NON COMPILA
   public static void hibernate() {} // NON COMPILA
}
  • I metodi final in superclasse non possono essere né sostituiti né nascosti; i metodi static in genere danno method hiding e regole distinte (§7).

6.7 Hiding di metodi statici e variabili

Ridichiarazione vs overriding

  • Method Redeclaring (Ridichiarazione): si ha quando in sottoclasse compare un metodo con lo stesso nome (e talvolta la stessa forma) di un metodo che non entra nel meccanismo di override — in particolare con un metodo private in superclasse: le sottoclassi possono definire un metodo nuovo, senza relazione di sostituzione col metodo privato.

Definizioni e Concetti

  • Method Hiding (Nascondimento del metodo): si verifica tra metodi static con la stessa firma, definiti in relazione di ereditarietà.
  • Variable Hiding (Nascondimento di variabile): si ha quando una variabile d'istanza o static in sottoclasse riutilizza un nome di variabile "eredita" in senso di gerarchia.
  • Differenze sostanziali con l'overriding: con l'hiding, la versione "vecchia" del membro nascosto esiste ancora; per metodi e campi sotto queste regole, la risoluzione spesso dipende dal tipo statico del riferimento (non dal tipo dinamico dell'oggetto come con l'override d'istanza), il che rende il codice fonte di confusione e difficile da mantenere se abusato.

Differenze con l'Overriding (richiamo) A differenza dell'overriding su metodi d'istanza, dove vale il legame polimorfo sul tipo reale dell'oggetto, con hiding (metodi static e variabili) l'accesso segue soprattutto il tipo di riferimento dichiarato.

⚠️ Tranelli (Hiding, variabili, Kangaroo):

  • Comportamento inatteso: per le variabili d'istanza il valore risolto non segue l'oggetto come con l'override dei metodi: conta il tipo del riferimento.
  • Esempio completo (Kangaroo / Joey):
class Kangaroo { public int age = 2; }
class Joey extends Kangaroo { public int age = 6; }

Kangaroo joey = new Joey();
System.out.println(joey.age); // Stampa 2, non 6
  • Spiegazione: la variabile age è nascosta, non sostituita; per sapere quale valore usare, Java guarda al tipo del riferimento (Kangaroo), non al fatto che l'oggetto sia un Joey.
  • Metodi static vs istanza: vedi l'esempio Bear nella sezione 6: non mescolare static e istanza.

6.8 Creazione di classi astratte

Definizioni e Regole

  • Abstract Class: dichiarata con abstract, non si può istanziare con new come classe concreta; l'inizializzazione d'istanza lungo la gerarchia prosegue comunque tramite le sottoclassi concrete e le rispettive catene di costruttori.
  • Metodo astratto: termina con ; e nessuna coppia di graffe. Può comparire solo in classi abstract (o interfacce, con regole proprie del costrutto).
  • Implementazione obbligatoria: la prima sottoclasse concreta estende/eredita l'abstract class (e, separatamente, rispetta i contratti delle interfacce): deve fornire implementazioni a tutti i metodi astratti lasciati privi di corpo, sia che arrivino da superclasse astratta sia da default o firme di interfaccia, secondo le regole del linguaggio.
  • Interfacce e classi astratte: oltre a implementare (o lasciare astratti) i metodi della superclasse astratta, una classe concreta deve onorare ogni vincolo ereditato da interfacce (con le regole d'ereditarietà multipla sulle interfacce).

⚠️ Tranelli (Metodi abstract):

  • Metodo astratto con corpo fittizio (graffe vuote): non compila — il corpo non è ammesso per la forma astratta.
public abstract void swim() {}; // NON COMPILA
  • Metodi abstract in classi non abstract: in esame, attento a classi "normali" che dichiarano metodi abstract — la classe stessa deve (di solito) essere abstract, altrimenti non compila (a meno di casi d'esame espliciti). I creatori d'esame usano spesso classi con dichiarazioni non valide, mescolando abstract a concrete.
public class Egret { // NON COMPILA: manca abstract sulla classe
   public abstract void peck();
}
  • Modificatori incompatibili: un metodo non può essere insieme abstract e private, né abstract e final (né private né final consentono la sostituzione richiesta a valle nelle sottoclassi).

6.9 Creazione di oggetti immutabili

Definizioni e Concetti

  • Immutable Object (Oggetto immutabile): istanza il cui stato non può mutare in modo lecito dopo la creazione, se il pattern è rispettato.

Regole di implementazione (strategia comune)

  1. Rendere la classe final oppure nascondere i costruttori (es. private) e fornire fabbricazione controllata.
  2. Rendere le variabili d'istanza private e, dove serve, final.
  3. Evitare setter che espongano mutazione di stato.
  4. Non permettere che riferimenti a oggetti mutabili interni vengano alterati dall'esterno: usare metodi delegate, copie, o wrapper immodificabili ove serva.
  5. Usare defensive copy in costruttore e getter quando un campo è un riferimento a struttura mutabile.

Riepilogo (pattern, glossario): una configurazione frequente = classe final o costruttore privato, nessun setter che violi lo stato, e nessun riferimento "perso" verso l'interno che consenta a codice esterno di mutare collection o buffer condivisi.

⚠️ Tranelli (Immutabilità e getter):

  • Modifica indiretta (lista, getter colpevole): anche con campi private final che puntano a una List, se il getter restituisce il riferimento reale alla collection, un chiamante può chiamare .clear() o mutare: l'oggetto "immutabile" non lo è davvero.

  • Esempio d'attacco (illustrativo d'esame):

var zebra = new Animal();
zebra.getFavoriteFoods().clear(); // se il getter dà il riferimento reale, lo stato interno muta
  • Soluzione (defensive copy): l'operazione di copia (defensive copy) evita che altro codice alteri lo stato interno attraverso un riferimento condiviso: la copia isola l'immutabilità del tuo oggetto da comportamenti esterni imprevedibili.
  • Nota: oltre al field hiding (§7), l'immutabilità va difesa soprattutto dall'aliasing di riferimenti a oggetti mutabili (collezioni, buffer, ecc.).

Ch 7: Beyond Classes

7.1 Implementazione delle Interfacce (Implementing Interfaces)

Definizioni e Concetti

  • Interface (Interfaccia): Un'interfaccia è un tipo di dato astratto che dichiara un elenco di metodi astratti che qualsiasi classe che implementa l'interfaccia deve fornire.
  • Dichiarazione: In Java, un'interfaccia è definita con la parola chiave interface, analoga alla parola chiave class utilizzata per definire una classe.
  • Ereditarietà Multipla: A differenza delle classi, una classe può implementare qualsiasi numero di interfacce. Un'interfaccia può estendere un'altra interfaccia utilizzando la parola chiave extends.
  • Modificatore implicito: È un modificatore che il compilatore inserisce automaticamente nel codice sorgente (es. un'interfaccia è sempre astratta anche se non è marcata esplicitamente come tale).
  • Modificatori Impliciti: Le interfacce sono implicitamente astratte, anche se non esplicitamente marcate. I metodi di interfaccia senza corpo sono implicitamente public e abstract.
  • Costanti d'Interfaccia: Le variabili dichiarate al suo interno sono considerate variabili costanti, ovvero assunte essere public, static e final. Sono inizializzate con un valore costante quando dichiarate e possono essere usate senza un'istanza.

Regole operative (interfacce)

  • Metodi astratti: Non possono essere dichiarati private né protected.
  • Metodi default: Possono comparire solo in un'interfaccia; richiedono la parola chiave default e un corpo; non possono essere static né abstract.
  • Metodi static: Devono avere un corpo; non sono ereditati dalle classi che implementano l'interfaccia e vanno invocati con il nome dell'interfaccia.

⚠️ Tranelli (Interfacce):

  • Riduzione della visibilità: I membri di un'interfaccia sono considerati public; una classe concreta che implementa l'interfaccia deve usare public sui metodi implementati. Se si restringe la visibilità (es. accesso a livello di package), il codice non compila — anche quando le implementazioni sono identiche, come nel caso in cui un metodo passi da public ad accesso di package.
  • Interfacce final: Le interfacce non possono essere final, perché ciò equivarrebbe a vietare a qualsiasi classe di implementarle.
  • Terminologia errata: In sede d'esame si mischiano spesso termini di classi e interfacce: una classe può implementare un'interfaccia ma non può estenderla; un'interfaccia può estendere un'altra interfaccia ma non può implementarla (né estendere una classe).
  • Metodi incompatibili: È impossibile scrivere una classe che soddisfi contemporaneamente due metodi astratti ereditati se i tipi di ritorno sono incompatibili (es. void vs int).

Esempio di Codice (Interfacce che non compilano):

public interface CanRun {}
public class Cheetah extends CanRun {} // NON COMPILA: serve implements

public class Hyena {}
public interface HasFur extends Hyena {} // NON COMPILA: interfaccia non estende una classe

public interface Herbivore { public void eatPlants(int plantsLeft); }
public interface Omnivore  { public int eatPlants(int foodRemaining); }
public class Tiger implements Herbivore, Omnivore { // NON COMPILA: conflitto sui tipi di ritorno
}

7.2 Metodi Concreti nelle Interfacce (default, static, private)

Definizioni e Concetti

  • Default interface method: Metodo d'istanza in un'interfaccia dichiarato con default e con corpo. Può essere sovrascritto dalle classi implementatrici ed è stato introdotto anche per retrocompatibilità (aggiungere metodi a un'interfaccia esistente senza rompere le implementazioni già compilate).
  • Static interface method: Metodo legato al tipo interfaccia, dichiarato static con corpo.
  • Private interface method: Metodo private o private static visibile solo dentro la dichiarazione dell'interfaccia; serve a condividere codice tra metodi default o static senza duplicazione.

⚠️ Tranelli (Metodi default, static e private):

  • Conflitti tra default duplicati: Se una classe eredita due metodi default con la stessa firma da interfacce diverse e non li unifica con un override, il compilatore segnala errore: in pratica “rinuncia” a risolvere da solo il conflitto — la classe deve sovrascrivere il metodo (o non ereditare entrambi i default in conflitto).
  • Metodi static dell'interfaccia: Non sono ereditati; la chiamata usa il nome dell'interfaccia. Un metodo static nell'interfaccia non può invocare un metodo default o private d'istanza.

7.3 Lavoro con le Enumerazioni (Working with Enums)

Definizioni e Concetti

  • Enumeration (enum): Tipo che rappresenta un insieme fisso di costanti (es. giorni della settimana, stagioni).
  • Enum semplice vs complesso: L'enum semplice elenca solo valori; quello complesso aggiunge campi, costruttori e metodi.
  • Ordine dei membri: In un enum complesso l'elenco dei valori costanti deve comparire per primo.
  • Costruttori: Sono implicitamente private; non è possibile estendere un enum con sottoclassi né istanziarlo con new. Possono essere invocati solo all'interno della dichiarazione dell'enum.
  • Metodi impliciti: Ogni enum possiede i metodi values() (restituisce un array di tutti i valori) e valueOf(String) (restituisce la costante corrispondente al nome esatto, altrimenti lancia IllegalArgumentException).
  • Punteggiatura: Dopo l'elenco dei valori, il punto e virgola è opzionale negli enum che contengono solo valori; diventa obbligatorio se seguono altri membri (campi, metodi, ecc.).

⚠️ Tranelli (Enum):

  • Ordinalità negli switch: Ogni costante ha un ordinale, ma non si può usare il numero ordinale direttamente nella clausola case; bisogna usare il nome della costante.
  • Ordine e ;: L'elenco valori deve essere in cima e terminare con ; se dopo ci sono altri membri.

Esempio di Codice (switch sull'ordinale):

void esempio(Stagione s) {
   switch (s) {
      case 0 -> System.out.println("x"); // NON COMPILA: usare il nome della costante enum, non l'ordinale
   }
}

7.4 Classi e Interfacce Sigillate (Sealed Classes)

Definizioni e Concetti

  • Sealed class: Limita la gerarchia indicando con sealed e permits quali classi possono estenderla direttamente.
  • Sottoclassi dirette: Devono dichiarare obbligatoriamente uno di questi tre modificatori: final (ferma la gerarchia), sealed (continua a controllare la gerarchia con un nuovo permits), oppure non-sealed (riapre la gerarchia a qualsiasi sottoclasse).
  • Locazione: Classe sigillata e sottoclassi dirette devono trovarsi nello stesso package (se non si usano i moduli) o nello stesso modulo dichiarato. Non è possibile usare permits su una classe in un package diverso.
  • Clausola permits implicita: È opzionale (e dedotta automaticamente dal compilatore) se la classe sigillata e le sottoclassi sono dichiarate nello stesso file (stessa compilation unit) o se le sottoclassi sono annidate nella classe sigillata.

⚠️ Tranelli (Classi sigillate):

  • Ordine dei modificatori: sealed deve precedere la parola chiave class (es. public sealed class ..., non public class sealed ...).
  • permits e classi annidate: Per una sottoclasse annidata serve il nome qualificato nella clausola permits (es. Snake.Cobra).
  • Modificatori sulle sottoclassi: Le sottoclassi dirette di una classe sealed devono essere esplicitamente final, sealed o non-sealed; ometterlo causa errore di compilazione.
  • Parola chiave non-sealed: È l'unica parola chiave in Java con il trattino. Opzioni all'esame come nonsealed o unsealed sono errate.
  • Record e interfacce sealed: I record sono implicitamente final. Se un record implementa un'interfaccia sealed, non è necessario scrivere la parola chiave final nella sua dichiarazione.
  • Switch e Pattern Matching (Exhaustiveness): Quando si usa un'espressione switch o il pattern matching su un tipo sealed, il compilatore sa esattamente quali sono le sottoclassi. Se si coprono tutte le sottoclassi permesse, la clausola default non è necessaria (ed è considerata best practice ometterla).

Esempio di Codice (Gerarchia e modificatori):

public sealed class Veicolo permits Automobile, Camion, Moto {}
public final class Automobile extends Veicolo {} // Gerarchia chiusa
public sealed class Camion extends Veicolo permits CamionFrigo {} // Gerarchia controllata
public non-sealed class Moto extends Veicolo {} // Gerarchia aperta
public class Scooter extends Moto {} // OK, Moto è non-sealed

Esempio di Codice (permits implicito con classi annidate):

public sealed class Risultato { // permits dedotto automaticamente
    public static final class Successo extends Risultato {}
    public static non-sealed class Errore extends Risultato {}
}

Esempio di Codice (ordine sealed errato):

public class sealed Frog permits GlassFrog {} // NON COMPILA: sealed prima di class

Esempio di Codice (permits e classe annidata):

public sealed class Snake permits Cobra { // NON COMPILA: manca il nome qualificato
   final class Cobra extends Snake {}
}
// Correzione: permits Snake.Cobra

7.5 Incapsulamento e Record (Encapsulating Data with Records)

Definizioni e Concetti

  • Incapsulamento: Limitare l'accesso ai dettagli interni di un oggetto (es. campi private esposti tramite metodi controllati).
  • Accessor (getter): Metodo che legge lo stato; nei record, l'accessor ha lo stesso nome del componente seguito da parentesi (es. campo name → metodo name()).
  • Mutator (setter): Metodo che modifica lo stato; i record standard non espongono setter perché sono immutabili.
  • Record: Classe orientata ai dati per cui il compilatore genera boilerplate: costruttore canonico, accessor, equals(), hashCode(), toString().
  • Immutabilità: I componenti del record sono final; non si possono dichiarare campi d'istanza fuori dall'intestazione del record (nemmeno private final aggiuntivi nel corpo).
  • Ereditarietà: I record non possono estendere altre classi (estendono già implicitamente java.lang.Record), ma possono implementare interfacce.
  • Costruttore compatto: Si dichiara senza lista di parametri tra parentesi; serve soprattutto per convalida e trasformazione degli argomenti prima che vengano assegnati ai campi. Non può assegnare i campi con this.campo = ... (a differenza del costruttore “lungo” generato o esplicito con firma completa).

Regole operative (record)

  • Campi: Vietati campi d'istanza non dichiarati nella testata del record.
  • Costruttori sovraccaricati: La prima istruzione deve essere una chiamata this(...) ad un altro costruttore del record. Se non esistono altri costruttori dichiarati, va invocato il costruttore canonico (quello che imposta tutti i componenti).

Pattern matching per record

  • Consente di estrarre i componenti nel controllo di tipo, es. if (animal instanceof Monkey(String n, int a)).
  • Il pattern associa il tipo del record e il tipo di ciascun componente nel pattern.
  • Nomi: Si può dare un nome al record oppure ai campi nel pattern, non entrambi (es. instanceof Monkey(String n, int a) myMonkey non compila).
  • Promozione numerica: Non è supportata nel pattern (es. pattern con long se il componente reale è int non compila).
  • Switch con Record: In Java 21, è possibile decostruire i record direttamente nei case di uno switch (es. case Monkey(String n, int a) -> ...).

⚠️ Tranelli (Record):

  • Campi extra nel corpo: Aggiungere variabili d'istanza nel corpo del record vanifica il modello e può violare l'immutabilità attesa.

Esempio di Codice (campo istanza non ammesso):

record Music(java.util.List<String> tempo) {
   final int score = 10; // NON COMPILA
}

Esempio di Codice (this nel costruttore compatto):

public record Crane(int numberEggs, String name) {
   public Crane {
      this.numberEggs = 10; // NON COMPILA nel costruttore compatto
   }
}

Esempio di Codice (pattern: nome record e campi insieme):

if (animal instanceof Monkey(String n, int a) myMonkey) {} // NON COMPILA

Esempio di Codice (pattern senza promozione numerica):

if (animal instanceof Monkey(String n, long a)) {} // NON COMPILA se il componente è int

Esempio di Codice (decostruzione in instanceof e switch):

public record Point(int x, int y) {}

public void checkPoint(Object obj) {
   // 1. Decostruzione con instanceof
   if (obj instanceof Point(int x, int y)) {
      System.out.println("Punto: " + x + ", " + y);
   }
   
   // 2. Decostruzione nello switch (con guardia 'when')
   switch (obj) {
      case Point(int x, int y) when x == 0 && y == 0 -> System.out.println("Origine");
      case Point(int x, int y) -> System.out.println("Punto: " + x + ", " + y);
      default -> System.out.println("Altro");
   }
}

7.6 Creazione di Classi Annidate (Nested Classes)

Tipi e Regole

  1. Inner class (classe interna): Non static, a livello di membro; richiede un'istanza della classe esterna. Può usare tutti e quattro i livelli di accesso (public, protected, package-private, private).
  2. Static nested class: static, a livello di membro; non vede i membri d'istanza della outer senza un riferimento esplicito all'istanza esterna.
  3. Local class: Dentro un metodo; senza modificatori di accesso; può essere final o abstract. Vede le variabili locali solo se sono final o effectively final.
  4. Anonymous class: Caso particolare di classe locale senza nome; in una singola espressione estende una classe oppure implementa un'interfaccia. Non ammette modificatori di accesso e non può essere dichiarata abstract né final.

⚠️ Tranelli (Classi annidate):

  • Istanziazione: La sintassi per creare un'istanza cambia. Per una Inner class serve un'istanza della classe esterna: Outer.Inner obj = new Outer().new Inner();. Per una Static nested class non serve: Outer.Nested obj = new Outer.Nested();.
  • Membri statici e outer: Una classe annidata static (o un record, implicitamente statico nel contesto rilevante) che accede a un campo d'istanza della classe esterna senza un riferimento all'istanza outer non compila.
  • Variabili locali e effectively final: Se una variabile locale usata nella classe locale viene riassegnata dopo la dichiarazione della classe, non è più effectively final e il codice non compila.

7.7 Comprensione del Polimorfismo (Understanding Polymorphism)

Definizioni e Concetti

  • Polimorfismo: Capacità di un oggetto di essere usato tramite un riferimento del proprio tipo, di una superclasse o di un'interfaccia implementata; in memoria resta un unico oggetto con una forma concreta.
  • Oggetto vs riferimento: Il tipo runtime dell'oggetto determina quali campi esistono; il tipo del riferimento usato nel codice determina quali membri sono accessibili in compilazione.
  • Cast implicito ed esplicito: Verso un supertipo o un'interfaccia supertipo il cast è implicito; verso un sottotipo serve il cast esplicito. Un cast illegale a runtime può causare ClassCastException.
  • instanceof: Verifica se un riferimento punta a un'istanza compatibile con un tipo; utile per evitare ClassCastException prima di un cast.

⚠️ Tranelli (Polimorfismo e casting):

  • Cast tra tipi non correlati: Il compilatore rifiuta cast tra tipi che non stanno nella stessa gerarchia.
  • instanceof e tipi non correlati: Anche instanceof tra tipi senza relazione di sottotipo è rifiutato in compilazione.
  • Hiding (variabili): Per campi nascosti (non overridden come i metodi), vale il tipo del riferimento: tramite un riferimento alla superclasse si legge il valore dichiarato nella superclasse, non quello della sottoclasse.

Esempio di Codice (cast non valido):

Fish fish = new Fish();
Bird bird = (Bird) fish; // NON COMPILA: tipi non correlati

Esempio di Codice (instanceof non valido):

if (fish instanceof Bird b) {} // NON COMPILA

Ch 8: Lambdas and Functional Interfaces

8.1 Scrittura di Lambda Semplici (Writing Simple Lambdas)

Definizioni e Concetti La programmazione funzionale (functional programming) è un modo di scrivere codice in modo più dichiarativo; si specifica cosa si vuole fare invece di gestire lo stato degli oggetti, concentrandosi più sulle espressioni che sui cicli. Una espressione lambda (lambda expression) è un blocco di codice che viene passato in giro; può essere pensata come un metodo senza nome esistente all'interno di una classe anonima, dotata di parametri e di un corpo proprio come i metodi completi, ma senza un nome come un metodo reale.

Regole di Sintassi e Comportamento Operativo

  • Componenti: Comprende i parametri, l'operatore freccia (->) per separare i parametri dal corpo, e un corpo che può contenere una o più linee di codice.
  • Parentesi dei parametri: Possono essere omesse solo se è presente un singolo parametro e il suo tipo non è dichiarato esplicitamente.
  • Parentesi graffe e ritorno: Java permette di omettere lo statement return e il punto e virgola (;) quando non vengono utilizzate le graffe, se il corpo consiste in una singola istruzione.
  • Corpo vuoto: s -> {} è una lambda valida; se non c'è codice sul lato destro dell'espressione, non sono necessari il punto e virgola o lo statement return.

⚠️ Tranello (Parentesi e tipi dichiarati): Se si specifica il tipo del parametro, le parentesi diventano obbligatorie.

Esempio di Codice (Tipo esplicito senza parentesi):

String x -> x.endsWith("eagle") // NON COMPILA

⚠️ Tranello (Vincoli delle graffe): Se si usano le graffe, il return (per i metodi non void) e il punto e virgola sono obbligatori.

Esempio di Codice (Graffe senza return):

x -> { x.startsWith("camel"); } // NON COMPILA: manca return

Esempio di Codice (Graffe senza punto e virgola):

x -> { return x.startsWith("giraffe") } // NON COMPILA: manca punto e virgola interno

⚠️ Tranello (Semicolon finale): Mentre non serve il punto e virgola in una lambda a riga singola senza graffe, l'intero statement di assegnazione della lambda a una variabile richiede il punto e virgola finale.

⚠️ Tranello (Uso di var senza contesto): var assume il tipo in base al contesto; se non c'è abbastanza contesto per determinare l'interfaccia funzionale, il codice non compila.

Esempio di Codice (var senza interfaccia funzionale):

var invalid = (Animal a) -> a.canHop(); // NON COMPILA: contesto insufficiente per l'interfaccia funzionale

8.2 Codifica delle Interfacce Funzionali (Coding Functional Interfaces)

Definizioni e Concetti Una interfaccia funzionale (functional interface) è un'interfaccia che contiene esattamente un singolo metodo astratto, condizione nota ufficialmente come regola SAM (Single Abstract Method).

Regole di Esclusione e Compatibilità

  • Metodi di Object: I metodi astratti con firme contenute nei metodi pubblici di java.lang.Object (toString(), equals(Object), hashCode()) non contano ai fini del computo SAM. Ogni classe che implementa l'interfaccia erediterà comunque tali implementazioni da Object.
  • Incompatibilità con Object: Non è possibile dichiarare in un'interfaccia un metodo astratto che sia incompatibile con un metodo di Object (ad esempio un int toString()) perché ciò impedirebbe la compilazione, dato che Object ne definisce una versione che restituisce una String.

⚠️ Tranello (Metodi che "sembrano" di Object): Se la firma non è identica a quella dei metodi pubblici di Object, il metodo conta come astratto.

Esempio di Codice (Interfaccia non funzionale):

public interface Hibernate { public boolean equals(Hibernate o); void rest(); } // NON COMPILA: ha 2 metodi astratti perché equals(Hibernate) non è equals(Object o)

8.3 Utilizzo dei Riferimenti ai Metodi (Using Method References)

Definizioni e Concetti I riferimenti ai metodi (method references) sono un altro modo per rendere il codice più leggibile, limitandosi a menzionare il nome del metodo invece di scrivere l'intera espressione lambda. Un riferimento al costruttore (constructor reference) è un tipo speciale di method reference che usa new al posto del nome del metodo e istanzia un oggetto; Java utilizza il contesto per determinare quale costruttore specifico chiamare in base ai parametri attesi dall'interfaccia funzionale.

Formati Supportati

  • Metodi statici: ClassName::methodName.
  • Metodi d'istanza su un oggetto particolare: instanceVariable::methodName.
  • Metodi d'istanza su un parametro da determinare a runtime: ClassName::methodName.
  • Costruttore: ClassName::new.

⚠️ Tranelli (Riferimenti ai metodi):

  • Dipendenza dal contesto: Non è sempre possibile determinare quale metodo viene chiamato solo guardando il riferimento; bisogna guardare il contesto per vedere quali parametri sono usati e se c'è un tipo di ritorno.
  • Ambiguità (ambiguous type error): Il compilatore riporta un errore di tipo ambiguo quando non riesce a trovare un metodo che corrisponda alla descrizione inferta dal contesto, o ne trova multipli.

8.4 Lavoro con le Interfacce Funzionali Integrate (Built-in Functional Interfaces)

Definizioni e Concetti Java fornisce un ampio numero di interfacce funzionali di uso generale nel pacchetto java.util.function, evitando allo sviluppatore di doverne scrivere di proprie ogni volta. Esistono inoltre numerose interfacce specifiche per i primitivi int, long e double (come IntSupplier o ToDoubleFunction) per migliorare le prestazioni evitando l'overhead delle classi wrapper.

Interfacce Principali

  • Supplier: T get(). Utilizzata per generare o fornire valori senza input.
  • Consumer: void accept(T). Esegue un'operazione su un parametro senza restituire nulla.
  • BiConsumer<T, U>: void accept(T, U). Simile a Consumer, ma accetta due parametri; ritorno void.
  • Predicate: boolean test(T). Usata per filtraggio o match.
  • BiPredicate<T, U>: boolean test(T, U). Come Predicate, ma con due parametri; ritorno boolean.
  • Function<T, R>: R apply(T). Trasforma un parametro in un valore di tipo potenzialmente diverso.
  • BiFunction<T, U, R>: R apply(T, U). Trasforma due parametri in un valore e lo restituisce.
  • UnaryOperator: T apply(T). Caso speciale di Function in cui tutti i parametri di tipo sono uguali.
  • BinaryOperator: T apply(T, T). Caso speciale di BiFunction in cui tutti i parametri di tipo sono uguali.

⚠️ Tranelli (Interfacce integrate):

  • Tipi di ritorno e Autoboxing: Un Predicate restituisce un primitivo boolean e non un oggetto Boolean. L'autoboxing funziona per le collezioni, non per inferire i predicati.
  • Eccezioni checked: Le interfacce funzionali integrate (come Supplier) non permettono eccezioni checked. Se una lambda lancia un'eccezione checked, deve essere gestita con un try-catch interno o mappata in una runtime.

8.5 Lavoro con le Variabili nelle Lambda (Working with Variables in Lambdas)

Definizioni e Concetti Le variabili possono comparire nelle lambda in tre punti: la lista dei parametri, le variabili locali dichiarate nel corpo della lambda e le variabili referenziate dal codice circostante. Una variabile effectively final è una variabile locale non modificata dopo l'assegnazione iniziale; può essere usata nel corpo della lambda anche senza la parola chiave final.

Regole per i Parametri e le Variabili

  • Coerenza dei formati: Il compilatore richiede che tutti i parametri nella lambda utilizzino lo stesso formato: senza tipi, con tipi espliciti, o con var.
  • Uso di var: var assume il tipo in base al contesto; se non c'è abbastanza contesto per determinare l'interfaccia funzionale, il codice non compila.

Regole di accesso

  • Variabili d'istanza: Sempre permesse nel corpo della lambda.
  • Variabili statiche: Sempre permesse nel corpo della lambda.
  • Variabili locali: Permesse solo se final o effectively final.
  • Parametri del metodo: Permessi solo se final o effectively final.
  • Parametri lambda: Sempre permessi nel corpo della lambda.

⚠️ Tranello (Redichiarazione): Il corpo di una lambda non può creare una variabile locale con lo stesso nome di una già dichiarata in quello scope.

Esempio di Codice (Redichiarazione di variabile):

public void variables(int a) { Predicate<Integer> p1 = a -> { ... }; } // NON COMPILA: 'a' è già usato come parametro del metodo

⚠️ Tranello (Posizione dell'errore): Se una variabile locale viene modificata dopo la definizione della lambda, l'errore di compilazione viene generato sulla riga in cui la lambda tenta di usare la variabile, non sulla riga della riassegnazione.

Ch 9: Collections and Generics

9.1 Utilizzo delle API Comuni per le Collezioni (Common Collection APIs)

Definizioni e Concetti Una collezione (collection) è un gruppo di oggetti contenuti in un singolo oggetto. Il Java Collections Framework è un insieme di classi in java.util per memorizzare collezioni. Include quattro interfacce principali: List (ordinata, ammette duplicati), Set (senza duplicati), Queue (ordine specifico di elaborazione) e Map (mappa chiavi a valori).

Regole di Sintassi e Comportamento Operativo

  • removeIf(Predicate<? super E> filter): Elimina gli elementi che soddisfano la condizione espressa dal Predicate.
  • forEach(Consumer<? super T> action): Esegue l'azione indicata dal Consumer su ciascun elemento della collezione.

⚠️ Tranello (Autoboxing e Null): Java protegge da molti problemi con le Collections, ma è comunque possibile scrivere codice che lancia una NullPointerException. Se si aggiunge un null a una collezione di wrapper e si tenta di assegnarlo a un primitivo, Java fallisce durante l'unboxing: tenta di ottenere il valore int di null e, poiché chiamare qualsiasi metodo su null produce una NullPointerException, è esattamente ciò che si ottiene.

9.2 Comprensione dei Tipi Generici (Generic Types)

Definizioni e Concetti I generics (parameterized types) permettono di specificare il tipo di oggetti contenuti in una collezione, come List<Integer>. Un bounded parameter type è un tipo generico che specifica un vincolo (bound) sul parametro di tipo. Il diamond operator (<>) è una notazione abbreviata che permette di omettere il tipo generico sul lato destro di un'assegnazione quando il tipo può essere inferito dal lato sinistro.

Regole di Sintassi e Comportamento Operativo

  • Posizionamento del diamond operator: Non può essere usato come tipo in una dichiarazione di variabile; è ammesso solo sul lato destro di un'assegnazione.
  • Inferenza con var: var inferisce il tipo dal lato destro della dichiarazione, mentre il diamond operator lo inferisce dal lato sinistro. var map = new HashMap<>(); compila; se entrambi devono inferire, non c'è abbastanza informazione e si ottiene Object come tipo generico.

⚠️ Tranello (Diamond Operator a sinistra): Il diamond operator non può comparire come tipo nella dichiarazione della variabile.

Esempio di Codice (Diamond Operator illegale):

List<> list = new ArrayList<Integer>(); // DOES NOT COMPILE

9.3 Utilizzo dell'Interfaccia List

Definizioni e Concetti Una List (lista) è una collezione ordinata di elementi che ammette duplicati; gli elementi sono accessibili tramite un indice int. ArrayList è come un array ridimensionabile: quando si aggiungono elementi, cresce automaticamente ed è consigliata per letture frequenti, poiché consente l'accesso a qualsiasi elemento in tempo costante. LinkedList permette di aggiungere/rimuovere facilmente all'inizio o alla fine e implementa sia List che Deque.

Regole di Sintassi e Comportamento Operativo (Tabella 9.1)

  • Arrays.asList(varargs): Restituisce una lista a dimensione fissa supportata da un array. Permette di sostituire elementi (set), ma non di aggiungerne o eliminarne. Modificare la List aggiorna l'array sottostante.
  • List.of(varargs): Restituisce una lista immutabile. Non è possibile aggiungere, sostituire o eliminare elementi.
  • List.copyOf(collection): Restituisce una lista immutabile con una copia dei valori della collezione originale. Non è possibile aggiungere, sostituire o eliminare elementi.

⚠️ Tranelli (Factory Methods):

  • Tabella 9.1: L'esame verifica rigorosamente cosa si può e non si può fare con le liste create tramite factory methods.
  • UnsupportedOperationException: Su List.of() e List.copyOf(), l'invocazione di set() lancia UnsupportedOperationException.
  • Ambiguità di remove(): Il metodo remove() che accetta un elemento restituisce false se l'elemento non è trovato. Il metodo remove() che accetta un int (indice) lancia un'eccezione se l'indice non è valido.

9.4 Utilizzo dell'Interfaccia Set

Definizioni e Concetti Un Set (insieme) è una collezione che non ammette duplicati. HashSet memorizza gli elementi in una hash table (chiavi hash, valori di tipo Object) e usa hashCode() per trovare elementi non ordinati. LinkedHashSet mantiene l'ordine di inserimento. TreeSet è ordinato, mantiene gli elementi nel loro ordine naturale (natural order), non ammette valori null e richiede che gli elementi implementino Comparable oppure che venga fornito un Comparator.

⚠️ Tranelli (TreeSet e strutture ordinate):

  • Valori null: TreeSet non ammette valori null; l'inserimento di un null lancia un'eccezione a runtime.
  • Comparable non implementato: A differenza dell'ordinamento esplicito, TreeSet non verifica a compile time che la classe implementi Comparable. L'errore avviene solo a runtime durante il tentativo di inserimento; Java lancia un'eccezione del tipo class Rabbit cannot be cast to class java.lang.Comparable.

9.5 Utilizzo delle Interfacce Queue e Deque

Definizioni e Concetti Una Queue (coda) ordina gli elementi in un ordine specifico per l'elaborazione. Una Deque (double-ended queue, coda a doppia estremità) è una sottointerfaccia di Queue che permette l'accesso a entrambe le estremità. ArrayDeque è una coda pura ed efficiente; LinkedList è più flessibile perché implementa anche List. Questi tipi supportano il pattern FIFO (First-In, First-Out) o LIFO (Last-In, First-Out); quest'ultimo corrisponde allo stack, gestito tramite i metodi push(), pop() e peek().

9.6 Utilizzo dell'Interfaccia Map

Definizioni e Concetti Una Map (mappa) associa chiavi univoche a valori; gli elementi sono coppie chiave/valore e Map non estende Collection. HashMap usa hashCode() per trovare le chiavi e associa chiavi univoche ai valori. LinkedHashMap mantiene l'ordine di inserimento. TreeMap ordina le chiavi secondo il loro ordine naturale e non ammette chiavi null.

Regole di Sintassi e Comportamento Operativo

  • merge(K, V, BiFunction): Unisce un valore con quello già presente per una chiave, secondo le regole della Tabella 9.7.
  • putIfAbsent(K, V): Inserisce la coppia chiave/valore solo se la chiave non è già presente.
  • getOrDefault(Object, V): Restituisce il valore associato alla chiave oppure un valore di default se la chiave è assente.

Regole di comportamento di merge() (Tabella 9.7)

  • Chiave con valore nullo nella mappa: Aggiorna il valore della chiave con il parametro value.
  • Funzione di mappatura che restituisce null: Rimuove la chiave dalla mappa.
  • Chiave assente dalla mappa: Aggiunge la chiave con il parametro value direttamente, senza invocare la funzione di mappatura.

⚠️ Tranelli (Map):

  • Chiavi null in TreeMap: TreeMap non ammette chiavi null; l'inserimento di una chiave null lancia un'eccezione a runtime.
  • Gestione valori nulli in merge(): Il comportamento di merge() cambia drasticamente se la chiave non esiste o se il valore associato è nullo. Se la chiave ha un valore null, la mappa aggiorna direttamente il valore della chiave con il parametro value, senza chiamare la funzione di mappatura.

Esempio di Codice (merge() con valore null — la lambda viene ignorata):

map.merge(3, 3, (a, b) -> a + b);
// Se la chiave 3 è mappata a null, il risultato è: chiave 3 → valore 3

9.7 Ordinamento dei Dati (Sorting Data)

Definizioni e Concetti Comparable è l'interfaccia che dichiara il metodo compareTo(T o) per definire l'ordine naturale (natural order) di una classe: restituisce un numero negativo se l'oggetto è minore dell'argomento, 0 se sono uguali, un numero positivo altrimenti. Comparator definisce compare(T o1, T o2) per ordinamenti personalizzati ed è spesso implementato tramite lambda.

Regole di Sintassi e Comportamento Operativo

  • Coerenza con equals (consistency with equals): Un ordinamento naturale è coerente con equals se x.equals(y) è vero ogni volta che x.compareTo(y) == 0.

9.8. Introduzione alle Collezioni Sequenziate (Sequenced Collections)

Definizioni e Concetti (Java 21) Introdotte in Java 21, le Sequenced Collections definiscono collezioni con un encounter order (ordine di incontro) ben definito: tutti gli elementi possono essere letti in modo ripetibile. SequencedCollection include implementazioni come ArrayList e LinkedList. SequencedSet include LinkedHashSet e TreeSet. SequencedMap include LinkedHashMap e TreeMap. Metodi specifici come addFirst(), getFirst(), removeLast() e reversed() permettono operazioni dirette sulle estremità della sequenza.

⚠️ Tranello (addFirst/addLast su strutture ordinate): Il solo fatto che una classe implementi SequencedCollection non implica che supporti tutti i metodi. Ad esempio, su un TreeSet non è possibile forzare un elemento in prima o ultima posizione: chiamate come addFirst() o addLast() falliscono a runtime perché inserire un elemento in una posizione arbitraria in una struttura ordinata potrebbe violare il Comparator.

9.9 Lavoro Avanzato con i Generics

Definizioni e Concetti È possibile creare classi generiche dichiarando un parametro di tipo tra parentesi angolari, come Crate<T>. Un wildcard generic type è un tipo generico sconosciuto rappresentato con ?. I bounded wildcards (wildcards vincolati) limitano i tipi accettabili:

  • ? (unbounded): Rappresenta qualsiasi tipo.
  • ? extends type (upper-bound): Accetta la classe specificata o una sua sottoclasse; la lista è di sola lettura per quanto riguarda l'aggiunta di elementi.
  • ? super type (lower-bound): Accetta la classe specificata o una sua superclasse (fino a Object); permette aggiunte di elementi compatibili con il bound inferiore.

Regole di Sintassi e Comportamento Operativo

  • Upper bounds e unbounded wildcards: La lista diventa logicamente immutabile e non può essere modificata tramite add().
  • Errore di compilazione su add(): Il compilatore segnala errore se si tenta di aggiungere un elemento in una List con wildcard unbounded o upper-bounded.

⚠️ Tranello (Immutabilità logica con upper bounds): Con upper bounds o wildcards unbounded, il compilatore non consente l'aggiunta di elementi perché non può garantirne il tipo specifico.

Esempio di Codice (Upper-bounded wildcard — add() non compila):

List<? extends Bird> birds = new ArrayList<Bird>();
birds.add(new Sparrow()); // DOES NOT COMPILE

⚠️ Tranello (Type Erasure e Overloading): Non è possibile sovraccaricare un metodo generico ereditato da una classe padre se, dopo l'type erasure, le firme risultano identiche: il tipo generico viene eliminato e il compilatore rileva un overloading non valido.

Esempio di Codice (Overloading invalido dopo type erasure):

public void chew(List<Object> input) {}
public void chew(List<Double> input) {} // DOES NOT COMPILE

⚠️ Tranello (L'"Evil Trick" del parametro di tipo che maschera una classe): L'esame usa nomi di parametri di tipo identici a nomi di classi esistenti per confondere. Per coincidenza, B può essere sia il nome di una classe sia il nome di un parametro di tipo nel metodo. All'interno dello scope del metodo, B rappresenta un tipo generico (classe A, B o C) e non più la classe B; di conseguenza non è possibile istanziare la classe B con new B() all'interno di quel metodo.

Ch 10: Streams

10.1 Restituzione di un Optional (Returning an Optional)

Definizioni e Concetti Optional (Optional<T>) è un contenitore che può contenere o meno un valore non nullo. Viene utilizzato per gestire i valori di ritorno che potrebbero essere null, evitando così NullPointerException. Si crea tramite i metodi factory Optional.empty(), Optional.of(value) o Optional.ofNullable(value).

Regole di Sintassi e Comportamento Operativo

  • Optional.of(value): Lancia un'eccezione se il valore è null.
  • Optional.ofNullable(value): Se il valore è null, viene assegnato l'Optional vuoto; altrimenti il valore viene incapsulato.
  • isPresent(): Restituisce true se c'è un valore.
  • ifPresent(Consumer c): Esegue l'azione se il valore esiste.
  • get(): Restituisce il valore o lancia una NoSuchElementException se l'Optional è vuoto.
  • orElse(T other): Restituisce il parametro se l'Optional è vuoto.
  • orElseGet(Supplier s): Restituisce il risultato del Supplier se l'Optional è vuoto.
  • orElseThrow(): Lancia un'eccezione se l'Optional è vuoto.

⚠️ Tranelli (Optional):

  • Optional.of() con null: Optional.of(value) lancia un'eccezione se il valore è null. Per valori potenzialmente nulli, usare Optional.ofNullable(value).
  • Optional.get() su contenitore vuoto: Se non si effettua il controllo e l'Optional è vuoto, si ottiene un'eccezione perché non c'è alcun valore al suo interno. In particolare, get() lancia NoSuchElementException.
  • Incompatibilità in orElseGet(): Il compilatore verifica rigorosamente che il Supplier restituisca lo stesso tipo dell'Optional. La variabile opt è un Optional<Double>: il Supplier deve restituire un Double. Poiché in questo caso restituisce un'eccezione, i tipi non corrispondono.

Esempio di Codice (orElseGet() — non compila):

Optional<Double> opt = average(); opt.orElseGet(() -> new IllegalStateException());
// DOES NOT COMPILE: il Supplier deve restituire un Double, non un'eccezione

10.2 Utilizzo degli Stream (Using Streams)

Definizioni e Concetti Uno Stream in Java è una sequenza di dati. Non è una struttura dati che memorizza elementi, ma un condotto per spostare dati attraverso una pipeline. La stream pipeline comprende le operazioni eseguite su uno stream: una source (sorgente), zero o più intermediate operations (operazioni intermedie) e una terminal operation (operazione terminale). Gli stream utilizzano la lazy evaluation (valutazione ritardata): le operazioni intermedie non vengono eseguite finché non viene invocata l'operazione terminale. Se manca l'operazione terminale, lo stream viene restituito ma non eseguito.

L'encounter order (ordine di incontro) indica l'ordine in cui gli elementi di una sorgente vengono processati dallo stream, quando tale ordine è ben definito (ad esempio in una List).

⚠️ Tranello (Utilizzo singolo): Uno stream può essere usato una sola volta: dopo che l'operazione terminale è stata eseguita, lo stream non è più valido. Qualsiasi tentativo di riutilizzo lancia un'eccezione a runtime, tipicamente IllegalStateException.

10.3 Creazione di Sorgenti di Stream (Creating Stream Sources)

Definizioni e Concetti La source (sorgente) indica da dove proviene lo stream. Può essere una collezione, un array o metodi factory che generano dati. Le sorgenti possono essere finite o infinite.

Regole di Sintassi e Comportamento Operativo (Tabella 10.3)

  • Stream.empty(), Stream.of(varargs), coll.stream(): Creano stream finiti dagli argomenti passati o da una collezione.
  • Stream.generate(Supplier): Crea uno stream infinito in cui gli elementi vengono inseriti su richiesta.
  • Stream.iterate(seed, UnaryOperator): Crea uno stream infinito partendo dal seed e applicando ripetutamente l'operatore.
  • Stream.iterate(seed, predicate, operator) — Java 21: Versione sovraccarica che funziona come un ciclo for e può produrre stream finiti; si interrompe se il Predicate restituisce false.

⚠️ Tranello (iterate() vs for loop): L'esame può tentare di confondere usando i punti e virgola, poiché la sintassi ricorda un ciclo for. Nello Stream.iterate(), i tre parametri devono essere separati da virgole (,), non da punti e virgola.

Esempio di Codice (iterate() Java 21 — corretto):

Stream.iterate(1, n -> n < 100, n -> n + 2)

10.4 Operazioni Terminali Comuni (Common Terminal Operations)

Definizioni e Concetti Le operazioni terminali producono un risultato (produces a result) o un effetto collaterale e chiudono lo stream. Poiché gli stream possono essere utilizzati una sola volta, non sono più validi dopo il completamento di un'operazione terminale. Le reductions (riduzioni) sono un tipo speciale di operazione terminale in cui tutti gli elementi dello stream vengono combinati in un unico primitivo o Object.

Regole di Sintassi e Comportamento Operativo (Tabella 10.4)

  • count(), min(), max(), reduce(), collect(): Operazioni di riduzione.
  • forEach(Consumer), anyMatch(), allMatch(), noneMatch(), findAny(), findFirst(): Altre operazioni terminali comuni.

⚠️ Tranelli (Stream infiniti e terminazione):

  • Operazioni che non terminano: count(), min(), max(), reduce() e collect() non giungono mai a conclusione se applicate a sorgenti infinite.
  • Operazioni che terminano: findAny() e findFirst() terminano anche su stream infiniti.
  • anyMatch() e allMatch(): A volte terminano grazie allo short-circuit. Se il predicato non trova mai una corrispondenza che soddisfi la condizione di uscita anticipata, il codice rimane bloccato.
  • Loop infiniti su stream primitivi: Anche con IntStream, LongStream o DoubleStream possono comparire domande su codice che non termina mai.

10.5 Operazioni Intermedie Comuni (Common Intermediate Operations)

Definizioni e Concetti Le operazioni intermedie trasformano lo stream in un altro stream. Restituiscono un nuovo stream e permettono il concatenamento della pipeline; non vengono eseguite finché non viene invocata l'operazione terminale.

Regole di Sintassi e Comportamento Operativo (Tabella 10.2)

  • filter(Predicate): Seleziona elementi.
  • map(Function): Trasforma gli elementi.
  • flatMap(Function): Appiattisce stream annidati.
  • distinct(): Rimuove duplicati.
  • sorted(): Ordina gli elementi.
  • limit(long) e skip(long): Dimensionano lo stream.
  • peek(Consumer): Permette il debug senza alterare il flusso.

⚠️ Tranelli (Side effects ed eccezioni checked):

  • Side effects: In generale è una cattiva pratica introdurre effetti collaterali in una pipeline di stream; tuttavia, all'esame si possono trovare side effects per rendere il codice più conciso, come l'incremento di variabili esterne nel forEach().
  • Checked exceptions: Il problema è che l'interfaccia funzionale a cui si espande il method reference non dichiara l'eccezione. L'interfaccia Supplier non consente eccezioni checked: se un metodo referenziato lancia un'eccezione checked (es. IOException), il codice non compila. Messaggio tipico del compilatore: unhandled exception type IOException.

10.6 Lavoro con gli Stream Primitivi (Working with Primitive Streams)

Definizioni e Concetti Java include IntStream, LongStream e DoubleStream per gestire i tipi primitivi senza l'overhead delle classi wrapper. IntStream copre int, short, byte e char; LongStream copre long; DoubleStream copre double e float. Offrono metodi statistici specifici e range numerici.

Regole di Sintassi e Comportamento Operativo (Tabella 10.5)

  • sum(): Restituisce la somma degli elementi dello stream come primitivo (int, long, double), non come Optional.
  • average(): Restituisce sempre un OptionalDouble, indipendentemente dal tipo di stream primitivo.
  • range(start, end): Intervallo di numeri da start a end - 1 (esclusivo sull'endpoint).
  • rangeClosed(start, end): Intervallo di numeri da start a end (inclusivo sull'endpoint).

Regole per il Mapping tra Stream (Tabelle 10.6 e 10.7)

  • mapToObj(): Converte uno stream primitivo in uno Stream<T> di oggetti.
  • mapToInt(), mapToLong(), mapToDouble(): Convertono uno stream in un altro tipo primitivo.
  • boxed(): Converte uno stream primitivo in uno Stream<T> dove T è la classe wrapper associata al valore primitivo.
  • Metodi mapToX: Java richiede una funzione di mappatura (ToIntFunction, ToDoubleFunction, ecc.) per convertire uno stream in uno di tipo diverso.

⚠️ Tranello (sum() vs min()/max()): Il metodo sum() restituisce un primitivo e non un Optional. A differenza di min() o max(), se lo stream è vuoto sum() restituisce 0 senza ricorrere a un Optional.

10.7 Chiamate Chained e Chaining Optionals

Definizioni e Concetti Gli Optional supportano filter(), map() e flatMap() similmente agli stream, permettendo di manipolare il valore contenuto in modo dichiarativo. Queste operazioni restituiscono un Optional vuoto se quello originale era vuoto o se il predicato/funzione fallisce. Il concatenamento permette di scrivere codice più leggibile ed espressivo rispetto ai blocchi if annidati.

Esempio di Codice (Optional chaining):

optional.map(n -> "" + n).filter(s -> s.length() == 3).ifPresent(System.out::println);

10.8 Collezionamento dei Risultati (Collecting Results)

Definizioni e Concetti La mutable reduction (riduzione mutabile) si riferisce all'operazione terminale collect(), che accumula gli elementi dello stream in un contenitore mutabile come una List o un Set. La classe helper Collectors fornisce implementazioni comuni per accumulare i risultati.

Regole di Sintassi e Comportamento Operativo (Tabella 10.10)

  • toList(), toSet(): Accumulano in collezioni mutabili.
  • joining(): Concatena stringhe; funziona solo con Stream<String>.
  • groupingBy(): Crea una mappa raggruppata.
  • partitioningBy(): Divide lo stream in gruppi true/false; crea sempre una mappa con due chiavi, anche se uno dei raggruppamenti è vuoto.
  • toMap(k, v): Lancia IllegalStateException se sono presenti chiavi duplicate, a meno che non venga fornita una merge function.
  • teeing(): Combina i risultati di due collettori distinti in un unico oggetto.

⚠️ Tranelli (Collectors):

  • toMap() con chiavi duplicate: Se si usa Collectors.toMap(k, v) senza merge function e lo stream contiene chiavi duplicate, Java lancia IllegalStateException a runtime (es. Duplicate key ... attempted merging values lions and bears).
  • partitioningBy(): La mappa risultante ha sempre esattamente dimensione 2, con le chiavi true e false.

10.9 Utilizzo di uno Spliterator (Using a Spliterator)

Definizioni e Concetti L'interfaccia Spliterator<T> viene utilizzata per attraversare e partizionare gli elementi di uno stream, specialmente per l'elaborazione parallela.

Regole di Sintassi e Comportamento Operativo (Tabella 10.11)

  • trySplit(): Restituisce uno Spliterator contenente idealmente metà dei dati, che vengono rimossi dallo Spliterator corrente; può restituire null se i dati non sono più divisibili.
  • tryAdvance(Consumer): Processa un singolo elemento dallo Spliterator, se ne resta almeno uno.
  • forEachRemaining(Consumer): Processa tutti gli elementi restanti nello Spliterator.

⚠️ Tranelli (Spliterator e stampa di uno Stream):

  • trySplit() restituisce null: Eventualmente restituisce null quando i dati non sono più divisibili; l'esame può verificare cosa accade in questo caso.
  • Stampare uno Stream direttamente: System.out.println(stream) stampa il riferimento all'oggetto, non gli elementi.

Esempio di Codice (Stampa di uno stream — output inatteso):

System.out.println(stream.limit(2).map(x -> x + "2"));
// Output: java.util.stream.ReferencePipeline$3@4517d9a3

In particolare: l'uso singolo degli stream e la IllegalStateException al riutilizzo; le operazioni terminali che non terminano su sorgenti infinite e il comportamento di short-circuit di anyMatch()/allMatch(); le eccezioni checked nelle lambda e il messaggio unhandled exception type IOException; sum() su stream primitivi vuoti che restituisce 0 senza Optional; le chiavi duplicate in toMap(); la dimensione fissa 2 di partitioningBy(); la stampa diretta di uno stream che mostra il riferimento oggetto; e trySplit() che può restituire null.

Ch 11: Exceptions and Localization

11.1 Comprensione dei Tipi di Eccezione (Understanding Exception Types)

Definizioni e Concetti Un'Exception (Eccezione) è un evento che altera il flusso del programma. In Java, tutti gli oggetti che rappresentano tali eventi appartengono alla classe radice java.lang.Throwable. Le Checked Exception (Eccezioni controllate) sono eccezioni che devono essere dichiarate o gestite dal codice applicativo nel punto in cui vengono lanciate; in Java, le eccezioni checked ereditano tutte da Exception ma non da RuntimeException. Le Unchecked Exception / Runtime Exception (Eccezioni non controllate) sono eccezioni che non richiedono dichiarazione o gestione obbligatoria; include qualsiasi classe che eredita da RuntimeException o Error. Un Error (Errore) indica una condizione così grave che il programma non dovrebbe tentare di recuperare; gli errori sono eccezioni unchecked che estendono la classe Error e sono lanciati dalla JVM. Lo Stack Trace è la gerarchia di chiamate a metodi effettuate per raggiungere la riga che ha lanciato l'eccezione.

Regole di Gestione (Tabella 11.1)

  • Le eccezioni Unchecked (sottoclassi di RuntimeException) possono essere catturate dal programma e non è richiesto gestirle o dichiararle.
  • Le eccezioni Checked (sottoclassi di Exception ma non di RuntimeException) possono essere catturate e il programma è obbligato a gestirle o dichiararle.
  • Gli Error (sottoclassi di Error) non dovrebbero essere catturati dal programma e non richiedono gestione o dichiarazione.

11.2 Riconoscimento delle Classi di Eccezione (Recognizing Exception Classes)

Definizioni e Concetti Per l'esame è fondamentale riconoscere le classi di eccezione più comuni e la loro classificazione (unchecked, checked o error). Tra le runtime figurano ArithmeticException (divisione per zero), ClassCastException e NumberFormatException (sottoclasse di IllegalArgumentException). Le eccezioni checked comuni includono IOException e la sua sottoclasse FileNotFoundException, mentre tra gli errori spiccano StackOverflowError (ricorsione infinita) e ExceptionInInitializerError (fallimento di un inizializzatore statico).

Eccezioni Runtime (Unchecked - Tabella 11.2)

  • ArithmeticException: Lanciata quando il codice tenta di dividere per zero.
  • ArrayIndexOutOfBoundsException: Lanciata quando il codice usa un indice illegale per accedere a un array.
  • ClassCastException: Lanciata quando si tenta un cast di un oggetto verso una classe di cui non è istanza.
  • NullPointerException: Lanciata quando è richiesto un oggetto ma il riferimento è null.
  • IllegalArgumentException: Lanciata dal programmatore per indicare che un metodo ha ricevuto un argomento illegale o inappropriato.
  • NumberFormatException: Sottoclasse di IllegalArgumentException. Lanciata quando si tenta di convertire una String in un tipo numerico ma la stringa non ha il formato appropriato.

Eccezioni Checked (Tabella 11.3)

  • IOException: Lanciata programmaticamente quando si verifica un problema nella lettura o scrittura di un file.
  • FileNotFoundException: Sottoclasse di IOException. Lanciata programmaticamente quando il codice tenta di referenziare un file che non esiste.
  • NotSerializableException: Sottoclasse di IOException. Lanciata programmaticamente quando si tenta di serializzare o deserializzare una classe non serializzabile.
  • ParseException: Indica un problema nel parsing dell'input.

Errori (Tabella 11.4)

  • ExceptionInInitializerError: Lanciato quando un inizializzatore statico lancia un'eccezione e non la gestisce.
  • StackOverflowError: Lanciato quando un metodo chiama se stesso troppe volte (ricorsione infinita).
  • NoClassDefFoundError: Lanciato quando una classe usata dal codice è disponibile in fase di compilazione ma non a runtime.

11.3 Gestione delle Eccezioni (Handling Exceptions)

Definizioni e Concetti La try statement è l'istruzione utilizzata per separare la logica che potrebbe lanciare un'eccezione dalla logica che la gestisce. Il catch block / clause definisce la gestione: il codice nel blocco try viene eseguito normalmente; se una delle istruzioni lancia un'eccezione catturabile dal tipo indicato nel catch, il blocco try si interrompe e l'esecuzione passa al catch corrispondente. Il finally block è un blocco di codice che viene eseguito sempre, indipendentemente dal fatto che si verifichi o meno un'eccezione. Il Multi-catch è una clausola catch in cui vengono specificati due o più tipi di eccezione separati da una pipe (|); il nome della variabile deve apparire una sola volta e alla fine.

Regole di Sintassi e Comportamento Operativo

  • Requisiti del try: Le parentesi graffe sono obbligatorie. Un'istruzione try deve essere seguita da catch, finally o entrambi.
  • Sintassi Multi-catch: Due o più tipi di eccezione sono specificati, separati da una pipe (|). Il nome della variabile deve apparire una sola volta e alla fine.
  • Esempio valido: catch(Exception1 | Exception2 | Exception3 e).
  • Esempio non valido: catch(Exception1 e | Exception2 e) (ERRORE: nome variabile ripetuto).
  • throw: La parola chiave throw viene usata come statement all'interno di un blocco di codice per lanciare una nuova eccezione o rilanciare un'eccezione esistente.
  • throws: La parola chiave throws viene usata solo alla fine della dichiarazione di un metodo per indicare quali eccezioni il metodo può propagare.

⚠️ Tranelli sulla Gestione:

  • Omissione parentesi graffe: Le parentesi graffe sono obbligatorie per i blocchi try e catch. Le istruzioni try sono come i metodi: le graffe sono richieste anche se c'è una sola istruzione nel blocco, mentre if e loop permettono di ometterle.
  • Blocco try "solitario": Il codice non compila se il blocco try non è seguito da nulla. Un'istruzione try deve essere seguita da catch, finally o entrambi.
  • Ordine delle eccezioni ereditate: Java esamina i blocchi catch nell'ordine in cui appaiono. Se uno dei catch è irraggiungibile, si ottiene un errore di compilazione per codice irraggiungibile; ciò accade ad esempio quando un catch di superclasse precede un catch di sottoclasse. Poiché NumberFormatException è una sottoclasse, verrà sempre catturata dal primo catch, rendendo il secondo catch codice irraggiungibile che non compila.
  • Catch di checked mai lanciate: All'esame, se compare un'eccezione checked in un catch, verificare che il blocco try possa effettivamente lanciare quell'eccezione o una sua sottoclasse; altrimenti il codice è irraggiungibile e non compila. Questa regola non si estende alle eccezioni unchecked né alle eccezioni dichiarate nella firma del metodo.
  • Ridondanza nel Multi-catch: Un blocco multi-catch non può elencare eccezioni in relazione di parentela (sottoclasse/superclasse). Ad esempio, la riga 10 non compila perché RuntimeException è sottoclasse di Exception nel multi-catch, rendendolo ridondante.
  • Scambio throw/throws: Non confondere throw (statement nel blocco) con throws (dichiarazione alla fine del metodo).
  • Mancata istanziazione: L'eccezione non viene mai istanziata senza la parola chiave new.

Esempio di Codice (try senza graffe — non compila):

try
    System.out.println("hello"); // DOES NOT COMPILE: graffe obbligatorie
catch (Exception e) { }

Esempio di Codice (try solitario — non compila):

try {
    System.out.println("hello");
} // DOES NOT COMPILE: manca catch o finally

Esempio di Codice (ordine catch errato — non compila):

try {
    throw new NumberFormatException();
} catch (Exception e) {
} catch (NumberFormatException e) { // DOES NOT COMPILE: catch irraggiungibile
}

Esempio di Codice (multi-catch ridondante — non compila):

try {
    throw new Exception();
} catch (Exception | RuntimeException e) { // DOES NOT COMPILE: RuntimeException è sottoclasse di Exception
}

Esempio di Codice (throw senza new — non compila):

throw RuntimeException(); // DOES NOT COMPILE: manca new

11.4 Automazione della Gestione delle Risorse (Automating Resource Management)

Definizioni e Concetti La try-with-resources è un'istruzione che automatizza la gestione delle risorse, chiudendole automaticamente al termine del blocco, a condizione che implementino l'interfaccia AutoCloseable. Le risorse vengono chiuse in ordine inverso rispetto alla dichiarazione. Le risorse dichiarate nel try sono in scope solo all'interno del blocco try; tentare di accedervi nel catch o finally causa errore di compilazione. Questa struttura è preferibile rispetto alla chiusura manuale nel blocco finally perché riduce il codice boilerplate e gestisce meglio le Suppressed Exceptions (Eccezioni soppresse): eccezioni accantonate quando più eccezioni vengono lanciate durante la chiusura delle risorse in un try-with-resources.

Regole di Sintassi e Comportamento Operativo

  • Chiusura delle risorse: Le risorse vengono chiuse in ordine inverso rispetto alla dichiarazione.
  • Scope delle risorse: Le risorse dichiarate nel try sono in scope solo all'interno del blocco try.
  • Punteggiatura: Punto e virgola obbligatorio tra le risorse; punto e virgola opzionale alla fine dell'elenco delle dichiarazioni.

⚠️ Tranelli sul try-with-resources:

  • Risorse non compatibili: La riga 7 non compila perché StringBuilder non implementa AutoCloseable ed è quindi incompatibile con un'istruzione try-with-resources.
  • Scope delle risorse: Tentare di accedere a una risorsa dichiarata nel try dal blocco catch o finally causa errore di compilazione.
  • Eccezioni non gestite nel main: Se il try-with-resources o il corpo del metodo lanciano eccezioni checked, queste devono essere dichiarate o gestite, altrimenti il codice non compila. Errore tipico: la riga 5 non compila perché la FileNotFoundException lanciata alla riga 12 non è gestita né dichiarata dal metodo.

Esempio di Codice (StringBuilder in try-with-resources — non compila):

try (StringBuilder sb = new StringBuilder()) { // DOES NOT COMPILE: StringBuilder non implementa AutoCloseable
    sb.append("hello");
}

11.5 Formattazione dei Valori (Formatting Values)

Definizioni e Concetti La Formatting (Formattazione) è il processo di inserimento e formattazione di parametri in stringhe tramite simboli specifici. La formattazione avviene tramite i metodi String.format() o String.formatted(). L'ordine dei parametri inseriti corrisponde all'ordine dei simboli forniti nella stringa di formato.

Simboli di Formattazione (Tabella 4.2)

  • %s: Si applica a qualsiasi tipo, comunemente valori String.
  • %d: Si applica a valori interi come int e long.
  • %f: Si applica a valori in virgola mobile come float e double.
  • %n: Inserisce un'interruzione di riga usando il separatore di riga dipendente dal sistema.

⚠️ Tranelli sulla Formattazione:

  • Mismatch dei tipi: Mescolare tipi di dati incompatibili può causare eccezioni a runtime. Ad esempio, il codice seguente lancia un'eccezione perché viene usato un numero in virgola mobile dove è atteso un valore intero.

Esempio di Codice (Mismatch tipi — lancia eccezione):

var str = "Food: %d tons".formatted(2.0); // Lancia IllegalFormatConversionException

11.6 Supporto all'Internazionalizzazione e Localizzazione (Localization)

Definizioni e Concetti La Localization (Localizzazione) è il supporto che permette a un programma di adattarsi a diversi paesi o lingue. Un Locale è la classe (java.util.Locale) utilizzata per rappresentare una specifica regione geografica, politica o culturale. Questo supporto è fondamentale per gestire correttamente formati di date, numeri e valute specifici per ogni cultura.

Sintassi dei Locale (Figura 11.6)

  • Composizione: Un Locale può avere solo il codice lingua (es. fr) oppure lingua e paese (es. en_US). In generale è composto da un codice lingua obbligatorio (in minuscolo, es. en) e un codice paese opzionale (in maiuscolo, es. US), separati da un underscore (es. en_US).
  • Case sensitivity: Il codice lingua deve essere in minuscolo; il codice paese deve essere in maiuscolo.
  • Separatore: Lingua e paese sono separati da un underscore (_).

11.7 Caricamento delle Proprietà con i Resource Bundle

Definizioni e Concetti I Resource Bundle sono file utilizzati per esternalizzare le stringhe e supportare la traduzione del programma senza modificare il codice sorgente. Java segue una gerarchia precisa: cerca prima il match più specifico e risale verso il bundle di base. Se non viene trovata alcuna corrispondenza per la lingua richiesta, Java ripiega sul Locale predefinito del sistema.

Gerarchia di Ricerca

  • Ordine di ricerca tipico: Nome_lingua_PAESE.properties → Nome_lingua.properties → Nome.properties.
  • Esempio concreto: Nome_en_US.properties → Nome_en.properties → Nome.properties.

⚠️ Tranelli sui Resource Bundle:

  • Default Locale Fallback: Se non viene trovata una corrispondenza per la lingua richiesta, Java ripiega sul locale predefinito del sistema. Non cercare subito il file base se esiste un bundle per il locale predefinito.
  • Esempio: Se cerchi fr ma non esiste, e il default è en_US, Java cercherà en_US prima di passare al bundle di base senza suffisso.
  • Esempio Penguin (Domanda 6 Assessment): Java utilizzerà Penguin_en.properties come bundle corrispondente. Se una chiave (es. "age") non è presente in Penguin_en.properties, Java deve cercare più in alto nella gerarchia fino a Penguin.properties.

11.8 Overriding e Eccezioni (Integrazione dalle Note)

Definizioni e Concetti In un override, un metodo sottoclasse non può dichiarare eccezioni checked nuove o più ampie rispetto al metodo ereditato. Un metodo override in una sottoclasse può invece dichiarare meno eccezioni rispetto alla superclasse o all'interfaccia.

⚠️ Tranello (Eccezioni più ampie in override): Dichiarare eccezioni checked più ampie o aggiuntive rispetto al metodo ereditato impedisce la compilazione.

Esempio di Codice (override con eccezione checked più ampia — non compila):

class Parent {
    void read() throws IOException { }
}
class Child extends Parent {
    void read() throws Exception { } // DOES NOT COMPILE: Exception è più ampia di IOException
}

11.9 Casi Limite e Tranelli Sintattici

Tutti i casi limite e i tranelli sopra descritti costituiscono gli elementi critici per evitare errori di compilazione e runtime nel Capitolo 11. In particolare: l'obbligo delle parentesi graffe in try/catch (a differenza di if e loop); il blocco try che deve essere seguito da catch, finally o entrambi; l'ordine delle clausole catch (superclasse prima della sottoclasse rende il codice irraggiungibile); i catch di eccezioni checked mai lanciate dal try (con l'eccezione delle unchecked e delle eccezioni dichiarate nella firma); la ridondanza nel multi-catch per eccezioni in relazione di parentela; lo scambio tra throw e throws; l'istanziazione obbligatoria con new in throw; le risorse try-with-resources che devono implementare AutoCloseable, la punteggiatura con punto e virgola tra risorse, e lo scope limitato al blocco try; le eccezioni checked non gestite nel main o nel corpo del metodo; le Suppressed Exceptions gestite automaticamente dal try-with-resources; il mismatch dei tipi in String.formatted() e la corrispondenza tra ordine dei simboli e ordine dei parametri; la sintassi dei Locale (case sensitivity e separatore _); la gerarchia di ricerca dei Resource Bundle con fallback al locale predefinito; e le regole sulle eccezioni checked in override (meno eccezioni ammesse, eccezioni più ampie vietate).

Ch 12: Modules

12.1 Introduzione ai Moduli (Introducing Modules)

Definizioni e Concetti Un modulo è un gruppo di pacchetti correlati e risorse insieme a un file descrittore di modulo denominato module-info.java. I moduli forniscono un meccanismo per raggruppare i pacchetti in una singola unità logica e garantiscono un incapsulamento più forte (strong encapsulation), consentendo allo sviluppatore di specificare esattamente quali pacchetti sono visibili all'esterno. Questo sistema risolve i problemi storici di classpath ingombranti e conflitti tra dipendenze (JAR hell), verificando che tutte le dipendenze siano presenti e compatibili già al momento dell'avvio (startup) dell'applicazione.

12.2 Creazione ed Esecuzione di un Programma Modulare (Creating and Running a Modular Program)

Definizioni e Concetti Il Module Descriptor (descrittore di modulo) è un file Java compilato (module-info.class, generato da module-info.java) posizionato nella cartella radice del modulo che contiene le direttive che controllano visibilità, esportazioni e dipendenze. Il module path indica al compilatore e alla JVM la posizione delle cartelle o dei file JAR contenenti i moduli nel file system.

Regole di Creazione, Compilazione ed Esecuzione

  • Struttura: Il file module-info.java deve essere collocato nella radice del modulo (ad esempio src/zoo.animal.feeding/module-info.java).
  • Compilazione (javac): Si utilizza l'opzione -d per specificare la cartella di destinazione dei file binari e si include il file descrittore insieme ai file sorgente.
  • Esecuzione (java): Si specifica il module path con --module-path (o -p) e il modulo da avviare con --module (o -m) seguito dal nome del modulo e dal nome completo della classe contenente il metodo main, separati da uno slash (/).

Esempi di Codice e Comandi:

// feeding/module-info.java
module zoo.animal.feeding {
}

# Compilazione
javac -d mods feeding/module-info.java feeding/zoo/animal/feeding/Task.java

# Esecuzione
java --module-path mods --module zoo.animal.feeding/zoo.animal.feeding.Task

⚠️ Tranelli (Comandi e Struttura):

  • Modificatori di accesso non permessi: Un modulo non può essere dichiarato public. Anche se le classi al suo interno sono pubbliche, la parola chiave public davanti a module non è consentita.
  • Sintassi dei trattini (Dashes): L'opzione breve -p richiede un singolo trattino, mentre la forma estesa --module-path ne richiede due. L'uso errato del numero di trattini (es. -module-path) impedisce l'avvio del programma.
  • Separatore Modulo/Classe: Nell'opzione --module, il nome del modulo e la classe principale devono essere separati da uno slash (/). L'uso del punto (.) al posto dello slash impedisce alla JVM di individuare la classe main.
  • Posizionamento del descrittore: Il file module-info.java deve risiedere nella cartella radice del modulo; collocarlo in un sotto-pacchetto (es. com/vet/module-info.java) genera un errore di compilazione.

Esempio di Codice (Dichiarazione con modificatore non valido — non compila):

public module zoo.animal.feeding { } // DOES NOT COMPILE: 'public' non è ammesso

12.3 Aggiornamento per Moduli Multipli (Updating Our Example for Multiple Modules)

Definizioni e Regole di Interazione Quando un progetto coinvolge più moduli, la comunicazione tra di essi è bloccata di default e deve essere esplicitamente dichiarata nei rispettivi file module-info.java.

  • requires: La direttiva requires nome.modulo dichiara che il modulo corrente dipende da un altro modulo e ha bisogno di leggerne i pacchetti esportati.
  • exports: La direttiva exports nome.pacchetto rende accessibili tutti i tipi pubblici del pacchetto specificato agli altri moduli.

Esempi di Codice:

// Modulo fornitore (care/module-info.java)
module zoo.animal.care {
    exports zoo.animal.care.medical;
}

// Modulo consumatore (talks/module-info.java)
module zoo.animal.talks {
    requires zoo.animal.care;
}

⚠️ Tranelli (Nomi e Dipendenze):

  • Confusione tra Moduli e Pacchetti: La direttiva requires fa sempre riferimento a un nome di modulo, mentre la direttiva exports fa sempre riferimento a un nome di pacchetto. Scambiare i riferimenti (esportare un modulo o richiedere un pacchetto) causa un errore di compilazione.
  • Dipendenze Cicliche: Java non ammette dipendenze circolari tra moduli (es. il Modulo A richiede il Modulo B, e il Modulo B richiede il Modulo A, anche attraverso moduli intermedi). Un ciclo di dipendenze impedisce la compilazione.

12.4 Approfondimento della Dichiarazione del Modulo (Diving into the Module Declaration)

Direttive Fondamentali

  • exports: Espone i membri pubblici e protetti di un pacchetto sia a tempo di compilazione che a runtime.
  • requires: Specifica una dipendenza diretta verso un modulo target.
  • requires transitive: Indica che qualsiasi modulo che dichiara una dipendenza verso questo modulo acquisirà automaticamente anche la dipendenza verso il modulo indicato come transitivo (implied readability).
  • opens: Concede l'accesso riflessivo (reflection) a runtime a tutti i membri del pacchetto (inclusi quelli privati), ma non rende il pacchetto accessibile a tempo di compilazione.
  • requires mandated java.base: Dipendenza implicita presente in qualsiasi modulo Java; non è necessario scriverla poiché la JVM include automaticamente il modulo fondamentale java.base.

Direttive Qualificate e Moduli Aperti

  • Qualified Exports: exports nome.pacchetto to moduloA, moduloB; limita l'esportazione del pacchetto esclusivamente ai moduli elencati.
  • Qualified Opens: opens nome.pacchetto to moduloReflective; limita l'accesso via reflection solo ai moduli autorizzati.
  • Open Module: Dichiarare open module nome.modulo { ... } apre automaticamente tutti i pacchetti del modulo alla reflection a runtime, senza dover specificare singole direttive opens.

Esempi di Codice:

// Modulo con dipendenza transitiva
module zoo.animal.care {
    exports zoo.animal.care.medical;
    requires transitive zoo.animal.feeding; // Chi richiede care legge automaticamente feeding
}

// Modulo aperto alla reflection per framework di terze parti
open module zoo.animal.talks {
    requires zoo.animal.care;
}

⚠️ Tranelli sulla Dichiarazione:

  • opens all'interno di open module: Non è consentito inserire una direttiva opens all'interno di un modulo già dichiarato come open module (l'operazione è ridondante e causa errore di compilazione).
  • Transitività omessa: Se il Modulo A richiede il Modulo B, e il Modulo B usa tipi del Modulo C nella firma pubblica dei suoi metodi ma dichiara un semplice requires C (senza transitive), il Modulo A non potrà compilare a meno che non aggiunga un proprio requires C esplicito.
  • Riflessione non autorizzata: Tentare un accesso via reflection (setAccessible(true)) su classi o campi non aperti tramite opens lancia a runtime una InaccessibleObjectException.

Esempio di Codice (opens ridondante in open module — non compila):

open module zoo.animal.talks {
    opens zoo.animal.talks.media; // DOES NOT COMPILE: modulo già interamente aperto
}

12.5 Creazione di un Servizio (Creating a Service)

Definizioni e Concetti Il meccanismo dei servizi permette il completo disaccoppiamento (decoupling) tra moduli tramite la classe java.util.ServiceLoader.

  • Service Provider Interface (SPI): Un'interfaccia o classe astratta che definisce il contratto del servizio.
  • Service Provider: La classe concreta che implementa l'interfaccia di servizio.
  • Service Locator: Il componente (ServiceLoader) incaricato di cercare e istanziare le implementazioni disponibili a runtime.

Direttive e Sintassi

  • uses: Utilizzata dal modulo consumatore per indicare l'intenzione di consumare un'interfaccia di servizio (es. uses zoo.animal.care.medical.HealthChecker;).
  • provides...with: Utilizzata dal modulo fornitore per associare l'interfaccia alla propria classe di implementazione concreta (es. provides SPI with Implementazione;).

Esempi di Codice:

// Modulo Fornitore del Servizio
module zoo.animal.care {
    exports zoo.animal.care.medical;
    provides zoo.animal.care.medical.HealthChecker 
        with zoo.animal.care.medical.VetDoctor;
}

// Modulo Consumatore del Servizio
module zoo.visitor {
    requires zoo.animal.care;
    uses zoo.animal.care.medical.HealthChecker;
}

// Codice Java di caricamento tramite ServiceLoader
ServiceLoader<HealthChecker> loader = ServiceLoader.load(HealthChecker.class);
for (HealthChecker checker : loader) {
    checker.checkHealth();
}

⚠️ Tranelli sui Servizi:

  • Distinzione uses vs provides: Il consumatore specifica l'interfaccia con uses; il fornitore specifica l'interfaccia e la classe implementativa con provides ... with ....
  • Costruttore della classe concreta: La classe di implementazione specificata nella clausola with deve essere una classe concreta (non astratta), deve implementare l'interfaccia dichiarata e deve possedere un costruttore pubblico senza argomenti (public no-args constructor) oppure un metodo factory statico public static provider().
  • Disaccoppiamento totale: Il modulo consumatore non deve includere una direttiva requires verso il modulo fornitore dell'implementazione, ma solo verso il modulo che dichiara l'interfaccia (SPI), consentendo di sostituire o aggiungere implementazioni a runtime senza ricompilare il consumatore.

12.6 Scoperta e Ispezione dei Moduli (Discovering and Inspecting Modules)

Strumenti da Riga di Comando

  • java --list-modules: Elenca tutti i moduli di sistema predefiniti forniti dalla distribuzione JDK in uso.
  • java --describe-module / java -d: Ispeziona e stampa a console la dichiarazione di un modulo compilato, inclusi pacchetti esportati, aperti e dipendenze.
  • java --show-module-resolution: Mostra in dettaglio durante l'avvio della JVM l'albero di risoluzione e caricamento di tutti i moduli coinvolti.
  • jdeps: Analizza le dipendenze di classi o file JAR a livello di pacchetto. Con l'opzione -s o --summary, riassume le dipendenze tra moduli a livello macro.
  • jmod: Crea o manipola file in formato archivio JMOD. A differenza dei JAR, i file JMOD possono contenere librerie native (es. file .dll, .so) e file di configurazione, e sono utilizzabili esclusivamente a tempo di compilazione e collegamento.
  • jlink: Assembla un insieme di moduli e un runtime personalizzato minimale (custom runtime image), includendo solo i moduli JDK strettamente necessari per l'applicazione.
  • jpackage: Genera un pacchetto di installazione nativo per lo specifico sistema operativo (es. .exe, .msi, .dmg, .deb, .rpm), incorporando il runtime generato.

Esempi di Comandi:

# Ispezionare un modulo specifico
java --describe-module zoo.animal.feeding

# Analizzare il riepilogo delle dipendenze di un JAR con jdeps
jdeps -s mods/zoo.animal.care.jar

# Creare un'immagine runtime minimale con jlink
jlink --module-path $JAVA_HOME/jmods:mods --add-modules zoo.animal.feeding --output customRuntime

⚠️ Tranelli sugli Strumenti:

  • jdeps a livello di pacchetto: jdeps elenca i pacchetti utilizzati dalle classi, permettendo di risalire ai moduli richiesti. Il suo output include sempre la voce requires mandated java.base.
  • Limitazioni dei file JMOD: I file con estensione .jmod non possono essere eseguiti direttamente tramite il comando java e non possono essere inseriti nel classpath a runtime; il loro impiego è riservato alla fase di build e linking con jlink.

12.7 Confronto tra Tipi di Moduli (Comparing Types of Modules)

Proprietà dei Moduli (Named, Automatic, Unnamed)

  • Named Module: Modulo collocato sul module path contenente un descrittore module-info.class compilato. Esporta solo i pacchetti esplicitamente dichiarati ed è leggibile solo da chi lo dichiara in requires. Non può accedere all'Unnamed Module.
  • Automatic Module: Normale archivio JAR (senza module-info.class) posizionato sul module path. Java ne genera il nome automaticamente o lo estrae dal manifesto. Esporta tutti i propri pacchetti a tutti gli altri moduli e può leggere tutti i moduli sul module path oltre a tutto il contenuto del classpath (Unnamed Module).
  • Unnamed Module: Insieme di tutti i file di classe e JAR posizionati sul tradizionale classpath. Non possiede un descrittore di modulo valido (se presente viene ignorato). Esporta tutti i propri pacchetti a tutte le classi del classpath e può accedere a tutti i moduli esportati, ma funge da contenitore legacy isolato per retrocompatibilità.

Algoritmo di Denominazione dei Moduli Automatici Se un file JAR privo di descrittore viene posto sul module path, Java ne determina il nome secondo queste regole:

  1. Se nel file MANIFEST.MF è specificata la voce Automatic-Module-Name, viene utilizzato tale valore.
  2. In caso contrario, Java ricava il nome dal nome del file:
    • Rimuove l'estensione .jar.
    • Rimuove le informazioni di versione finali (es. commons-lang3-3.12.0.jar $\to$ commons-lang3).
    • Sostituisce qualsiasi carattere non alfanumerico (trattini, trattini bassi) con un punto (commons-lang3 $\to$ commons.lang3).
    • Rimuove eventuali punti iniziali, finali o doppi punti consecutivi.

⚠️ Tranelli sui Tipi di Moduli:

  • Isolamento degli Unnamed Modules: Un Named Module sul module path non può mai accedere alle classi presenti sull'Unnamed Module (classpath). Qualsiasi tentativo genera errore di compilazione.
  • JAR modulare posto sul Classpath: Se un JAR contenente un regolare module-info.class viene inserito per errore sul classpath invece che sul module path, la JVM lo tratta come un ordinario Unnamed Module ignorando completamente il suo descrittore.

12.8 Migrazione di un'Applicazione (Migrating an Application)

Strategie di Migrazione

  • Bottom-up Migration: Si inizia convertendo in moduli i JAR di livello più basso (quelli privi di dipendenze da altre librerie interne del progetto), spostandoli gradualmente dal classpath al module path come Named Modules, risalendo l'albero delle dipendenze fino alla classe principale.
  • Top-down Migration: Si posizionano inizialmente tutti i JAR dell'applicazione sul module path facendoli agire come Automatic Modules (garantendo la compilazione immediata), per poi convertire ciascun JAR in un Named Module uno alla volta, aggiungendo il rispettivo module-info.java.

12.9 Casi Limite e Tranelli Sintattici

Tutti i casi limite e i tranelli sintattici sopra descritti costituiscono i punti critici per l'esame nel Capitolo 12:

  • Il divieto assoluto del modificatore public nella dichiarazione del modulo (public module non compila).
  • La rigorosa distinzione tra nomi di moduli nelle direttive requires e nomi di pacchetti nelle direttive exports e opens.
  • L'obbligo di collocare il file module-info.java nella cartella radice del modulo e il divieto di inserire opens all'interno di un open module.
  • La corretta sintassi dei comandi CLI: la differenza nel numero di trattini tra -p e --module-path, e l'uso obbligatorio dello slash (/) come separatore tra nome del modulo e classe principale nell'opzione --module.
  • I vincoli architetturali dei servizi SPI: il costruttore pubblico senza argomenti obbligatorio nella classe di implementazione (with) e il disaccoppiamento che vieta il requires diretto del consumatore verso il fornitore.
  • L'impossibilità per i Named Modules di accedere alle classi dell'Unnamed Module sul classpath.
  • L'algoritmo di naming dei moduli automatici e la gestione dei file JMOD (non eseguibili direttamente né utilizzabili sul classpath a runtime).

13.1 Introduzione ai Thread (Introducing Threads)

Definizioni e Concetti Un thread è la più piccola unità di esecuzione che può essere pianificata da un sistema operativo o dalla JVM. Java 21 supporta due tipologie fondamentali di thread:

  • Platform Thread (Thread di piattaforma): Thread tradizionale gestito direttamente dal sistema operativo sottostante (mappatura 1:1 con i thread del kernel del sistema operativo). Ha un costo di memoria significativo (tipicamente 1 MB di stack riservato) e un limite rigido sul numero massimo di istanze creabili.
  • Virtual Thread (Thread virtuale): Introdotto come funzionalità standard in Java 21, è un thread leggero gestito interamente dalla JVM in memoria utente (user-space). Migliaia o milioni di virtual thread possono essere eseguiti contemporaneamente sfruttando un piccolo pool di carrier thread (platform thread sottostanti), rendendoli ideali per operazioni di I/O bloccante ad alto throughput.

Terminologia Tecnica dei Thread

  • Task: Una singola unità di lavoro autonoma eseguita da un thread.
  • Thread Scheduler: Componente del sistema operativo o della JVM che determina quale thread, tra quelli attualmente nello stato RUNNABLE, debba essere allocato ed eseguito sulla CPU.
  • Context Switch: Il processo mediante il quale lo scheduler memorizza lo stato di esecuzione corrente di un thread (registri CPU, puntatore d'istruzione, stack) e ripristina lo stato di un altro thread per riprenderne l'elaborazione.
  • Thread Priority: Valore numerico intero associato a ciascun thread che funge da suggerimento (hint) allo scheduler per la scelta del thread da mandare in esecuzione tra quelli pronti. In Java i valori ammessi vanno da Thread.MIN_PRIORITY (1) a Thread.MAX_PRIORITY (10), con valore predefinito Thread.NORM_PRIORITY (5).

Creazione ed Esecuzione con il Builder di Java 21 Oltre all'estensione della classe Thread o all'implementazione dell'interfaccia funzionale Runnable, Java 21 introduce l'API fluente di factory/builder:

  • Thread di piattaforma: Thread.ofPlatform().name("p-thread").start(runnable)
  • Thread virtuale: Thread.ofVirtual().name("v-thread").start(runnable)

Stati del Thread (Thread States e Ciclo di Vita) L'enumerazione Thread.State definisce i sei stati del ciclo di vita di un thread:

  • NEW: Il thread è stato istanziato ma non è ancora stato avviato (non è ancora stato invocato il metodo start()).
  • RUNNABLE: Il thread è in esecuzione sulla CPU o è pronto per essere eseguito non appena lo scheduler gli assegna tempo macchina.
  • BLOCKED: Il thread è in attesa di acquisire un lock intrinseco per entrare o rientrare in un blocco o metodo synchronized.
  • WAITING: Il thread è in attesa indefinita che un altro thread esegua un'azione specifica (es. dopo aver invocato Object.wait(), Thread.join() senza timeout o LockSupport.park()).
  • TIMED_WAITING: Il thread è in attesa per un intervallo di tempo specificato (es. dopo aver invocato Thread.sleep(ms), Object.wait(ms), Thread.join(ms) o LockSupport.parkNanos()).
  • TERMINATED: Il thread ha completato l'esecuzione del metodo run() oppure è terminato a causa di un'eccezione non gestita.

⚠️ Tranelli (Virtual Threads e Ciclo di Vita):

  • Assenza di costruttori pubblici per i Virtual Thread: Non esiste una classe pubblica istanziabile VirtualThread. Il tentativo di invocare new VirtualThread() causa un errore di compilazione; è obbligatorio usare i factory method come Thread.ofVirtual().
  • Daemon status dei Virtual Thread: I virtual thread sono sempre thread daemon di default. Il tentativo di renderli non-daemon tramite thread.setDaemon(false) lancia una IllegalArgumentException.
  • Invocare run() invece di start(): Chiamare direttamente il metodo run() esegue il codice in modo sincrono nel thread chiamante corrente senza allocare né avviare alcun nuovo thread.
  • Confusione tra BLOCKED e WAITING: BLOCKED riguarda esclusivamente l'attesa di un monitor synchronized. L'attesa dovuta a wait(), join() o LockSupport pone il thread in WAITING o TIMED_WAITING.

Esempi di Codice:

Runnable task = () -> System.out.println("Esecuzione thread");

// Creazione e avvio corretto con Java 21 Builder
Thread vThread = Thread.ofVirtual().name("my-virtual-thread").start(task); // OK
Thread pThread = Thread.ofPlatform().daemon().start(task);                // OK

// Errori di compilazione e runtime
var err1 = new VirtualThread(task); // DOES NOT COMPILE: nessun costruttore pubblico
vThread.setDaemon(false);           // Lancia IllegalArgumentException a runtime

// Errore logico: non avvia un nuovo thread
Thread t = new Thread(task);
t.run(); // Esegue il task nel thread corrente (NON avvia un nuovo thread)
t.start(); // OK: avvia un nuovo thread asincrono

13.2 Creazione di Thread con l'API di Concorrenza (Creating Threads with the Concurrency API)

Definizioni e Oggetti L'API di concorrenza (java.util.concurrent) astrae la gestione diretta dei thread fornendo interfacce per la definizione e l'esecuzione di task asincroni:

  • Runnable: Interfaccia funzionale con metodo void run(); non accetta parametri, non restituisce valori e non può lanciare eccezioni controllate (checked exceptions).
  • Callable<V>: Interfaccia funzionale con metodo V call() throws Exception; consente di restituire un valore di tipo generico V e di lanciare qualsiasi eccezione controllata o non controllata.
  • Future<V>: Rappresenta il risultato di un'elaborazione asincrona. Fornisce metodi per verificare se il task è completato (isDone()), cancellarlo (cancel(boolean)) e recuperare il valore (get()).
  • ExecutorService: Servizio di orchestrazione che gestisce un pool di thread e il ciclo di vita dell'esecuzione dei task.
  • ScheduledExecutorService: Sotto-interfaccia di ExecutorService per la pianificazione di task ritardati o periodici.

Metodi Principali di ExecutorService

  • execute(Runnable): Esegue il task in modo asincrono; ha tipo di ritorno void e non offre alcun modo per monitorare il completamento del task.
  • submit(Callable<T>) / submit(Runnable): Sottomette il task e restituisce un oggetto Future per monitorare o estrarre il risultato.
  • invokeAll(Collection<Callable<T>>): Esegue tutti i task e restituisce una List<Future<T>> mantenendo l'ordine della collezione; il metodo è sincrono e si blocca finché tutti i task non sono completati.
  • invokeAny(Collection<Callable<T>>): Esegue i task e si blocca finché uno di essi non termina con successo, restituendo direttamente il valore del primo completato e cancellando gli altri.

Metodi di Future

  • get(): Si blocca a tempo indefinito in attesa che il task termini, restituendo il risultato. Può lanciare InterruptedException ed ExecutionException.
  • get(long timeout, TimeUnit unit): Si blocca al massimo per l'intervallo specificato; se il task non è ancora terminato, lancia TimeoutException.
  • cancel(boolean mayInterruptIfRunning): Tenta di annullare l'esecuzione del task.
  • isDone() / isCancelled(): Restituiscono true se il task è completato (con successo o con eccezione) o se è stato cancellato.

Pianificazione con ScheduledExecutorService

  • schedule(Callable/Runnable, long delay, TimeUnit unit): Esegue il task una sola volta dopo il ritardo specificato.
  • scheduleAtFixedRate(Runnable, long initDelay, long period, TimeUnit unit): Esegue il task periodicamente a intervalli fissi, calcolando il periodo a partire dall'inizio dell'esecuzione di ciascun ciclo.
  • scheduleWithFixedDelay(Runnable, long initDelay, long delay, TimeUnit unit): Esegue il task periodicamente calcolando l'intervallo a partire dalla fine dell'esecuzione del ciclo precedente.

Ciclo di Vita dell'Executor (Executor Lifecycle) Un ExecutorService possiede tre stati interni:

  1. Active: Accetta nuovi task ed esegue quelli sottomessi.
  2. Shutting Down: Stato successivo all'invocazione di shutdown(); rifiuta nuovi task (lanciando RejectedExecutionException) ma prosegue con l'esecuzione dei task già sottomessi o in corso.
  3. Shutdown / Terminated: Tutti i task sono terminati e nessun thread è più attivo.

⚠️ Tranelli (Executor e Lifecycle):

  • Metodo factory per Virtual Thread: La classe Executors dispone di un unico metodo dedicato ai thread virtuali: Executors.newVirtualThreadPerTaskExecutor(). L'uso di metodi tradizionali come newFixedThreadPool(n) alloca sempre platform thread.
  • Differenza tra isShutdown() e isTerminated(): Appena viene chiamato shutdown(), isShutdown() restituisce immediatamente true, mentre isTerminated() rimane false finché tutti i task correnti non hanno effettivamente terminato l'esecuzione.
  • Blocco della JVM per mancato shutdown: Se non si invoca shutdown() su un ExecutorService basato su platform thread non daemon, la JVM non terminerà l'esecuzione dell'applicazione al termine del main().
  • Parametri di ScheduledExecutorService: scheduleAtFixedRate e scheduleWithFixedDelay accettano solo Runnable e non Callable.

Esempi di Codice:

// ExecutorService con Virtual Thread
try (ExecutorService service = Executors.newVirtualThreadPerTaskExecutor()) {
    Future<String> future = service.submit(() -> "Risultato da Callable");
    String result = future.get(2, TimeUnit.SECONDS); // Può lanciare TimeoutException
    System.out.println(result);
} // L'uscita dal try-with-resources invoca implicitamente close() (che invoca shutdown())

// ScheduledExecutorService
ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();
scheduler.scheduleWithFixedDelay(() -> {
    System.out.println("Esecuzione periodica con delay fisso");
}, 1, 3, TimeUnit.SECONDS);

13.3 Scrittura di Codice Thread-Safe (Writing Thread-Safe Code)

Definizioni e Meccanismi La Thread-safety è la proprietà di un programma o struttura dati di funzionare correttamente quando eseguita contemporaneamente da più thread senza generare stati inconsistenti.

  • Race Condition (Corsa critica): Condizione anomala che si verifica quando due o più thread tentano di accedere e modificare contemporaneamente una risorsa condivisa, e il risultato finale dipende dalla sequenza temporale non deterministica di esecuzione dei thread.
  • Sezione Critica: Porzione di codice che accede a risorse condivise modificabili e che deve essere protetta da accessi concorrenti non coordinati.

Classi Atomiche (Atomic Classes) Il package java.util.concurrent.atomic fornisce classi come AtomicInteger, AtomicLong, AtomicBoolean e AtomicReference che consentono di eseguire operazioni di lettura, aggiornamento e scrittura in modo atomico (indivisibile) a livello di istruzioni CPU (tramite operazioni CAS - Compare-And-Swap), senza ricorrere a lock espliciti:

  • get() / set(val): Legge o imposta il valore atomico.
  • getAndSet(val): Imposta il nuovo valore e restituisce il valore precedente.
  • incrementAndGet() / getAndIncrement(): Incrementa di 1 (equivalenti atomici rispettivamente di ++val e val++).
  • decrementAndGet() / getAndDecrement(): Decrementa di 1 (equivalenti atomici di --val e val--).
  • compareAndSet(expected, update): Imposta il valore a update solo se il valore attuale è uguale a expected, restituendo true in caso di successo.
  • updateAndGet(IntUnaryOperator updateFunction): Aggiorna atomicamente il valore corrente applicando la funzione specificata e restituisce il valore aggiornato.
  • getAndUpdate(IntUnaryOperator updateFunction): Aggiorna atomicamente il valore corrente applicando la funzione specificata e restituisce il valore precedente prima dell'aggiornamento.
  • accumulateAndGet(int x, IntBinaryOperator accumulatorFunction): Aggiorna atomicamente il valore corrente combinandolo con x tramite la funzione specificata e restituisce il valore aggiornato.
  • getAndAccumulate(int x, IntBinaryOperator accumulatorFunction): Aggiorna atomicamente combinando il valore corrente con x e restituisce il valore precedente prima dell'accumulazione.

Meccanismi di Lock e ReentrantLock Oltre alla sincronizzazione implicita tramite la parola chiave synchronized, Java fornisce l'interfaccia java.util.concurrent.locks.Lock e la sua implementazione ReentrantLock:

  • lock(): Acquisisce il lock, bloccando il thread finché non diventa disponibile.
  • unlock(): Rilascia il lock. Deve essere sempre collocato all'interno di un blocco finally per evitare deadlock in caso di eccezioni.
  • tryLock(): Tenta di acquisire il lock immediatamente; se è occupato, restituisce false senza bloccare l'esecuzione.
  • tryLock(long timeout, TimeUnit unit): Tenta di acquisire il lock per un tempo massimo specificato.
  • isLocked(): Verifica se il lock è attualmente detenuto da un qualsiasi thread ("Checks if the lock is currently held by any thread").
  • isHeldByCurrentThread(): Verifica se il lock è attualmente detenuto specificamente dal thread chiamante corrente.
  • getQueueLength(): Restituisce una stima del numero di thread attualmente in coda in attesa di acquisire questo lock ("Returns an estimate of the number of threads waiting to acquire this lock").
  • hasQueuedThreads(): Restituisce true se sono presenti uno o più thread in attesa di acquisire il lock.

⚠️ Tranelli (Sincronizzazione e Atomicità):

  • Non-atomicità di count++: L'operazione count++ è composta da 3 distinte operazioni macchina (lettura, incremento, scrittura). Più thread che eseguono count++ concorrentemente perderanno aggiornamenti se non protetti da sincronizzazione o classi atomiche.
  • Sincronizzazione su monitor differenti: Se due thread sincronizzano la stessa sezione critica bloccandosi su due istanze di oggetti diverse (es. synchronized(new Object())), la sincronizzazione è inefficace e si verifica comunque una race condition.
  • Dimenticare unlock() nel blocco finally: Se si lancia un'eccezione all'interno della sezione protetta prima di rilasciare il lock, il lock rimarrà permanentemente acquisito causando il blocco di tutti gli altri thread.

Esempi di Codice:

// 1. Thread-safe tramite AtomicInteger e metodi funzionali
public class AtomicCounter {
    private final AtomicInteger count = new AtomicInteger(0);
    
    public void increment() {
        count.incrementAndGet(); // OK: atomico
    }
    
    public int multiplyByTwo() {
        return count.updateAndGet(n -> n * 2); // OK: aggiornamento atomico con funzione
    }
    
    public int addValue(int x) {
        return count.accumulateAndGet(x, (curr, val) -> curr + val); // OK: accumulazione atomica
    }
    
    public int get() { return count.get(); }
}

// 2. Thread-safe tramite ReentrantLock (pattern obbligatorio con isLocked e getQueueLength)
public class LockCounter {
    private int count = 0;
    private final ReentrantLock lock = new ReentrantLock();

    public void increment() {
        lock.lock();
        try {
            count++; // Sezione critica
        } finally {
            lock.unlock(); // Rilascio garantito anche in caso di eccezioni
        }
    }
    
    public void checkStatus() {
        System.out.println("Lock attivo: " + lock.isLocked());
        System.out.println("Thread in attesa: " + lock.getQueueLength());
    }
}

13.4 Utilizzo di Collezioni Concorrenti (Using Concurrent Collections)

Definizioni e Classi Concorrenti Il package java.util.concurrent include collezioni progettate per gestire accessi e modifiche concorrenti da parte di molteplici thread in modo performante e thread-safe:

  • ConcurrentHashMap: Mappa thread-safe basata su segmenti/bucket sincronizzati indipendentemente. Non accetta né chiavi né valori null (lancia NullPointerException).
  • CopyOnWriteArrayList / CopyOnWriteArraySet: Liste e insiemi in cui ogni operazione di scrittura o modifica (add, set, remove) crea una copia integrale dell'array sottostante. Gli iteratori sono weakly consistent (iterano su uno snapshot statico creato all'atto dell'iterazione) e non lanciano mai ConcurrentModificationException. Sono particolarmente efficienti quando le letture superano di gran lunga le scritture.
  • ConcurrentSkipListMap / ConcurrentSkipListSet: Versioni concorrenti e ordinate (sostituti thread-safe di TreeMap e TreeSet). Anche in questo caso non sono ammessi elementi o chiavi/valori null.
  • BlockingQueue (LinkedBlockingQueue, ArrayBlockingQueue): Code progettate per il pattern Produttore-Consumatore. Forniscono metodi con timeout (offer(e, timeout, unit) e poll(timeout, unit)) o bloccanti (put(e) e take()).

Collezioni Sincronizzate (Synchronized Wrappers) La classe Collections fornisce metodi factory per decorare collezioni standard rendendole sincronizzate: Collections.synchronizedList(list), Collections.synchronizedMap(map), Collections.synchronizedSet(set).

⚠️ Tranelli (Collezioni Concorrenti e Sincronizzate):

  • Iterazione su collezioni sincronizzate: Mentre le collezioni concorrenti (come ConcurrentHashMap o CopyOnWriteArrayList) possono essere iterate in sicurezza anche durante modifiche concorrenti, i wrapper di Collections.synchronizedList() richiedono la sincronizzazione manuale esplicita durante l'iterazione (synchronized(list) { for (var item : list) ... }), altrimenti l'iteratore lancerà ConcurrentModificationException.
  • Inserimento di null in ConcurrentHashMap: A differenza di HashMap standard, l'inserimento di una chiave o valore null in ConcurrentHashMap lancia immediatamente una NullPointerException.
  • Assenza di ConcurrentHashSet: Non esiste una classe denominata ConcurrentHashSet; per ottenere un Set concorrente si usa ConcurrentHashMap.newKeySet() o CopyOnWriteArraySet.

Esempi di Codice:

// ConcurrentHashMap: vietati i null
Map<String, String> concurrentMap = new ConcurrentHashMap<>();
concurrentMap.put("k1", "v1"); // OK
// concurrentMap.put(null, "v2"); // Lancia NullPointerException a runtime!

// CopyOnWriteArrayList: iterazione sicura durante la modifica
List<String> list = new CopyOnWriteArrayList<>(List.of("A", "B"));
for (String item : list) {
    list.add("C"); // OK: non lancia ConcurrentModificationException
}
System.out.println(list.size()); // Stampa 4 (gli elementi aggiunti non influenzano l'iteratore corrente)

13.5 Identificazione dei Problemi di Threading (Identifying Threading Problems)

Problemi di Liveness (Vitalità) Un problema di liveness si verifica quando un'applicazione multithreaded non riesce a completare l'esecuzione a causa di blocchi o contese tra thread:

  • Deadlock (Stallo): Si verifica quando due o più thread sono bloccati permanentemente in attesa ciascuno di una risorsa (lock) attualmente detenuta dall'altro thread, creando una dipendenza circolare.
  • Livelock: I thread non sono bloccati rigidamente, ma continuano ad alternare il proprio stato in risposta reciproca alle azioni dell'altro thread senza fare alcun progresso utile (simile a due persone che cercano di superarsi in un corridoio spostandosi ripetutamente dallo stesso lato).
  • Starvation (Inedia): Un thread non riesce mai ad ottenere l'accesso alle risorse condivise necessarie per completare il proprio lavoro perché altri thread più veloci o con priorità superiore monopolizzano costantemente la risorsa.

Sincronizzazione di Gruppo con CyclicBarrier La classe CyclicBarrier permette a un insieme prefissato di thread di sincronizzarsi attendendosi reciprocamente in un punto di barriera comune prima di proseguire:

  • Costruttore: new CyclicBarrier(int limit) oppure new CyclicBarrier(int limit, Runnable barrierAction) (la barrierAction viene eseguita una sola volta quando l'ultimo thread raggiunge la barriera).
  • Metodo await(): Ciascun thread invoca await() quando raggiunge la barriera e si mette in attesa finché il numero totale di thread chiamanti non raggiunge il limit prefissato. La barriera è cyclic perché si resetta automaticamente e può essere riutilizzata per cicli successivi.

⚠️ Tranelli (CyclicBarrier e Thread Insufficienti):

  • Blocco infinito (Hang) per insufficienza di thread: Se la dimensione del pool dell'Executor è inferiore al limite impostato nella CyclicBarrier, il numero di thread attivi non sarà sufficiente per soddisfare la barriera. I thread disponibili resteranno bloccati indefinitamente su await(), impedendo ai task successivi di essere presi in carico dall'executor e causando il blocco totale del programma (hang).

Esempio di Codice (Tranello CyclicBarrier - Assessment Test Q27):

// Esempio che causa il blocco infinito (Hang):
// Il pool ha solo 1 thread, ma la CyclicBarrier richiede 3 thread per sbloccarsi!
ExecutorService service = Executors.newSingleThreadExecutor();
CyclicBarrier barrier = new CyclicBarrier(3, () -> System.out.println("Barriera superata"));

for (int i = 0; i < 12; i++) {
    service.submit(() -> {
        try {
            System.out.println("Task in attesa...");
            barrier.await(); // Il singolo thread chiama await() e si blocca in attesa di altri 2 thread
            System.out.println("Task completato");
        } catch (Exception e) {
            e.printStackTrace();
        }
    });
}
// Risultato: Il primo task occupa l'unico thread del pool e chiama await().
// Nessun altro task può essere avviato per raggiungere la barriera -> PROGRAMMA BLOCCATO (HANG).

13.6 Lavoro con gli Stream Paralleli (Working with Parallel Streams)

Definizioni e Operazioni Uno Stream parallelo suddivide l'elaborazione dei dati tra molteplici thread sfruttando il framework ForkJoinPool comune, consentendo un incremento prestazionale significativo su elaborazioni computazionalmente intensive di collezioni voluminose.

  • Creazione: Invocando collection.parallelStream() oppure trasformando uno stream sequenziale esistente tramite stream.parallel().

Metodi Sensibili all'Ordine negli Stream Paralleli

  • findAny() vs findFirst(): Negli stream paralleli findAny() restituisce in modo non deterministico il primo elemento trovato da qualsiasi thread attivo, offrendo prestazioni nettamente superiori rispetto a findFirst(), che deve attendere e sincronizzare i risultati per preservare l'ordine originale di incontro.
  • forEach() vs forEachOrdered(): forEach() elabora gli elementi in ordine casuale e concorrente; forEachOrdered() preserva l'ordine originario della sorgente, ma azzera gran parte dei vantaggi prestazionali del parallelismo.
  • unordered(): Metodo intermedio che informa la pipeline che l'ordine di elaborazione non è rilevante, ottimizzando operazioni come distinct(), limit() e skip().

Operazioni di Riduzione Parallela (reduce e collect) Le operazioni di riduzione su stream paralleli devono rispettare proprietà rigorose di associatività (ossia (a + b) + c == a + (b + c)) e statelessness (nessuna modifica di stato condiviso non thread-safe):

  • Firma di reduce a 3 argomenti: <U> U reduce(U identity, BiFunction<U, ? super T, U> accumulator, BinaryOperator<U> combiner)
    • Accumulator: Combina un singolo elemento nello stato parziale del thread corrente ("Combines a single element into the current thread's partial state").
    • Combiner: Unisce i risultati parziali prodotti dai diversi thread in un unico risultato ("Merges the partial results produced by different threads into a single result").
    • Regola di Associatività: Il combiner deve essere necessariamente associativo ("The combiner must be associative, meaning (a + b) + c is equal to a + (b + c)").
  • collect con collector concorrenti: Per collezioni parallele non ordinate, Collectors.toConcurrentMap() o Collectors.groupingByConcurrent() offrono prestazioni scalabili senza overhead di sincronizzazione.

⚠️ Tranelli (Sintassi e Operazioni Parallele):

  • Separatori nella sintassi Stream.iterate(): Il metodo a tre argomenti di Stream.iterate() accetta il valore seed, il predicato di continuazione e la funzione di avanzamento separati da virgole (,), esattamente come ogni invocazione di metodo in Java. L'esame tenta spesso di confondere la sintassi usando punti e virgola (;) simulando un ciclo for.
  • Modifica concorrente di collezioni non thread-safe: L'utilizzo di forEach() parallelo per inserire elementi in un ArrayList standard (es. list.parallelStream().forEach(resList::add)) causa perdite di dati o ArrayIndexOutOfBoundsException / NullPointerException poiché ArrayList non è thread-safe.

Esempi di Codice:

// Sintassi corretta di Stream.iterate() con virgole
Stream<Integer> stream = Stream.iterate(1, n -> n < 100, n -> n + 2); // OK

// DOES NOT COMPILE: uso errato del punto e virgola
// Stream.iterate(1; n -> n < 100; n -> n + 2);

// Riduzione parallela con combiner
List<String> words = List.of("w", "o", "l", "f");
int totalLength = words.parallelStream()
                       .reduce(0, 
                               (count, str) -> count + str.length(), 
                               (c1, c2) -> c1 + c2); // OK: combinatore unisce i risultati dei thread

// Uso corretto di forEachOrdered vs forEach
List<Integer> nums = List.of(1, 2, 3, 4, 5);
nums.parallelStream().forEachOrdered(System.out::print); // Stampa garantita: 12345
nums.parallelStream().forEach(System.out::print);        // Stampa non deterministica (es. 31452)

13.7 Casi Limite e Tranelli Sintattici

Tutti i casi limite e i tranelli sintattici e operativi sopra descritti costituiscono gli elementi critici per il superamento dell'esame 1Z0-830 nel Capitolo 13:

  • Terminologia e Priorità: La priorità del thread è compresa nell'intervallo 1 (MIN_PRIORITY) - 10 (MAX_PRIORITY) con default 5 (NORM_PRIORITY); il context switch salva e ripristina lo stato del thread.
  • Virtual Thread: Assenza di costruttori pubblici (new VirtualThread() non compila); impossibilità di renderli non-daemon (lancia IllegalArgumentException); creazione obbligatoria tramite builder Thread.ofVirtual() e factory executor Executors.newVirtualThreadPerTaskExecutor().
  • Chiamata start() vs run(): L'invocazione di run() non lancia un nuovo thread ma esegue il metodo in modo sincrono sul thread corrente.
  • Ciclo di vita dell'Executor: isShutdown() restituisce true non appena viene invocato shutdown(), mentre isTerminated() diventa true solo dopo che tutti i task in corso e in coda sono stati completati; la mancata invocazione di shutdown() impedisce l'arresto della JVM se sono presenti platform thread non-daemon.
  • Atomicità e Lock: Operazioni composte come count++ non sono atomiche; le classi atomiche offrono anche metodi funzionali come updateAndGet() e accumulateAndGet(); con ReentrantLock il rilascio lock.unlock() deve risiedere categoricamente nel blocco finally, e i metodi isLocked() e getQueueLength() consentono di ispezionarne lo stato e la coda dei thread.
  • Collezioni Concorrenti vs Sincronizzate: ConcurrentHashMap non accetta chiavi o valori null; le collezioni sincronizzate (Collections.synchronizedList()) richiedono un blocco synchronized esplicito per essere iterate in sicurezza senza scatenare ConcurrentModificationException.
  • Deadlock e CyclicBarrier: Dimensionare un pool di thread con un numero di thread inferiore al limite della CyclicBarrier conduce a un blocco permanente (hang) dell'intera applicazione.
  • Stream Paralleli: Stream.iterate() richiede argomenti separati da virgole; findAny() è non deterministico in parallelo ma molto più efficiente di findFirst(); l'accumulazione concorrente di risultati richiede combiner associativi e collector thread-safe, non manipolazioni su collezioni standard non sincronizzate.

14.1 Riferimento a File e Directory (Referencing Files and Directories)

Definizioni e Concetti In Java la gestione di file e directory si basa su due modelli: l'API legacy java.io.File (introdotta in Java 1.0) e l'API moderna NIO.2 (java.nio.file.Path, introdotta in Java 7 e potenziata in Java 21). Un oggetto Path rappresenta una locazione gerarchica all'interno del file system (file o cartella), sia essa esistente o puramente concettuale.

  • Percorso Assoluto (Absolute Path): Specifica la posizione completa partendo dall'elemento radice (root) del file system (es. /home/user/data.txt su Unix o C:\user\data.txt su Windows). path.isAbsolute() restituisce true.
  • Percorso Relativo (Relative Path): Specifica la posizione a partire dalla directory di lavoro corrente senza indicare la radice (es. user/data.txt).
  • Creazione di oggetti Path: In Java 21 il modo standard di creare un percorso è tramite i metodi factory Path.of(String first, String... more) o Path.of(URI uri). La classe di utilità Paths.get(...) è un alias equivalente, così come FileSystems.getDefault().getPath(...).
  • Interoperabilità File e Path: La classe java.io.File dispone del metodo di istanza file.toPath() per passare a NIO.2, mentre Path dispone di path.toFile() per retrocompatibilità.

Metodi Principali dell'Interfaccia Path

  • toString(): Restituisce la rappresentazione in formato stringa del percorso completo.
  • getFileName(): Restituisce l'ultimo elemento del percorso come nuovo oggetto Path (il nome del file o della cartella terminale).
  • getParent(): Restituisce il percorso della cartella genitore oppure null se si tratta della radice o di un percorso relativo senza genitore esplicito.
  • getRoot(): Restituisce l'elemento radice del percorso o null se il percorso è relativo.
  • getNameCount(): Restituisce il numero totale di elementi presenti nel percorso (esclusa la radice).
  • getName(int index): Restituisce l'elemento alla posizione specificata (0-based) come nuovo oggetto Path.
  • subpath(int beginIndex, int endIndex): Estrae una porzione del percorso dall'indice beginIndex (incluso) a endIndex (escluso). Non include mai la radice e lancia IllegalArgumentException se gli indici sono fuori limite.
  • isAbsolute(): Verifica se il percorso è assoluto.
  • toAbsolutePath(): Converte un percorso relativo in assoluto agganciandolo alla directory di lavoro corrente della JVM.
  • resolve(Path other) / resolve(String other): Unisce due percorsi. Se other è un percorso assoluto, il metodo restituisce direttamente other ignorando il percorso di base.
  • resolveSibling(Path other): Sostituisce l'ultimo elemento del percorso chiamante con il percorso specificato (risolve rispetto al genitore).
  • relativize(Path other): Calcola il percorso relativo necessario per raggiungere other partendo dal percorso corrente. Regola d'oro: entrambi i percorsi devono essere entrambi assoluti o entrambi relativi (su Windows devono appartenere alla stessa unità disco), altrimenti lancia IllegalArgumentException.
  • normalize(): Rimuove le ridondanze sintattiche come . (directory corrente) e .. (directory superiore) basandosi unicamente sulla manipolazione della stringa, senza verificare l'esistenza del file sul disco.
  • toRealPath(LinkOption... options): Risolve i collegamenti simbolici (symbolic links), normalizza il percorso e ne verifica l'effettiva esistenza sul file system reale, lanciando NoSuchFileException se il target non esiste.

⚠️ Tranelli (Path e Riferimenti):

  • Mescolare assoluti e relativi in relativize(): Invocare relativize() tra un percorso assoluto e uno relativo (o viceversa) provoca immediatamente una IllegalArgumentException a runtime.
  • Passaggio di un path assoluto a resolve(): Invocare path1.resolve(path2) quando path2 è assoluto restituisce path2 senza alcuna concatenazione.
  • Inclusione della root in subpath(): subpath() conta solo gli elementi di nome; tentare di accedere alla radice o superare getNameCount() lancia IllegalArgumentException.
  • Normalizzazione vs Esistenza: normalize() ripulisce solo la stringa (es. trasforma a/b/../c in a/c), ma non garantisce che la risorsa esista realmente sul disco; solo toRealPath() esegue la verifica reale.

Esempi di Codice:

Path path = Path.of("/zoo/armadillo/shells.txt");
System.out.println(path.getNameCount()); // 3 (zoo, armadillo, shells.txt - root esclusa)
System.out.println(path.getName(0));      // zoo
System.out.println(path.subpath(1, 3));   // armadillo/shells.txt

Path p1 = Path.of("fish.txt");
Path p2 = Path.of("birds.txt");
System.out.println(p1.relativize(p2));   // ../birds.txt

Path absolute = Path.of("/home/user");
Path relative = Path.of("docs/file.txt");
// absolute.relativize(relative); // Lancia IllegalArgumentException a runtime!

System.out.println(relative.resolve("/etc/config")); // Stampa /etc/config (parametro assoluto)

14.2 Introduzione agli Stream di I/O (Introducing I/O Streams)

Definizioni e Concetti Uno Stream di I/O è un condotto sequenziale per il trasferimento di dati da una sorgente a una destinazione. Gli stream non memorizzano dati, ma consentono la lettura o la scrittura ordinata di flussi continui.

  • Byte Streams (Flussi di Byte): Elaborano dati binari a 8 bit (immagini, file compilati, archivi compressi). Le classi base astratte sono InputStream (lettura) e OutputStream (scrittura).
  • Character Streams (Flussi di Caratteri): Elaborano dati testuali a 16 bit Unicode gestendo automaticamente la codifica dei caratteri (character encoding/charset). Le classi base astratte sono Reader (lettura) e Writer (scrittura).
  • Stream di Basso Livello (Low-Level Streams): Si collegano direttamente alla risorsa fisica (es. FileInputStream, FileOutputStream, FileReader, FileWriter).
  • Stream di Alto Livello (High-Level / Filter Streams): Avvolgono (wrap) un altro stream per aggiungere funzionalità come bufferizzazione, formattazione o serializzazione (es. BufferedReader, BufferedWriter, ObjectInputStream, ObjectOutputStream, PrintStream, PrintWriter).
  • Stream Ponte (Bridge Streams): Consentono di convertire un flusso di byte in un flusso di caratteri specificando il charset: InputStreamReader e OutputStreamWriter.

Metodi Principali delle Classi Base

  • read(): Legge un singolo byte o carattere restituendo un valore intero compreso tra 0 e 255 (per byte) o 0 e 65535 (per caratteri), oppure -1 quando si raggiunge la fine dello stream (EOF).
  • read(byte[] b) / read(char[] cbuf): Legge un blocco di byte/caratteri riempiendo l'array e restituisce il numero di elementi effettivamente letti (o -1 a fine stream).
  • write(int b) / write(byte[] b) / write(String s): Scrive byte o stringhe verso la destinazione.
  • flush(): Forza lo svuotamento del buffer interno scrivendo immediatamente tutti i byte/caratteri accumulati sulla destinazione fisica.
  • close(): Chiude lo stream rilasciando le risorse native allocate. Nelle catene di decoratori, chiudere lo stream più esterno chiude a cascata tutti gli stream interni sottostanti.
  • Supporto mark() e reset(): Permette di memorizzare una posizione nello stream con mark(int readAheadLimit) e di ritornarvi successivamente tramite reset(). Prima di invocare reset() è obbligatorio verificare markSupported().

Regole Operative e Bufferizzazione La bufferizzazione ottimizza drasticamente le prestazioni di I/O memorizzando blocchi di dati in memoria RAM invece di eseguire accessi fisici al disco per ogni singolo byte o carattere.

  • BufferedReader mette a disposizione il metodo fondamentale readLine() che restituisce una stringa (senza i caratteri di a capo) oppure null al raggiungimento della fine dello stream.
  • BufferedWriter mette a disposizione il metodo newLine() per inserire il separatore di riga dipendente dal sistema operativo.

⚠️ Tranelli (Stream e Decoratori):

  • Incompatibilità diretta tra Byte e Character Streams: Non è possibile passare un InputStream direttamente a un costruttore di Reader senza passare per la classe ponte InputStreamReader (es. new BufferedReader(new FileInputStream("a.txt")) non compila).
  • Omessa gestione di IOException: Quasi tutti i costruttori e metodi di I/O dichiarano la checked exception IOException, che deve essere obbligatoriamente gestita o rilanciata nella firma.
  • Mancata verifica di markSupported(): Chiamare reset() su stream che non supportano il riposizionamento (come FileInputStream puro) lancia IOException a runtime.

Esempi di Codice:

// Pattern corretto con Try-with-resources e stream a catena
Path source = Path.of("source.txt");
Path target = Path.of("target.txt");

try (var reader = new BufferedReader(new FileReader(source.toFile()));
     var writer = new BufferedWriter(new FileWriter(target.toFile()))) {
    String line;
    while ((line = reader.readLine()) != null) {
        writer.write(line);
        writer.newLine(); // A capo standard
    }
} // Chiusura automatica di entrambi i flussi e delle risorse sottostanti

14.3 Lettura e Scrittura di File (Reading and Writing Files)

Metodi e Operazioni della Classe java.nio.file.Files La classe di utilità Files fornisce metodi statici altamente ottimizzati per operare su file e cartelle tramite oggetti Path:

  • Metodi Factory di I/O: Files.newInputStream(path), Files.newOutputStream(path), Files.newBufferedReader(path), Files.newBufferedWriter(path).
  • Lettura e Scrittura Rapida:
    • Files.readAllBytes(path): Legge l'intero file in memoria come byte[].
    • Files.readString(path) / Files.writeString(path, charSeq): Legge o scrive l'intero contenuto testuale in una sola chiamata.
    • Files.readAllLines(path): Legge tutte le righe caricandole interamente in una List<String> (può causare OutOfMemoryError su file di grandi dimensioni).
    • Files.lines(path): Restituisce uno Stream<String> pigro (lazy) che legge le righe su richiesta (richiede obbligatoriamente la chiusura con try-with-resources).
  • Confronto di File:
    • Files.isSameFile(Path p1, Path p2): Restituisce true se i percorsi puntano alla stessa risorsa fisica. Se i due Path sono sintatticamente uguali (equals()), restituisce true senza accedere al disco; altrimenti controlla il file system reale risolvendo eventuali link simbolici.
    • Files.mismatch(Path p1, Path p2): Confronta il contenuto di due file byte per byte. Restituisce -1L se i file sono identici, oppure l'indice 0-based del primo byte differente.

Operazioni di Manipolazione del File System

  • Creazione:
    • Files.createDirectory(path): Crea una singola cartella; lancia eccezione se la cartella esiste già o se le cartelle genitori non esistono.
    • Files.createDirectories(path): Crea la cartella e tutte le directory intermedie mancanti lungo il percorso; non lancia eccezione se la cartella finale esiste già.
    • Files.createFile(path): Crea un nuovo file vuoto; lancia eccezione se il file esiste già.
  • Copia e Spostamento:
    • Files.copy(source, target, StandardCopyOption... options): Copia un file o directory. Per le cartelle, esegue una copia superficiale (shallow copy), creando la nuova cartella vuota senza copiare ricorsivamente i file in essa contenuti.
    • Files.move(source, target, StandardCopyOption... options): Sposta o rinomina un file o una directory.
    • Opzioni di Copia/Spostamento (StandardCopyOption): REPLACE_EXISTING (sovrascrive se esiste), COPY_ATTRIBUTES (preserva i metadati del file), ATOMIC_MOVE (spostamento atomico garantito a livello di file system).
  • Cancellazione:
    • Files.delete(path): Cancella il file o la directory (lancia NoSuchFileException se non esiste, o DirectoryNotEmptyException se la cartella non è vuota).
    • Files.deleteIfExists(path): Cancella il target se presente restituendo true, oppure restituisce false senza lanciare eccezioni se il target non esiste.

⚠️ Tranelli (Files e mismatch):

  • mismatch() con file inesistenti: Lancia NoSuchFileException a meno che entrambi i parametri non puntino allo stesso identico percorso non esistente.
  • Indici 0-based di mismatch(): Se la discrepanza si trova al secondo carattere/byte del file, il metodo restituisce 1L.
  • Copia di directory: Files.copy(dir1, dir2) non copia i file interni; per una copia profonda (deep copy) è necessario attraversare l'albero con Files.walk().

Esempi di Codice:

Path p2 = Path.of("hello.txt"); // Contiene "Hello"
System.out.println(Files.mismatch(p1, p2)); // 1 (la 'o' e la 'e' differiscono all'indice 1)

// Lettura efficiente con Stream e Try-with-resources

    stream.filter(l -> l.contains("ERROR"))
          .forEach(System.out::println);
} // Stream chiuso correttamente, rilasciando l'handle di sistema

14.4 Serializzazione dei Dati (Serializing Data)

Definizioni e Requisiti La Serializzazione è il processo di conversione di un grafo di oggetti Java in una sequenza di byte. La Deserializzazione è il processo inverso che ricostruisce gli oggetti in memoria a partire dal flusso di byte.

  • Interfaccia Serializable: Interfaccia marcatore (marker interface, non contiene metodi) appartenente al package java.io. Una classe deve implementare esplicitamente Serializable (o estendere una classe che la implementa) affinché le sue istanze possano essere serializzate.
  • Stream di Oggetti: Si utilizzano le classi di alto livello ObjectOutputStream (metodo writeObject(Object)) e ObjectInputStream (metodo readObject()).
  • serialVersionUID: Identificatore di versione numerico a 64 bit (private static final long serialVersionUID = 1L;) utilizzato dalla JVM per garantire che la classe caricata per la deserializzazione corrisponda esattamente alla versione utilizzata durante la serializzazione.

Regole di Trattamento dei Membri della Classe

  • Campi transient: I campi contrassegnati con la parola chiave transient non vengono serializzati. Durante la deserializzazione, Java non legge alcun dato per essi e li inizializza al rispettivo valore predefinito del tipo di dato (null per i riferimenti a oggetti e wrapper, 0 per interi, false per boolean).
  • Campi static: Le variabili statiche appartengono alla classe e non all'istanza; non vengono serializzate. Al momento della deserializzazione, il campo statico manterrà il valore corrente già presente nella JVM in esecuzione.
  • Campi Oggetto Annidati: Tutte le classi referenziate come campi d'istanza devono essere a loro volta Serializable; in caso contrario, l'invocazione di writeObject() lancerà a runtime una NotSerializableException.
  • Ereditarietà e Costruttori: Durante la deserializzazione di una classe serializzabile, il costruttore della classe stessa non viene eseguito. Tuttavia, se una superclasse non implementa Serializable, Java eseguirà il costruttore senza argomenti (no-arg constructor) della prima superclasse non serializzabile. Se tale costruttore non esiste o non è accessibile, viene lanciata InvalidClassException.
  • Serializzazione dei Record (Java 21): A differenza delle classi ordinarie, i record serializzabili vengono sempre deserializzati passando obbligatoriamente attraverso il loro costruttore canonico, garantendo l'immutabilità e la validazione dei componenti.

⚠️ Tranelli (Serializzazione):

  • Mancata implementazione di Serializable: Il codice compila regolarmente, ma lancia NotSerializableException a runtime non appena si tenta di invocare writeObject().
  • Tipo di ritorno e Checked Exception di readObject(): readObject() restituisce un tipo generico Object e richiede un casting esplicito verso il tipo di destinazione. Inoltre, dichiara sia IOException che ClassNotFoundException, entrambe obbligatorie da gestire.
  • Valori transient dopo la deserializzazione: Gli inizializzatori di campo d'istanza e i costruttori non vengono eseguiti durante la deserializzazione ordinaria; un campo transient int count = 25; avrà valore 0 dopo la deserializzazione, non 25.

Esempi di Codice:

public class Bird implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name = "Tweety";
    private transient int age = 10;
    private transient String color = "Yellow";
    
    // Costruttore standard
    public Bird(String name, int age, String color) {
        this.name = name;
        this.age = age;
        this.color = color;
    }
    // Getter e Setter...
}

// Scrittura e Lettura
ByteArrayOutputStream buffer = new ByteArrayOutputStream();
try (var out = new ObjectOutputStream(buffer)) {
    out.writeObject(new Bird("Robin", 3, "Red"));
}

try (var in = new ObjectInputStream(new ByteArrayInputStream(buffer.toByteArray()))) {
    Bird b = (Bird) in.readObject(); // Richiede casting e gestione ClassNotFoundException
    System.out.println(b.getName());  // Robin (preservato)
    System.out.println(b.getAge());   // 0 (transient: assume default di int)
    System.out.println(b.getColor()); // null (transient: assume default di Object)
}

14.5 Interazione con l'Utente (Interacting with Users)

Definizioni e Metodi Java fornisce la classe java.util.Console per gestire in modo avanzato l'interazione bidirezionale da terminale con l'utente. L'istanza singleton della console viene recuperata tramite l'invocazione di System.console().

  • Flussi Standard del Sistema:
    • System.in: Stream di input a byte (InputStream).
    • System.out: Stream di output a caratteri bufferizzato per stampe standard (PrintStream).
    • System.err: Stream di output a caratteri per messaggi di errore (PrintStream).
  • Metodi Principali della Classe Console:
    • readLine() / readLine(String fmt, Object... args): Stampa un eventuale prompt formattato e acquisisce una riga di testo terminata da invio, restituendo una String.
    • readPassword() / readPassword(String fmt, Object... args): Acquisisce una stringa di input da terminale disabilitando l'eco a schermo dei caratteri digitati per impedire la visualizzazione visiva dei dati sensibili (shoulder surfing). Restituisce un array di caratteri char[].
    • format(String fmt, Object... args) / printf(...): Scrive output formattato direttamente sulla console.
    • writer(): Restituisce un oggetto PrintWriter collegato alla console.
    • reader(): Restituisce un oggetto Reader collegato alla console.
    • flush(): Svuota forzatamente il buffer di output della console.

⚠️ Tranelli (Console e Sicurezza):

  • Valore null di System.console(): Se l'applicazione viene eseguita all'interno di un ambiente non interattivo (ad esempio la maggior parte degli IDE come Eclipse o IntelliJ, oppure come servizio o processo in background), System.console() restituisce null. Chiamare metodi direttamente su System.console() senza un controllo di nullità provoca una NullPointerException immediata a runtime.
  • Tipo di ritorno di readPassword(): Restituisce categoricamente char[] e non String. Questo consente al programmatore di sovrascrivere l'array in memoria (es. Arrays.fill(pwd, 'x')) non appena terminata la validazione, evitando che il dato sensibile rimanga immutabile nella string pool della memoria heap fino all'intervento del Garbage Collector.

Esempi di Codice:

Console console = System.console();
if (console != null) {
    String username = console.readLine("Inserisci username: ");
    char[] password = console.readPassword("Inserisci password: ");
    
    console.format("Benvenuto, %s!%n", username);
    
    // Best practice di sicurezza: azzeramento immediato dell'array
    java.util.Arrays.fill(password, '0');
} else {
    System.err.println("Console interattiva non disponibile nell'ambiente corrente.");
}

14.6 Lavoro con API Avanzate (Working with Advanced APIs)

Attributi e Viste dei File (Attributes and Views) NIO.2 consente di ispezionare e modificare i metadati dei file in modo efficiente e multipiattaforma:

  • BasicFileAttributes: Interfaccia di sola lettura che recupera in una singola chiamata al file system un insieme completo di attributi essenziali.
    • Metodi: size(), creationTime(), lastModifiedTime(), lastAccessTime(), isDirectory(), isRegularFile(), isSymbolicLink(), isOther(), fileKey().
    • Recupero: Files.readAttributes(path, BasicFileAttributes.class).
  • BasicFileAttributeView: Interfaccia che permette non solo di leggere, ma anche di modificare gli attributi del file.
    • Metodo principale: setTimes(FileTime lastModifiedTime, FileTime lastAccessTime, FileTime createTime). Se un parametro è null, l'attributo corrispondente rimane inalterato.
    • Recupero: Files.getFileAttributeView(path, BasicFileAttributeView.class).

Navigazione e Ricerca nel File System con gli Stream I metodi statici di Files consentono di esplorare gerarchie di cartelle sfruttando la potenza della Stream API di Java:

  • Files.list(Path dir): Restituisce uno Stream<Path> contenente gli elementi (file e sottocartelle) situati esclusivamente al primo livello della cartella specificata (non è ricorsivo, profondità 1).
  • Files.walk(Path start, int maxDepth, FileVisitOption... options): Attraversa ricorsivamente l'albero delle directory in profondità (depth-first search). Se non specificato, maxDepth è Integer.MAX_VALUE.
  • Files.find(Path start, int maxDepth, BiPredicate<Path, BasicFileAttributes> matcher, FileVisitOption... options): Attraversa l'albero e filtra direttamente gli elementi combinando percorso e attributi in un'unica operazione ottimizzata.

⚠️ Tranelli (Navigazione, Risorse e Cicli):

  • Chiusura obbligatoria degli Stream di Files: I metodi Files.list(), Files.walk(), Files.find() e Files.lines() aprono connessioni con il file system sottostante. Devono essere sempre racchiusi in un blocco try-with-resources, altrimenti i descrittori di file rimarranno aperti causando resource leak nel sistema operativo.
  • Collegamenti simbolici e FileSystemLoopException: Di default, Files.walk() e Files.find() non seguono i link simbolici (FileVisitOption.FOLLOW_LINKS). Se l'opzione FOLLOW_LINKS viene abilitata esplicitamente e il file system contiene un ciclo circolare (una cartella che punta a un genitore superiore), il metodo entrerà in un ciclo infinito e lancerà una FileSystemLoopException.

Esempi di Codice:

Path startPath = Path.of("/data");

// 1. Lettura attributi
BasicFileAttributes attrs = Files.readAttributes(startPath, BasicFileAttributes.class);
System.out.println("Dimensione: " + attrs.size());
System.out.println("Data creazione: " + attrs.creationTime());

// 2. Ricerca avanzata con Files.find e Try-with-resources
try (Stream<Path> stream = Files.find(startPath, 5, 
        (p, a) -> p.toString().endsWith(".java") && a.size() > 1024)) {
    stream.forEach(System.out::println);
}

14.8 Casi Limite e Tranelli Sintattici

Tutti i casi limite e i tranelli sintattici e operativi sopra descritti costituiscono gli elementi critici per il superamento dell'esame 1Z0-830 nel Capitolo 14:

  • Differenza File e Path: I metodi di Files (NIO.2) non sono metodi d'istanza della classe legacy java.io.File; occorre sempre convertire con toPath() o toFile().
  • Comportamento di relativize(): Entrambi i percorsi devono essere dello stesso tipo (entrambi assoluti o entrambi relativi) e appartenere alla stessa radice/unità disco, altrimenti lancia IllegalArgumentException.
  • Comportamento di resolve(): Se l'argomento passato a resolve() è assoluto, la base viene ignorata e viene restituito direttamente il parametro.
  • Conteggio e Indici di subpath(): Non include la root; subpath(0, 1) del percorso /a/b/c restituisce a. Indici errati lanciano IllegalArgumentException.
  • Esito di Files.mismatch(): Restituisce l'indice numerico zero-based del primo byte differente, oppure -1L se i file sono completamente identici; se i file non esistono, lancia eccezione.
  • Copia Superficiale delle Directory: Files.copy() crea solo la cartella target vuota senza copiare i file figli.
  • Gestione Risorse negli Stream NIO.2: I metodi di Files che restituiscono Stream (lines(), list(), walk(), find()) devono essere racchiusi in try-with-resources per evitare leak di descrittori di file.
  • Campi transient e Serializzazione: Durante la deserializzazione, i campi transient assumono il valore predefinito del tipo (null, 0, false) e non quello dichiarato nell'inizializzatore inline o nel costruttore.
  • Checked Exceptions su readObject(): Richiede la gestione sia di IOException che di ClassNotFoundException e il cast esplicito da Object.
  • Superclassi non serializzabili: Se la superclasse non implementa Serializable, deve possedere un costruttore accessibile senza argomenti (no-arg constructor), altrimenti la deserializzazione fallisce con InvalidClassException.
  • Controllo di Nullità su System.console(): Negli ambienti non interattivi (es. IDE), System.console() restituisce null; readPassword() restituisce sempre char[] e non String.
  • Cicli nei Link Simbolici: L'abilitazione di FileVisitOption.FOLLOW_LINKS su percorsi con link circolari può causare FileSystemLoopException durante l'uso di Files.walk().

Questi metodi sono fondamentali perché si comportano diversamente dai wrapper numerici.

  1. static boolean parseBoolean(String s) Converte una stringa nel primitivo boolean. È estremamente "tollerante": restituisce true solo se la stringa è "true" (ignorando maiuscole e minuscole); per qualsiasi altra stringa (o se è null) restituisce false senza mai lanciare eccezioni.

  2. static Boolean valueOf(String s) Come il precedente, ma restituisce l'oggetto Boolean.TRUE o Boolean.FALSE dalla memoria, usando la stessa logica di tolleranza.

  3. static Character valueOf(char c) Crea o recupera dalla cache (da 0 a 127) un oggetto Character partendo da un primitivo char. Nota da esame: Non esistono metodi parseCharacter o valueOf(String) per questa classe.

Metodi di Unboxing Manuale (ereditati da Number)

Tutti i wrapper numerici (Byte, Short, Integer, Long, Float, Double) possiedono questi metodi di istanza per estrarre il valore in uno specifico tipo primitivo, effettuando eventuali conversioni o troncamenti automatici.

  1. byte byteValue() Estrae il valore dell'oggetto come primitivo byte (possibile perdita di precisione).

  2. short shortValue() Estrae il valore dell'oggetto come primitivo short.

  3. int intValue() Estrae il valore dell'oggetto come primitivo int (es. se usato su un Double, tronca brutalmente i decimali).

  4. long longValue() Estrae il valore dell'oggetto come primitivo long.

  5. float floatValue() Estrae il valore dell'oggetto come primitivo float.

  6. double doubleValue() Estrae il valore dell'oggetto come primitivo double.

Metodi speciali per la virgola mobile (Double e Float)

Questi metodi statici testano lo stato di numeri che seguono lo standard IEEE 754.

  1. static boolean isNaN(double v) (esiste anche per float) Restituisce true se il valore valutato non è un numero matematicamente valido (Not-a-Number), tipicamente generato da operazioni come 0.0 / 0.0.

  2. static boolean isInfinite(double v) (esiste anche per float) Restituisce true se il valore rappresenta l'infinito positivo o negativo (es. generato da 1.0 / 0.0).

Metodi di utilità (Introdotti in Java 8)

Questi metodi statici sono presenti nelle classi wrapper Integer, Long, Float e Double (le firme qui sotto usano int per l'esempio, ma esistono gli equivalenti). Sono molto testati in combinazione con le Stream API.

  1. static int max(int a, int b) Confronta due valori e restituisce il maggiore.

  2. static int min(int a, int b) Confronta due valori e restituisce il minore.

  3. static int sum(int a, int b) Restituisce la somma aritmetica dei due valori.

Array "Old Style" (es. int[], String[]) e java.util.Arrays

Gli array primitivi o di oggetti (es. int[]) in Java sono oggetti, ma non hanno metodi propri oltre a quelli ereditati da Object (come clone()) e l'attributo speciale length (che non è un metodo). Tuttavia, per l'esame è essenziale conoscere i metodi di utilità della classe java.util.Arrays.

  1. static void sort(int[] a) (e relativi overload) Ordina l'array passato per riferimento. Esistono overload per quasi tutti i primitivi e per oggetti (Object[] o con Comparator).

  2. static int binarySearch(int[] a, int key) (e relativi overload) Cerca un elemento nell'array. Attenzione: l'array deve essere già ordinato. Se l'elemento non c'è, restituisce -(punto_di_inserimento) - 1.

  3. static int compare(int[] a, int[] b) Confronta due array in ordine lessicografico. Restituisce 0 se sono uguali, un numero negativo se a < b, o positivo se a > b.

  4. static int mismatch(int[] a, int[] b) Trova e restituisce l'indice del primo elemento discordante tra i due array. Se sono identici, restituisce -1.

  5. static boolean equals(int[] a, int[] b) / deepEquals(Object[] a, Object[] b) equals confronta il contenuto di array monodimensionali. deepEquals va usato per array multidimensionali (es. int[][]).

  6. static int[] copyOf(int[] original, int newLength) Crea un nuovo array copiando il contenuto dell'originale. Se newLength è maggiore, riempie il resto con i valori di default (es. 0 o null).

Metodi fondamentali di String

Le stringhe sono immutabili. Qualsiasi metodo che "modifica" una stringa restituisce in realtà una nuova stringa.

  1. int length() Restituisce la lunghezza della stringa (attenzione: per gli array è una proprietà .length senza parentesi, per le stringhe è un metodo length()).

  2. String substring(int beginIndex, int endIndex) Estrae una sottostringa. beginIndex è incluso, endIndex è escluso. (L'overload con solo beginIndex arriva fino alla fine della stringa).

  3. boolean isBlank() vs boolean isEmpty() isEmpty() verifica solo se length() == 0. isBlank() verifica se la stringa è vuota o contiene solo spazi bianchi (spazi, tab, a capo).

  4. String strip() / stripLeading() / stripTrailing() Rimuove gli spazi bianchi all'inizio e/o alla fine (supporta pienamente l'Unicode, a differenza del vecchio e meno potente trim()).

  5. String indent(int n) Aggiunge (o rimuove, se negativo) spazi di indentazione all'inizio di ogni riga e aggiunge un carattere di newline (\n) finale se non già presente.

  6. String formatted(Object... args) Alternativa di istanza al metodo statico String.format(). Formatta la stringa usando i segnaposto (es. "%s %d".formatted("Test", 1)).

  7. String repeat(int count) Ripete la stringa il numero specificato di volte.

Metodi fondamentali di List e Collections (focus Java 21)

Per l'esame è cruciale conoscere non solo i metodi base, ma anche le recenti aggiunte come le Sequenced Collections (introdotte proprio in Java 21).

  1. static List<E> of(E... elements) / copyOf(Collection<? extends E> coll) Creano liste immutabili. Non accettano valori null (se presenti, lanciano NullPointerException).

  2. boolean remove(Object o) vs E remove(int index) Nelle liste di Integer c'è spesso un trabocchetto da esame: list.remove(1) usa l'overload primitivo e rimuove l'elemento all'indice 1, mentre list.remove(Integer.valueOf(1)) rimuove l'oggetto col valore 1.

  3. void replaceAll(UnaryOperator<E> operator) Sostituisce ogni elemento della lista applicando l'operatore specificato.

  4. boolean removeIf(Predicate<? super E> filter) Rimuove (dalla collezione) tutti gli elementi che soddisfano la condizione data dal predicato. È un metodo di Collection.

  5. void sort(Comparator<? super E> c) Ordina la lista in-place. Se si passa null al posto del comparatore, viene usato l'ordinamento naturale (gli elementi devono implementare Comparable).

Novità Java 21: Sequenced Collections

In Java 21 le interfacce List, Deque e SortedSet implementano la nuova interfaccia SequencedCollection, uniformando i metodi per accedere al primo e all'ultimo elemento.

  1. E getFirst() / E getLast() Restituiscono il primo o l'ultimo elemento. Lanciano NoSuchElementException se la collezione è vuota.

  2. void addFirst(E e) / void addLast(E e) Aggiungono l'elemento in testa o in coda. Nelle collezioni non modificabili lanciano UnsupportedOperationException.

  3. E removeFirst() / E removeLast() Rimuovono e restituiscono il primo o l'ultimo elemento.

  4. SequencedCollection<E> reversed() Restituisce una "vista" invertita della collezione. Iterare, modificare o accedere agli elementi di questa vista si rifletterà sulla collezione originale (e viceversa).
